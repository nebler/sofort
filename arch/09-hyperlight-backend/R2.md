# 09 — R2 Hyperlight baseline

**G5 FIXED/PASS:** one harness, four modes × five identical snippets × 30 samples =
**600 validated results**. `raw.jsonl` retains every sample, load average and memory
counter. Hyperlight is the D11 benchmark baseline; all DECISIONS-R1 are accepted.

## Method and isolation contract

- Apple M4 Pro / macOS 26.6.1, shared host. Main run uptime/load:
  `2:36 up 3:49, 2 users, 29.51/71.19/53.39` →
  `2:36 up 3:50, 2 users, 24.08/66.55/52.23`. Every sample records `uptime`.
- `r2/bench.py` is the ONE external Python supervisor. Each iteration shuffles
  workload order, then rotates/reverses mode order. No modes run concurrently.
  One common `test.echo` dispatcher schedules each response 5 ms after receipt;
  independent pending replies overlap naturally. Timings include JSON IPC and
  external memory sampling identically across modes; no synthetic jitter subtraction.
- **jitk cold:** fresh process + HW VM, 02 READY kernel, 32 MiB RAM, one console.
  Copied/frozen `/tmp/jitk-02/r2/host` and `kernel.bin` into `/tmp/jitk-09/r2-jitk/`.
  Kernel SHA256 `00040cfa7187a3cf25fb7cf8f01d973bf41f4f9179b4fc382dcb890b34d13edf`.
- **HL strict:** fresh worker process + new Apple HW VM, load persisted initialized
  OCI snapshot, one snippet, destroy. This is the comparable single-use contract.
- **HL fresh:** initialize runtime and generic bootstrap from source for each job
  inside a resident worker. Fresh logical sandbox, **shared Apple VM, not 1 HW VM/job**.
- **HL clone:** restore a fresh logical sandbox from the initialized snapshot in a
  resident worker. **Shared Apple VM, not 1 HW VM/job**; process-wide HVF lock.
- All Hyperlight modes compile the exact same submitted async body at execution.
  All use 16 MiB guest heap + 16 MiB scratch. The 1 MiB scratch default failed
  JSON smoke with `GuestAborted(13, "Out of physical memory")`; failure retained.
  A shared generic template contains no tenant code/data. Cache is warm; snapshot
  construction/save, download/build, and resident-worker startup are excluded.
- Cold timing starts before process spawn; resident timing starts before run send.
  Both end at validated `done`. Cold reap is separately recorded; return2 median
  through reap: jitk **10.978 ms**, HL strict **9.487 ms**. All workers are reaped.
- JSON case creates an exactly 1,048,576-byte JSON string inside the guest, parses,
  stringifies, and returns its length. CPU case loops in 1,000-op chunks until
  `Date.now()` passes 50 ms. It includes clock-query overhead, not fixed CPU cycles.

## Memory — same counters and sampling for every mode

External `proc_pid_rusage(pid, RUSAGE_INFO_V0)` supplies **ri_phys_footprint and
ri_resident_size (RSS)**. The supervisor samples at ready/event-loop boundaries
and every nominal 250 us, retaining the observed per-execution maximum, baseline
and increment. These are sampled maxima, **not guaranteed true transient peaks**:
largest observed gaps were jitk 7.14 ms, HL strict 22.04 ms, fresh 19.01 ms,
clone 7.72 ms under contention. All jobs have samples; return2 clone median is 6.
RSS includes file-backed resident pages; footprint can include compressed private
pages and exceed RSS. Neither is PSS or total system VM cost. **HVF kernel memory,
kernel-owned page tables/VM allocations, and unrelated supervisor/tool memory are
NOT attributed**. Configured guest RAM/heap is not presented as measured memory.

Median MiB (n=30 each). “Increment” is observed maximum minus the same process
counter immediately before launch/request, including allocations retained by the
worker; it is not a claim of marginal bytes per concurrently resident sandbox.

| Mode / workload | Total footprint | Total RSS | Footprint increment | RSS increment |
|---|---:|---:|---:|---:|
| jitk cold / return2 | 10.649 | 15.406 | 10.532 | 15.062 |
| HL strict / return2 | 2.266 | 8.977 | 2.164 | 8.734 |
| HL fresh / return2 | 2071.488 | 1826.750 | 67.399 | 66.883 |
| HL logical clone / return2 | 4.174 | 9.594 | 0.016 | 0.000 |
| jitk cold / JSON 1 MiB | 14.876 | 19.633 | 14.750 | 19.297 |
| HL strict / JSON 1 MiB | 6.375 | 17.227 | 6.235 | 16.945 |
| HL fresh / JSON 1 MiB | 2071.614 | 1774.328 | 68.203 | 70.453 |
| HL logical clone / JSON 1 MiB | 8.088 | 17.406 | 4.156 | 8.219 |

**Fresh-source retention is material:** that resident worker baseline grew from
1.563 to 2,007.474 MiB footprint across 150 source initializations, plateauing
after roughly 60–75 jobs. Only one job sandbox was live; it is dropped after every
done. The ~2 GiB retained process footprint is observed, not “2 GiB/job” and not
proven to be a leak. Allocation/caching attribution is UNVERIFIED. The return2
per-job observed footprint increment is 67.399 MiB. Logical clone increment is
0.016 MiB for return2 but 4.156 MiB for JSON; do not generalize the tiny case.
`raw-summary.json` and `memory-details.json` include median/p90/p99 for every case.

## Backend/protocol adapter — FIXED, with one typing integration item

- `r2/backend.ts` implements 04 R2 `park/read/send/kill/exited`, reads ready(v=1),
  and speaks only v1 `run/ns`, call IDs 1..4096, ARRAY args, ret ok/typed err,
  logs, and done ok/typed err. The trusted 04 executor owns policy and tools.
- Separate signed Rust worker with `panic=abort`, empty environment, no filesystem
  module loader; separate Python SIGKILL watchdog survives a blocked Node loop.
  `exited` joins worker/watchdog reap. OS confinement remains security-owner work.
- `protocol.ts` copies 03 R2 dispatcher (latest UTF-8 code/log budgets), with raw
  DEL rejection fixed to match normative 0x20–0x7E. Includes schema, duplicate-key,
  depth, frame, call, outstanding, inflight, byte, log and state limits.
- **11/11 adapter checks PASS**, **6/6 actual 04 R2 executor checks PASS**, strict
  TS `--noEmit` PASS. Tests include tools, denial, logs/Unicode, malformed schema,
  abort, CPU watchdog, fresh state, and normal/escaped DEL distinction.
- **BLOCKED only at typed selector:** 04 R2 restricts Backend.kind to jitk|local-qjs.
  Owner 04 must add hyperlight-js for direct TS assignment. `BaselineBackend`
  widens only that tag; all other members typecheck against the actual interface.
  Runtime integration is already measured with the unchanged built 04 executor.
  See `INTEGRATION.md`; 09 did not modify 04 files or impersonate the jitk tag.
- UNVERIFIED/unsupported: guest setTimeout shim, cache-cold OCI performance,
  Linux/KVM performance, production snapshot digest enforcement/worker confinement.
  No full production-readiness claim is made from the benchmark adapter.

`6d825f225d7beff5a9707ec10db63cf3347524dc3ba183b16d0f6d809d2f0929`.

or that this proves universal impossibility. This unmodified Linux binary does
not initialize through this Hyperlight API/version; its expected Linux ABI is
absent. Arch 10 owns jitk syscall-growth requirements; Lua-on-jitk is not claimed.

## Honest verdict — comparable strict single-use cold modes

95% CIs below are paired bootstrap (10,000 resamples of the 30 interleaved blocks)
for the difference of medians, **jitk minus HL strict**, in ms. They describe this
loaded host/run; not portable confidence or tail SLAs. n=30 p99 is simply the max.

| Workload | Winner | Median advantage | 95% CI, jitk−HL | Confidence |
|---|---|---:|---:|---|
| return 2 | Hyperlight | 1.817 ms; 1.22× | +0.654 to +2.464 | moderate, local |
| one 5 ms tool | Hyperlight | 2.586 ms; 1.18× | +0.683 to +7.430 | moderate, local |
| ten parallel 5 ms tools | jitk | 45.906 ms; 3.95× | −48.865 to −44.403 | strong, local + concurrency evidence |
| 1 MiB JSON | jitk | 3.682 ms; 1.23× | −10.345 to −3.133 | moderate, local |
| 50 ms loop | inconclusive | nominal HL 1.094 ms | −0.140 to +2.386 | insufficient for winner |
| return2 process footprint | Hyperlight | 2.266 vs 10.649 MiB; 4.70× | sampled counters, not total HVF | strong observation; limited attribution |

Logical snapshot clone return2 is **0.847 ms**, 11.7× below cold jitk, but has the
shared-HW-VM contract above. Its ten-tool case is still **53.525 ms**, slower
even than cold jitk. Fresh initialization is slower and retains far more process
memory than snapshot reuse in this build. These are real baseline options, not
interchangeable isolation/density claims. `verdict.json` contains all comparisons.

**Round-1 conclusion revised:** the blanket “jitk is not justified by JS-only
performance” is rejected by the concurrent-tools and JSON measurements. Hyperlight
wins other JS cases and sampled process memory. D11 baseline status and D14 Linux
ABI differentiator are supported; no disagreement with DECISIONS-R1.
