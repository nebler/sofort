# Sofort v1: goal, scope and exit criteria (2026-10-25)

Status: **proposal**, written after round 6. It is based on:
- `arch/jitk/shard/RESULTS-R6.md` (shard port);
- `arch/research/native-census/RESULTS.md` (native tools census);
- `arch/research/perf/SUMMARY.md` (perf round);
- `arch/architecture/ARCHITECTURE.md`.

Background and pitch material: `demo.md`.

Labels: **[M]** measured (nested KVM unless noted), **[T]** target, **[E]** estimate.

## 1. One sentence

**A local MCP sandbox where Claude Code, Cursor or Codex run agent code *and real CLI tools*, each in a throwaway hardware-isolated computer that costs about 0.5 MiB and boots from a snapshot in about a millisecond.**

v1 proves the two differentiators we can measure now:
1. **density with the real kernel**, at Hyperlight-class memory;
2. **unmodified native Linux tools**, which Hyperlight and Wasm can't run.

Pause, fork and move across hosts are the **v2 headline** (see section 8).

## 2. Why this v1
- **It proves the differentiators with numbers, not projections.**
  - Round 6 measured 0.48–0.55 MiB/VM for small runs with the real kernel [M].
  - 9 of 15 native tool profiles already run unchanged [M].
- **It runs on hardware we own:** the Mac (dev) and the M1 Air with Asahi (reference metal). No cloud and no new servers.
- **It is installable and demoable.** That matters for the launch and for the CV capstone.
- **It is the foundation v2 needs.** Restore-from-snapshot already works. Pausing at a tool call means snapshotting a slot's dirty pages and registers at WAIT, which is a small step from here.

## 3. Scope

| Area | v1 |
|---|---|
| **Platforms** | **Linux arm64 KVM via the shard** is the product runtime. The M1 Air with Asahi is the reference machine; Graviton and other GICv3 ARM hosts work the same way. **macOS** keeps today's libkrun backend as the developer path. |
| **Runtimes** | JS code mode (QuickJS), plus **native tools**: jq (musl), read-only SQLite, BusyBox text applets (sed/awk/grep/sort/wc/tar-list), Lua, MicroPython, gzip and zstd. **Stretch:** ripgrep (`-j1 --no-mmap`). |
| **Interface** | One MCP server with two tools:<br>• `execute(code)`: JS with tool stubs;<br>• `run(tool, args, files)`: native tools.<br>Inputs are read-only files bound late per run. Outputs are stdout bytes, stderr bytes and an exit code. |
| **Isolation** | One hardware VM per run; no network; effects only through tools. **Fresh state every run**: generation, entropy, clock and **QuickJS RNG**. A watchdog deadline per run. Snapshots never contain tenant data or credentials. |
| **Install** | One command (`npx sofort` or `brew install sofort`), then wired into Claude Code in under 60 seconds. |
| **Proof** | A published same-host benchmark against Firecracker-snapshot, Hyperlight and `docker run`; the hostile-guest suites; a claims doc listing what is and isn't proven. |

### Decision recorded
**Native tools with byte streams are Linux-only in v1.** On macOS v1 offers JS code mode plus text-output tools on the existing libkrun path.
- Bringing the Mac to the ring ABI is architecture gate 7 (the HVF worker) and is deferred.
- The user may revisit this.

## 4. Exit criteria
All measured on **the M1 Air with Asahi (metal, no nesting)** unless noted. Every number needs method, n, load and raw data.

| # | Criterion | Target | Where we are |
|---|---|---|---|
| 1 | Marginal memory, small run (return2 / one tool / `Promise.all(10)`) | ≤0.6 MiB/VM | 0.48 / 0.50 / 0.55 [M, nested] |
| 2 | Restore/reset p99 | ≤1 ms | 2.8–6.0 ms [M, nested] |
| 3 | Execute → result p50 (small run, one immediate tool) | ≤2 ms | 31–40 ms [M, nested] |
| 4 | Service CPU per tiny run | ≤2 CPU-ms | 34–44 ms [M, nested] |
| 5 | Concurrent waiting runs, fixed thread count | ≥1,000 | 1,024 on 1 thread [M, nested] |
| 6 | Restore cycles with zero leaks **and distinct `Math.random` per run** | 10,000 | 10,000 with no leaks, but `Math.random` repeats [M] |
| 7 | Native tools give byte-identical output to Linux on a test corpus | jq, SQLite, BusyBox applets, gzip, zstd, Lua, MicroPython | 9 profiles pass; SQLite and gzip/zstd blocked [M] |
| 8 | Deadline kill per run | ≤50 ms | external SIGKILL only; no leases [M] |
| 9 | `make -C arch/jitk test` | green, including the nested Linux suite or a documented replacement | nested Linux suite times out (1,800 s), independent of R6 [M] |
| 10 | Fresh install → Claude Code runs `execute` and `run` | ≤60 s on a clean Mac | not built |

**If criteria 2–4 cannot reach their targets on metal**, publish the measured numbers honestly and change the pitch from "about a millisecond" to the measured value. Don't ship until the criteria are re-evaluated with the user.

## 5. Not in v1
- Pause, fork and move across hosts; durable continuations; the effects journal (v2).
- The Wasm tier, x86-64, Windows, a hosted API.
- Go tools and threads (`clone`/`futex`/`epoll`), a writable filesystem, network access, CPython.
- Cap'n Web, `/cap` files beyond the minimum, Cloudflare integration.
- Moving the Mac to the ring ABI (gate 7) and removing libkrun from the Mac path (gate 8).

## 7. Launch demo for v1
Pick one, depending on the metal numbers:
- **"1,000 untrusted files, 1,000 computers."** jq and SQLite over a folder of hostile inputs, one fresh VM per file. The tiles turn green, the hostile ones turn red and are contained, and everything finishes in seconds, next to `docker run` per file.
- **"A million computers for a nickel."** A live counter of fresh restores with the real CPU bill. Only after criterion 4 is met on metal.

Honesty rules from `demo.md` apply:
- label every number with its environment;
- compare marginal memory, not configured RAM;
- never call a raw parked path "cold".

## 8. What comes after v1
- **v1.1 (stretch):** same-host "park to disk and resume" at a tool call. Snapshot the slot's dirty pages and registers at WAIT, then restore later in a new process. It teases the "Pull the plug" story.
- **v2: computers that pause, fork and move.** It needs:
  - the effects journal (prepared/dispatched/completed/delivered, idempotency keys, fencing);
  - cross-host restore;
  - forks with fenced effects;
  - the flagship "Pull the plug" demo.
- **Reach, after v2 or when demand shows up:**
  - the Wasm tier (portable, pause/fork prototype already measured);
  - x86-64 (about 20–35 days after the shard port);
  - Raspberry Pi (GICv2, 3–5 days);
  - a hosted API;
  - a decision on threads for Go tools versus a Linux tier.
