# jitk-abi: the ring and IPC ABI, defined once

A `no_std` Rust crate holding every value the guest kernel, the KVM shard and
the Node executor must agree on (R10 change #2, R9 N19):

- `layout`: guest physical layout per architecture (`AARCH64`). GPAs (kernel
  view) and RAM offsets (shard view) are both derived from one `Layout`.
- `ring`: the guest ring ABI of `shard/ABI-R7.md`: control-page magic and
  field offsets, doorbell operations, record kinds/flags and the one
  `RecordHeader` codec, the JS profile's pseudo-fds, and the guest limits
  (calls, call/reply/done/source bytes, argv, output cap).
- `arena`: arena classes (`glue-2m`, `glue-4m`) and the `JTKARENA` layout
  record that the kernel links and the preparer checks.
- `ipc`: Node <-> shard IPC geometry, header offsets, message kinds and
  per-kind bounds of `executor/ipc/ABI.md`.
- `ABI_VERSION`: sent by the shard in READY (u32 LE payload) and recorded as
  `abiVersion` in the prepared snapshot `.identity`; Node and the shard refuse
  a mismatch. Bump it with any peer-visible change.

`guest-payloads.json` is the shared CALL/DONE payload acceptance corpus for
the shard's and the executor's tests.

The shard depends on the crate (`path = "../abi"`). The ring kernel mounts
`src/lib.rs` as `mod abi` (`#[path]`): a Cargo dependency would change the
kernel crate's metadata hash and with it the image bytes, and the kernel keeps
refactors image-identical (`kernel/ARCH.md`). So `src/lib.rs` stays
self-contained (no dependencies, no `crate::` paths). The ring image also
defines the linker's `__ring_arena` from `ring::ARENA_GPA`
(`kernel/src/arch/aarch64/mmu_ring.rs`), so no build passes `--defsym`.

Everything else is generated by `src/bin/abi-gen.rs` and checked in:

| Output | Consumer |
|---|---|
| `executor/abi.ts` | `executor/shard-ipc.ts` (`IPC`), `shard-backend.ts`, `prepared-helpers.mjs` callers, `shard/snapshot.ts` |
| `executor/ipc/bridge_abi.h` | `executor/ipc/bridge.c` |
| `kernel/ring-bootstrap.js` (from `.js.in`) | the ring kernel image, the snapshot helper hash |
| `kernel/payload/ring-rng/checkpoint.h` (from `.h.in`) | the ring QuickJS payload build |
| `executor/shard-helpers.js` (from `.js.in`) | the prepared shard helpers (call budget for logs), the snapshot helper hash |

The three guest files are templates (`{{NAME}}` placeholders) so their output
stays byte-identical to what the images embed. Edit the crate or a template,
then:

```sh
make -C arch/jitk/abi gen    # rewrite the generated files
make -C arch/jitk/abi test   # cargo test, fmt, clippy, abi-gen --check (part of make test)
```
