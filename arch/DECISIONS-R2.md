## Decisions
- **E1 — one integrated tree.** Round 3 consolidates the work into `arch/jitk/` (layout: `kernel/ vmm/ executor/ protocol/ grow/ bench/ linux/ docs/`). Owners write their subtree there, and **only** their subtree:

  | Subtree | Owner |
  |---|---|
  | `kernel/` | 02 |
  | `vmm/` | 01 |
  | `protocol/` | 03 |
  | `executor/` | 04 |
  | `linux/` | 05 |
  | `bench/` | 06 |
  | `grow/` | 08 |
  | `bench/hyperlight/` | 09 |
  | `docs/` | 10 |
  | `vmm/sandbox/` and `executor/policy/` | 07 |

  Each subtree gets a README with build/run commands. A top-level `Makefile` (owned by 10) runs `make build test bench demo`.
- **E2 — kernel layout.** Adopt 08's one file per syscall in `kernel/src/syscalls/<name>.rs`, with fixed dispatch slots generated by `build.rs`. The packer must reject RX/RW segments that share a page (10's finding).
- **E3 — the VMM ships with:**
  - 07's precompiled Seatbelt profile, applied in-process before `build()`. The supervisor compiles it once.
  - 07's libkrun robustness patch.
  - The control-RX one-liner.
  - `panic=abort`.
  - A Linux build with seccomp, Landlock, netns and rlimits. cgroups use CLONE_INTO_CGROUP only.

  On Linux the supervisor sends `run` only after the sandbox ack **and** READY.
- **E4 — results resolve before reap.** The executor resolves on a validated `done`. Kill, reap and refill happen off the critical path; the capacity token is still held until reap.
- **E5 — policy.** Use 07's `policy.mjs` rules (minted per-call credentials; private-read→exfil-capable needs approval; tool-output→state-change needs approval) instead of 04's whole-run taint. Host-side opaque handles are v1.
- **E6 — benchmarks are load-gated.** 06 builds `bench/` to sample only while the 1-minute load is below a threshold, or to interleave and report load per sample, and produces **one canonical numbers table** that every claim cites. Fair comparison: the jitk parked pool against Hyperlight strict-snapshot, plus cold against cold.
- **E7 — Linux.** Run the full Linux kit functionally under nested KVM (07's harness) on this Mac. Only performance waits for metal, which needs user approval.
- **E8 — D14 demo.** Run Lua 5.4 static on jitk by growing the missing syscalls with the grow loop: signals return ENOSYS, plus whatever else is missing.
- **E9 — CVE text.** CVE-2026-1144 is quickjs-ng, not bellard. ITScape is not reachable because libkrun creates no ITS and we run a single vCPU.

## Round-3 gates
- **H1** `make build test` passes on macOS from a clean checkout of `arch/jitk/`.
- **H2** `make demo` runs, in this order:
  1. `executor.execute()` on jitk returns the result.
  2. The grow loop regrows a deleted syscall.
  3. Lua runs on the grown kernel.
- **H3** The Linux nested-KVM functional suite passes: boot, qjs tool call, seccomp-kill test, fault guests.
- **H4** The canonical bench table, load-gated: cold, parked, vs Hyperlight (strict + clone), refill/s, and CPU-ms/VM.
- **H5** Hostile-guest containment suite on the integrated build. Each attack must be killed or handled with no host effect:
  - forged frames
  - floods
  - control bytes
  - runaway CPU
  - memory exhaustion
  - bad hvc/PSCI
  - console abuse
