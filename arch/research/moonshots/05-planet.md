# Cloudflare maximalism: the planet as one computer

Research date: **2026-10-27**. Lens: **CLOUDFLARE MAXIMALISM — THE PLANET AS ONE COMPUTER**.

**I — Bet on an agent whose shape and location change while its identity survives:** one continuation in a phone, eight or thirty-two speculative workers for thirty seconds, then one continuation again. Cloudflare supplies much of the substrate. The interesting missing contract is a program that can change execution hosts, fan out, surrender its old authority, and become a downloadable artifact again. A giant deployment map alone is a weak contribution.

**Labels:** **F** = sourced fact, including an attributed vendor claim; **M-prior** = an existing project measurement, not rerun here; **I** = inference/design/judgment; **E** = estimate or proposed experimental threshold. All web sources were accessed **2026-10-27**; publication/update dates are included where available. There are **no new runtime measurements** in this report. Arithmetic below was checked locally; it remains **E**, since its workload assumptions are hypothetical. Proofs and tweets describe proposed demonstrations, not completed deployments.

**F — Background read:** [the brief](BRIEF.md), [landscape](../v8/02-landscape.md), [roadblocks](../v8/03-roadblocks.md), [signal](../v8/06-signal.md), [Wasm portability](../portability/02-wasm.md), [GrowOS](../../jitk/grow/README.md), and [demo.md, especially §§0, 9, 10](../../../demo.md). ## 1. What exists on the planet in October 2026

**F — The incumbent already understands the thesis.** Cloudflare announced an early preview of `@cloudflare/computer` on **August 3, 2026**: an agent runtime orchestrating execution across isolates, containers, and a web browser. Consequently, “give every agent a computer” and “choose the cheapest runtime” are occupied positioning. Its announcement does not establish an independently downloadable, cross-host live-heap continuation contract. **I:** build a sharp addition to that ecosystem, preferably an adapter, rather than another general agent platform. [Cloudflare announcement](https://blog.cloudflare.com/cloudflare-computer/).

**F — The network is large; its products have different placement semantics.** Cloudflare's current network page enumerates **348 cities**, satisfying the requested **330+** baseline; another official product page still says 330+. These are network-presence figures, not promises that every stateful/GPU product can execute in each city. The network page's extracted animated counters also contain zero placeholders; use its enumerated locations rather than deriving a latency SLA from its promotional counters. [Network, current](https://www.cloudflare.com/network/), [Realtime product page, current](https://www.cloudflare.com/products/turn-sfu/).

## 2. The physics and bill that every idea must survive

### Small-file computers are real; arbitrary small computers are not

**M-prior — Local evidence:** the minimal continuation was **99,854 bytes gzip**, backed by **2 MiB raw linear memory**, with a separate **966,584-byte Wasm engine**. Subsequent workloads produced **1.50 MB compressed** with Zod, **2.88 MB** with 5,000 retained retrieval records, and **6.39 MB** with a 6 MiB binary buffer. Warm instantiate/grow/restore medians were roughly **0.27–0.79 ms**; compression alone reached **116–136 ms** on larger cases. These Mac results exclude network, cold owner startup, policy, persistence and decompression. [Portability](../portability/02-wasm.md), [roadblocks §5](../v8/03-roadblocks.md#5-real-snapshot-sizes-forks-and-storageegress-economics).

**M-prior — CPU/memory qualification matters more than the demo's empty heap.** QuickJS/Wasm glue was **5.2–11.5×** slower than direct V8 in paired tests; a numeric loop was **31.1×** slower. The spike's nominal **16 MiB** engine cap allowed **31 MiB** of retained buffers because allocator accounting was wrong. Its fixed **32 MiB** Wasm ceiling worked, but excludes host memory. Freeing a buffer left the high-water image effectively unchanged. [Roadblocks §§1–2, 5, 7](../v8/03-roadblocks.md).

**I — Consequences:** keep bulk data/model weights outside the heap, use handles and bounded windows, repair allocator/stack limits, and meter deterministic work between awaits. A same-thread timeout cannot interrupt synchronous Wasm. **F:** Workers' clocks do not advance during synchronous computation; ordinary Workers also require deployed Wasm modules rather than arbitrary byte-based compilation, and provide no Web Worker threading API. **I:** use a fixed interpreter, work quotas and platform CPU enforcement. A snapshot can retain old sensitive bytes after guest objects are freed. Shared templates require deliberate sanitization and separation of per-user data, not just compression. [Workers standards](https://developers.cloudflare.com/workers/runtime-apis/web-standards/), [Workers Wasm](https://developers.cloudflare.com/workers/runtime-apis/webassembly/), both updated Apr 23, 2026.

### A billion sleepers: almost no compute is not almost no bill

**E — One retained image per agent, decimal units, one billion agents, no free allowances, replicas, histories or metadata:**

| Stored bytes per agent | Total state | R2 Standard storage/month |
| --- | ---: | ---: |
| 1 KB unique delta over a shared base, hypothetical | 1 TB | $15 |
| 100 KB, minimal demo class | 100 TB | $1,500 |
| 1.5 MB | 1.5 PB | $22,500 |
| 3 MB | 3 PB | $45,000 |
| 6.4 MB | 6.4 PB | $96,000 |

**E — Operations become the floor.** One billion initial object writes cost approximately **$4,500**; one billion reads **$360**. A complete wake with one new image PUT, one GET, one 20 ms Worker slice and one billed Worker request is approximately **$5,560 per billion wakes**, before ownership, queues, additional slices, model calls or tools. Ten retained images multiply storage tenfold. A billion 1 KB records in individual objects can have a $15 storage term and a much larger creation/maintenance term. These calculations use [R2 rates](https://developers.cloudflare.com/r2/pricing/) and [Workers rates, Oct 2](https://developers.cloudflare.com/workers/platform/pricing/).

**E/I — Avoid the Dynamic Worker identity tax:** a billion distinct newly invoked IDs in one day would imply roughly **$2 million** in identity charges before allowances. Inactive R2 files do not incur that charge; loading each as unique Dynamic Worker code/ID does. Use ordinary deployed Workers with the fixed interpreter, or a small stable-ID adapter pool taking snapshots as data. Fresh Wasm instances and request-scoped broker grants still separate guests. The billing API's cache key is not a tenant security boundary. [Identity billing](https://developers.cloudflare.com/dynamic-workers/pricing/).

**F/I — Existing sleepers are a serious baseline:** eligible idle DOs already avoid duration billing, and Workflows already exclude waits from running concurrency. A capsule earns its complexity through portable continuation/fork semantics, not an invented contrast with an always-on VM. [DO billing, Oct 18](https://developers.cloudflare.com/durable-objects/platform/pricing/).

**E — Waking the billion simultaneously is another system.** At a queue's published 5,000 messages/s, enqueueing a billion wakes through one queue alone takes **55.6 hours**, before downstream limits. A billion wakes/day averages about **11,574/s**, requiring at least three queues on rate alone and more capacity for bursts. Three normal queue operations per message add about **$1,200/billion messages** before retries and included usage. No one-DO global registry: shard address space and effect ownership. [Queue rates](https://developers.cloudflare.com/queues/platform/limits/), [queue billing](https://developers.cloudflare.com/queues/platform/pricing/).

### The honest value of X in “wakes under X ms anywhere”

**E — Latency decomposition:** `wake = client→ingress + authorization/ownership + checkpoint fetch + decode/verify + runtime readiness + restore + first useful guest slice`. Model/tool latency comes after this and must be reported separately. A receipt must distinguish the execution colo from the ingress colo and the ownership coordinator.

**E — Targets worth testing, not promises:**

| Wake class | Explicit conditions | Proposed target |
| --- | --- | --- |
| Local ready runtime | Compatible compiled module and raw image already in RAM | **p95 <10 ms** through first guest frame; excludes network/persistence |
| Nearby prepared edge | At most 100 KB compressed, immutable image cached, compatible runtime warm; authority cost included | **p95 <250 ms client-to-first-frame** on declared test networks |
| Uncached, multi-MB image | 3 MB fetched remotely, warm and cold runtime cohorts separated | Initial gate **p95 <2 s on ≥100 Mbit/s test links**; publish failures and geography |
| Universal global wake | Arbitrary bandwidth, cache miss, distant ownership/data, cold runtime | **No defensible finite X established** |

**E — Why:** 3 MB alone takes **2.4 s at 10 Mbit/s**, before RTT; 100 KB takes **80 ms**. A 10,000 km fiber path at an assumed 200,000 km/s imposes roughly **50 ms one-way / 100 ms RTT** before path inflation and equipment. An authoritative cross-ocean ownership call can consume most of a 250 ms target. Cache replicas remove fetch distance, not consensus distance. R2 zero egress charges change money, not propagation speed.

**I — Publish “measured under X in these locations for this checkpoint/cache class,” never “under X anywhere.”** Cloudflare's Dynamic Workflows launch describes same-machine Dynamic Worker creation in single-digit milliseconds; that is a vendor startup claim, not capsule fetch+restore latency or a global tail guarantee. [May 1, 2026 announcement](https://blog.cloudflare.com/dynamic-workflows/).

## 3. Eight ideas, pushed and pressure-tested

The ranks below are judgments (**I**), not scores pretending to be measurements. Every proof is deliberately scoped to **one or two weeks** and a trusted/preset workload; none estimates the time to ship a hostile multi-tenant platform.

### A. The computer follows its user — rank 3

**I — One sentence:** your personal agent's continuation follows your active device and nearest useful execution site. **100× version:** a billion people own a persistent personal computer whose execution moves between their phones, browsers, home machines and edge sites; replacing a device changes the host, not the agent's identity or accumulated running state.

**F — Lineage:** Emerald moved fine-grained objects and process objects, rather than treating the whole machine as the mobility unit. Sprite delivered transparent process migration but encountered difficult open-file/distributed-state handling and centralized-resource bottlenecks. These worked within their intended environments; “failed” would be the wrong history. [Jul et al., Feb 1988, original paper](https://people.eecs.berkeley.edu/~prabal/resources/osprelim/JLH%2B88.pdf), [Douglis/Ousterhout, Aug 1991](https://web.stanford.edu/~ouster/cgi-bin/papers/migration-spe.pdf). **I — Old ceiling / new difference:** heterogeneous runtimes and ambient OS resources made arbitrary migration expensive. A fixed Wasm build and a narrow, explicitly rebound tool boundary reduce that surface; stronger agents make the persistent task state worth carrying.

**I — Value/model scaling:** personal assistants, field-service software and accessibility products pay for continuity across intermittent devices. Better models accumulate longer, more useful plans and automate more device-local work. Moving a chat transcript is insufficient if the valuable work is a suspended generated program; if it is only chat, use ordinary database sync.

**E — First proof:** start in a laptop Web Worker, park on an approval with a closure/Map/cycle, persist to R2, destroy the owner, resume in hosted Workers, then transfer to a real Android/iOS browser. Test two region-hinted executors through distinct fetch destinations; measure actual locations rather than animate requested hints. Keep one DO as ownership authority and disclose its RTT. Guest CPU slices ≤100 ms, initial raw state cap 8 MiB, only one active authoritative branch.

**I — 60 s demo/hook:** close the laptop lid after the durable acknowledgment; scan the same URL on a phone, reveal the surviving local variable, then hand computation back to the edge. Draft tweet: “This agent's running state went laptop → Cloudflare → phone. I destroyed each old runtime. Same checkpoint lineage, same pending approval, new host. QuickJS/Wasm; timings and handoff ledger included.”

**E — Kill test:** in 1,000 interrupted handoffs, if the proposed implementation cannot preserve a single effect owner with zero lost acknowledged events, stop migration work and retain checkpointed single-region execution.

### B. The computer follows its data — rank 2

**I — One sentence:** migrate an agent's continuation to the next data domain instead of repeatedly dragging data through the agent's home region. **100× version:** a planetary query/planning program visits thousands of independently administered data owners, performs local reasoning through narrow capabilities, and brings back only authorized summaries or proposals.

**F — Lineage:** Obliq transmitted closures with lexical bindings that retained their original sites; its paper distinguishes moving computation from copying source and deliberately keeps state objects local. MapReduce later demonstrated the value of scheduling work near input. [Cardelli, Winter 1995](https://www.usenix.org/publications/compsystems/1995/win_cardelli.pdf), [Dean/Ghemawat, 2004](https://research.google/pubs/mapreduce-simplified-data-processing-on-large-clusters/). **I — Old ceiling / new difference:** retained remote references can preserve network dependence, and fixed batch operators do not cover open-ended agent plans. A capsule can cross a host boundary at a tool await while each data owner decides what capabilities and outputs to permit.

**I — Value/model scaling:** data platforms and companies with regional/private datasets pay for less movement and fewer serial WAN round trips. Better models write richer local analyses and decide when to revisit a domain. Privacy is a host policy, not a consequence of Wasm: an unrestricted tool or returned payload can still export data.

**E — First proof:** a two-domain incident investigator first analyzes synthetic EU logs, then US deployment metadata, retaining the live investigation continuation between domains. Compare three identical-result paths: fixed home executor + Hyperdrive, stationary executor with Smart Placement, and one explicit mid-task handoff. Use fetch handlers for placement; RPC-only placement is not supported. Audit every exported field. Keep the mobile heap free of restricted raw records; a capsule containing them would itself violate the intended boundary.

**E — Limits/economics:** if a 3 MB move costs 0.5 s and avoids 20 sequential round trips each reduced by 100 ms, approximate net gain is **1.5 s**. If it avoids only two, stay put. Enforce a minimum predicted benefit and placement dwell time to avoid ping-pong. Jurisdiction-pinned data need jurisdiction-appropriate tools; Smart Placement alone is not a residency guarantee.

**I — 60 s demo/hook:** show raw bytes staying in their domain while one function crosses two hosts and makes its next decision. Tweet: “Instead of bringing two regions' logs to an agent, I sent its continuation to the logs. Same investigation, restricted local tools, measured WAN calls avoided. Compared against Smart Placement + Hyperdrive.”

**E — Kill test:** demote migration if it fails to improve p95 completion time by **30%** on a real, chatty two-domain workload against the optimized stationary baseline at equal result quality and access policy.

### C. A billion sleeping agents as an object population — rank 6

**I — One sentence:** persist each waiting program as immutable state plus a wake address, with no allocated executor while it sleeps. **100× version:** every order, repair, scientific instrument, contract and long-lived question has an executable future that can wait years, awaken on mail/webhook/sensor input, and move to a suitable host.

**F — Lineage:** Orleans' virtual actors separated logical identity from activation and relieved developers of much activation/resource management. It is a successful precedent, not a failed one. [Bernstein et al., March 2014](https://www.microsoft.com/en-us/research/publication/orleans-distributed-virtual-actors-for-programmability-and-scalability/). **I — Old ceiling / new difference:** actor activation/state persistence does not by itself provide an exported opaque running continuation across a browser and different cloud hosts. Capsules add that artifact boundary. Native Workflows/Agents already cover most ordinary waits, which keeps this idea below the top three.

**I — Value/model scaling:** after-sales support, industrial maintenance, research monitoring and procurement pay per meaningful event, not per continuously running agent. Stronger models can handle rarer, less predefined events and resume more sophisticated prepared logic. A “billion agents” identity count without useful independent state is a storage demo.

**E — First proof:** store **10,000 genuinely distinct** suspended programs, vary retained data and pending calls, and leave them without heartbeat/keepalive. Wake a random sample through HTTPS and inbound email after destroying all execution owners. Report object count, stored bytes, operation count and three wake classes from §2. Target **p95 <250 ms only for the prepared 100 KB class**; test remote 3 MB cold misses separately.

**E/I — Limit:** the economic range is §2's **$1,500–96,000/month** for a billion full images, before replicas/history. A **$15/month** unique-delta population is a research target, not today's measured snapshot size. Pack/deduplicate immutable bases, but retain random access, integrity, deletion and bounded restore chains. Persist long-lived timers externally; queue retention is finite.

**I — 45 s demo/hook:** show an empty executor pool, wake arbitrary old programs, inspect their different closures and display the measured bill. Tweet: “10,000 suspended programs; zero resident executors while asleep. R2 stores the state. An email wakes one inside its function. Here's the stored byte count, real wake distribution, and the billion-agent cost calculation.”

**E — Kill test:** if realistic capsule customers get no necessary capability beyond native Workflows/DO hibernation at a competitive total cost, drop the independent sleeper product; keep persistence as infrastructure for other ideas.

### D. One program, live cells across cities and devices — rank 4

**I — One sentence:** a program is a graph of resumable cells, each placed with its data or human, communicating through declared messages. **100× version:** a company or simulation is one inspectable executable graph spanning hundreds of cities and millions of devices; cells move, fork and retire without recreating the global application from scratch.

**F — Lineage:** Obliq explored distributed lexical scope; CRDTs give explicit conditions for convergence under concurrent updates. They do not merge arbitrary execution heaps. [Obliq, 1995](https://www.usenix.org/publications/compsystems/1995/win_cardelli.pdf), [Shapiro et al., Jan 2011](https://perso.lip6.fr/Marc.Shapiro/papers/2011/Comprehensive-CRDTs-RR7506-2011-01.pdf). **I — Old ceiling / new difference:** location transparency hides expensive links, while consistency is application-specific. Keep remote boundaries visible. Agents may generate and repair the cell graph, but a deterministic checker must enforce schemas, permissions and merge algebra.

**I — Value/model scaling:** collaborative incident rooms, multiplayer simulations and distributed research organizations pay for local responsiveness and inspectable recovery. Stronger models can decompose work and reason about the graph; they cannot wish away partitions or invent a correct arbitrary-heap merge.

**E — First proof:** four cells: EU telemetry, US planner, a phone-owned annotation cell, and a browser-owned private document index. Use per-cell DO mailboxes plus Wasm continuations, typed events, and an existing CRDT implementation for annotations only. Disconnect the phone for 60 s; other cells continue; reconnect and converge. Export a root manifest containing checkpoint hashes and mailbox offsets. A root file references multiple states; only a deliberately assembled archive is self-contained.

**E/I — Limits:** each DO remains single-threaded; no planetary shared RAM. Allocate at most four active guest instances per request and shard queues. At an assumed **100 ms RTT**, one serial remote dependency per step limits a chain to about **10 steps/s** regardless of CPU abundance. Make local work coarse and messages bounded. Irreversible shared decisions serialize through an owner; CRDTs handle only data with the correct merge semantics.

**I — 75 s demo/hook:** click one program graph, inspect the actual cell on the phone, partition it, migrate a server cell, then reconnect. Tweet: “One program, four live cells: two regions, a browser and a phone. I disconnected one and moved another. Messages and checkpoint hashes explain what survived. Explicit cells; no shared-memory illusion.”

**E — Kill test:** if one independently written cell migration/partition scenario requires coordinated recovery changes across every other cell, the abstraction has failed; return to ordinary services with explicit checkpoints.

### E. Every URL is a resumable computer — rank 5

**I — One sentence:** a URL identifies a computation with a mailbox, durable history and a downloadable continuation, rather than just a document or endpoint. **100× version:** the internet becomes an operating environment where every long-lived problem has an address, can receive events, grant limited capabilities, fork possible futures, and resume on its owner's device.

**F — Lineage:** Plan 9 used network resources and per-process namespaces to recreate a private computing environment wherever needed. It deliberately rebuilt a broad software environment around that model. [Pike et al., 1995](https://9p.io/sys/doc/9.html). **I — Old ceiling / new difference:** adopting a whole OS is a high integration cost; HTTPS, browser Wasm and existing identity systems allow a much narrower application contract. Cloudflare's Computer preview is already adjacent, so the URL must buy exportability and user ownership, not merely a pretty actor address.

**I — Value/model scaling:** a hiring process, support case, procurement negotiation or research notebook becomes something participants can return to and act upon. SaaS vendors pay for persistent, portable interactions. More capable models turn an addressed object from a chat log into useful ongoing work; ordinary CRUD remains the baseline.

**E — First proof:** `/computer/<id>` renders state without executing effects; authenticated `POST /events` wakes it; `POST /fork` makes a proposal branch; `GET /checkpoint` exports an authorized snapshot. A pending procurement scenario receives a mail reply, parks for approval, and later resumes in an offline browser with tool calls disabled. Use a DO only for the live address/authority record and R2 for immutable content.

**I — Limits:** a public URL is a name, not permission. Link previews, crawlers and GET prefetch must never approve/send/buy. Separate address, authentication and per-action grants. Offline execution can prepare a proposal but cannot authoritatively commit remote writes without reconnecting. Email replies are input events, not automatic authorization. **E — Initial envelope:** at most **64 KB per delivered event**, **8 MiB raw checkpoint**, and **100 ms guest CPU per slice**; deliver attachments by bounded blob handle rather than embedding them in the continuation.

**I — 60 s demo/hook:** send a link to a paused problem, let a second person inspect/fork it, export the file and continue without the origin service. Tweet: “This URL names a suspended program. Reply by email to wake it; download its checkpoint to continue in your browser. GET is read-only. The live tool authority stays in a separate ledger.”

**E — Kill test:** if an adopter needs a custom editor, custom model harness and custom identity stack before one URL is useful, reduce it to a capsule adapter for existing applications; drop the internet-OS product pitch.

### F. Become a swarm for thirty seconds, then one file again — rank 1

**I — One sentence:** an agent forks its actual parked continuation into bounded speculative branches, joins typed results, and returns to one portable continuation. **100× version:** every difficult decision can briefly rent a topology of hundreds of specialists across data owners and devices, then collapse into a compact accountable future without maintaining a permanent swarm.

**F — Lineage:** Cilk made fork/join and work/span central to efficient parallel computation; MapReduce made distributed task execution/reduction practical at cluster scale. Neither makes arbitrary parallel state mergeable. [Blumofe et al., MIT report Jan 1996](https://dspace.mit.edu/entities/publication/39a8b7ab-7690-4016-94c0-5a0bfb328fa8), [MapReduce, 2004](https://research.google/pubs/mapreduce-simplified-data-processing-on-large-clusters/). **I — Old ceiling / new difference:** rigid tasks and serialized job boundaries fit batch work; tool-writing agents can propose useful branch strategies dynamically. A copied continuation preserves prepared local structures, while read-only branch capabilities make speculative execution tractable.

**I — Value/model scaling:** incident response, code repair and analytical decisions pay for reduced wall time or improved answers under a fixed spend. Stronger models make each branch more capable and produce more verifiable proposals. This survives model improvement only where independent search/tool work remains useful; many weak agents losing to one stronger call is a real kill condition.

**E — First proof:** preserve the investigator's closure/index and fork **8 branches**, each receiving a distinct hypothesis as the pending tool reply. Give branches read-only synthetic incident tools; collect bounded structured findings; resume the original parent's pending `swarm()` call with the selected/reduced result. Then checkpoint that parent. Do not merge eight heaps. Add **32 branches** only after the eight-branch system passes.

**E/I — Limits:** two coordinator DOs with four active Dynamic Workers each fit published fan-out limits. A 30 s **wall** interval is not a 30 s CPU requirement; cap guest CPU at **100 ms/invocation** and model/tool spend separately. Eight 3 MB image transfers total **24 MB** before outputs; ordinary Wasm instances are not portable CoW forks. With **32 × 30 CPU-seconds**, Workers CPU alone would be roughly **$0.0192**, but inference, identity charges, coordination and snapshots are extra. Choose a model/rate envelope that actually admits the burst; do not assume Paid frontier limits admit 32 immediate calls.

**I — 75 s demo/hook:** one state file blooms into eight actual branches, each produces a different checked finding, one branch is killed, surviving findings rejoin, and the parent returns to the phone as one file. Tweet: “My agent became eight read-only investigators for 30 seconds, joined their findings, then fit back into one checkpoint. Same pre-fork continuation. I killed one branch. All eight costs, host locations and the join are visible.”

**E — Kill test:** on a held-out incident/code-repair task set, if eight branches cannot improve success rate by **10 percentage points at equal budget**, or halve completion time at equal success rate, against one strong agent, stop selling swarming; preserve fork as a debugging/speculation primitive.

### G. The last mile is a computer: a personal device mesh — rank 8

**I — One sentence:** use a person's consenting devices as intermittent capsule executors, with edge recovery when they disappear. **100× version:** billions of foreground browsers become a cooperative compute fabric where small programs visit local capabilities and spare compute, while Cloudflare handles addresses, rendezvous and durable fallbacks.

**F — Lineage:** BOINC supported public-resource computation, owner resource allocation and validation across unreliable machines; Sprite reclaimed borrowed workstations when their owners returned. These systems succeeded for suitable work. [Anderson, Nov 2004](https://boinc.berkeley.edu/grid_paper_04.pdf), [Sprite, 1991](https://web.stanford.edu/~ouster/cgi-bin/papers/migration-spe.pdf). **I — Old ceiling / new difference:** participation, stragglers, validation and packaging constrain the usable workload. Browser Wasm removes installation for small guests and capsules permit checkpoint evacuation; mobile power and lifecycle limits remain.

**I — Value/model scaling:** the strongest buyer is a user who wants local private-data access or offline continuity, not a cloud operator seeking cheaper CPU. Better models create more useful local tools and can partition tasks, but cannot make an untrusted browser result authentic. Same-owner devices first; cross-owner jobs require cheap independent checking and explicit data grants.

**E — First proof:** laptop + two real phones voluntarily process ten independent, non-sensitive research batches in foreground tabs. Show pause/withdraw controls. Transfer state via WebRTC DataChannel with TURN credentials and HTTPS fallback; after a phone is closed without graceful shutdown, rerun from its last acknowledged checkpoint at the edge. Measure bytes, wall time, duplicate work and a coarse battery/thermal observation separately from CPU benchmarks.

**E/I — Limits:** use 100 KB–3 MB images, 8 MiB raw guest cap and short slices; no background uptime promise. Relaying **1 TB** through Realtime costs about **$50 marginally** after allowance, while **one million 20 ms Worker slices cost about $0.40 in CPU** before requests. Chasing CPU savings can lose immediately to coordination/network cost. A result hash proves bytes, not honest execution; reexecution can erase savings. Neither Wasm nor an encrypted connection hides a task's plaintext from its executing device.

**I — 60 s demo/hook:** devices visibly join, work and withdraw; one disappears and its task resumes elsewhere. Tweet: “These phones volunteered foreground browser time to the same checkpointable task pool. Close one and the edge takes over. No background-mining claim; here's the transfer cost and the work that stayed on-device.”

**E — Kill test:** if a useful workload has neither necessary local-data access nor measured total-cost/latency benefit over Workers after validation and transfer, drop the general compute mesh. Keep personal-device continuity from A.

### H. A continuation CDN: replicate possible futures — rank 7

**I — One sentence:** place immutable parked continuations near likely next interactions, allowing fast local speculative resume while one authority determines the committed future. **100× version:** the internet caches executable futures as naturally as static assets; an interactive program appears locally ready on several continents and becomes authoritative only when an event is accepted.

**F — Lineage:** Emerald separated object identity and location; CRDT research distinguishes convergent concurrent updates from operations needing stronger coordination. [Emerald, Feb 1988](https://people.eecs.berkeley.edu/~prabal/resources/osprelim/JLH%2B88.pdf), [CRDT report, 2011](https://perso.lip6.fr/Marc.Shapiro/papers/2011/Comprehensive-CRDTs-RR7506-2011-01.pdf). **I — Old ceiling / new difference:** moving/copying state has never removed consistency costs. Content hashes, ubiquitous edge execution and useful read-only agent speculation make prepositioning more practical, but cannot make two incompatible effects both correct.

**I — Value/model scaling:** globally shared approval tools, multiplayer planning and interactive assistants may pay for immediate speculative feedback. Stronger models make plausible branches worth preparing. Worse prediction wastes more inference and state transfer; caching speculative intelligence needs a hit-rate budget.

**E — First proof:** one 100 KB checkpoint, three geographically distinct real clients, immutable cached images, simultaneous replies. All three may compute previews; a DO accepts one logical event/version and the other two become explicit proposal branches. Compare warm/cold reads and one-region execution. Never put the mutable current-head pointer in ordinary KV or an unvalidated CDN response.

**E/I — Limits:** three full replicas triple stored bytes; a 3 MB image at **348 locations** would mean **1.044 GB per checkpoint**, before versions, if one implemented such replication. Cloudflare does not expose an API promising to pin this image in every city's cache. The practical first policy is demand caching near a handful of audiences. R2 allows only **one concurrent write/s to the same key**: use immutable versioned keys, not a global overwritten checkpoint. A remote commit fence retains its WAN RTT. [R2 limits, Jun 8](https://developers.cloudflare.com/r2/platform/limits/).

**I — 45 s demo/hook:** previews appear on three real screens; the race resolves to one accepted version, with rejected branches inspectable. Tweet: “I cached a program's next possible future near three users. All can preview locally; only one reply owns the real next step. The latency chart includes the cross-region commit.”

**E — Kill test:** if expected audience reuse/prediction produces under **50% cache usefulness** and fewer than **100 ms p95** saved after ownership validation, stop prepositioning live state. Cache the engine and ordinary data instead.

## 4. The common contract: what actually moves

**I — Minimal capsule:** `{format, engineHash, abiHash, computerId, branchId, checkpointHash, parentHash, rawLength, memoryAndGlobals, pendingCallDigests, journalCursor, requestedCapabilities}`. An optional blob manifest lists immutable external data needed for a self-contained export. Store credentials, authorization grants and the authoritative effect ledger outside portable memory. Hashes identify content; they do not attest that a browser executed it honestly.

**I — Capture boundary:** pause at a guest tool promise, return all Wasm frames to the host, drain runnable guest jobs within a work budget, and persist the VM state together with the host-side pending-call/cursor metadata. A native V8 heap, a live TCP connection, DOM, Browser Run process, model weights or container process is not included. Use the exact compatible interpreter/ABI at restore; a future engine version needs replay or explicit conversion. This scope is supported by the existing [quiescent-boundary evidence](../portability/02-wasm.md#31-preferred-path-quickjs-heap-continuation-empty-wasm-stack).

**I — Authority handoff, deliberately more explicit than “upload then resume”:**

1. **Prepare:** owner epoch `e` stops accepting new effects, drains or marks uncertain pending calls, and uploads immutable checkpoint `h` to R2.
2. **Commit:** the authority DO records `head=h`, journal position and epoch `e+1` transactionally in its own storage. R2 upload and DO transaction are separate: unused uploaded objects are harmless and later collected. A current-head record never points to an incomplete upload.
3. **Activate:** destination verifies hash/build/size and obtains an epoch-scoped run grant. Old owners may continue computing, but the broker rejects their stale-epoch effects. On reconnect a browser must revalidate; a self-reported epoch is not authority.
4. **Dispatch:** broker writes a logical operation record before making an external effect, uses the provider's idempotency key when available, and records the response. If effect completion is uncertain and no idempotency/reconciliation API exists, block and reconcile; never blindly retry and claim exactly-once behavior.
5. **Fork/join:** branches get separate identities and read-only or simulated tools by default. Resume the parent's pending call with a typed result, or promote one child through an authority transition. Arbitrary child heap merging is outside the contract. If promoting a child, the final file is that child's continuation, not all histories magically compressed into one heap.

**I — Two explicit compromises:** keeping the authority DO stationary preserves simple fencing but charges each effect a potential geographic hop. Moving the authority to a new actor needs a durable, discoverable forwarding/transfer protocol and failure handling; it is not achieved by changing `locationHint`. Start stationary. Also, a file alone can run offline with disabled external effects, but cannot independently recreate cloud-held grants or commit globally authorized writes. Exportability concerns execution state; it does not turn bytes into unlimited authority.

## 5. The smallest demo a Cloudflare engineer might retweet

**I — Build “One → Eight → One,” an adapter-sized demonstration combining F with A, not a general operating system.** The surprising evidence is the same live continuation moving, temporarily changing topology, and returning as a usable file. The map is secondary. No endorsement or retweet is predictable.

**E — One-to-two-week scope:** a fixed QuickJS/Wasm build, TypeScript host adapters, one R2 bucket, one per-run authority DO, two small coordinator DOs, and eight stable Dynamic Worker adapter slots. Each adapter creates a fresh Wasm instance; code/ID stay stable while the checkpoint is request data. Deny ambient outbound access and broker the allowlisted tools. A single browser page supplies the UI and local Web Worker executor. Optional Workers AI calls use a model whose actual account limit admits eight requests; deterministic investigation tools keep runtime verification independent of model output.

**E — Useful workload:** investigate a seeded synthetic outage from eight distinct hypotheses. The parent has already parsed a small evidence index, built a Map/cyclic structure and created a closure over an investigation-specific secret nonce before awaiting `swarm()`. The nonce is demo data, not a credential. All children restore that checkpoint and see the same prepared state, then receive different branch replies. Read-only tools inspect explicit fixture data. Findings are checked against known fixture evidence. A real model may propose hypotheses; label prerecorded/replayed model output if used.

**E — 75-second recording script, with visible source and receipts:**

1. **0–12 s:** run the investigator locally in the browser; pause at `await swarm()`. Show raw/compressed bytes, engine hash, checkpoint hash and journal cursor.
2. **12–20 s:** upload, await durable head acknowledgment, terminate the Web Worker, reload the page. The closure-bearing execution owner is gone; the checkpoint is the recovery source.
3. **20–50 s:** explicitly request an eight-branch, thirty-second wall-time budget. Restore on hosted Cloudflare and launch two groups of four. Show the actual execution locations, eight distinct branch IDs, read-only capabilities and each branch's metered CPU/tool/model use. Several branches may share a colo; do not draw eight fake cities. Deliberately exhaust one branch's configured CPU quota, then recover it or mark it failed; no undocumented remote-kill API is assumed.
4. **50–63 s:** join checked findings into the parked parent, verify the nonce/Map/cycle and next source position, then park again. Show one new authoritative checkpoint and the retired branch grants. “One file” is the resulting parent state; retained audit logs and external immutable blobs are separately itemized.
5. **63–75 s:** download that checkpoint to a real phone browser with the compatible engine cached. Disable network and resume a final pure computation from it. Show offline completion and the effect ledger's unchanged external-write count. If phone support fails, publish the failed matrix and use the tested laptop browser; remove the phone claim.

**E — Build order:** days 1–2 fix/qualify bounded memory, stack and work interruption on preset guests; import the fixed engine and restore once on actual paid Workers. Days 3–4 implement immutable persistence and stationary-authority fencing. Days 5–7 implement four-way fan-out, two coordinators, join and deadlines. Days 8–10 add phone restore, receipts and interrupted-run tests. If the runtime envelope or hosted restore fails in week one, stop expanding the demo. This is a controlled proof, not security qualification for public arbitrary-code upload.

**E — Acceptance evidence:** 1,000 preset suspend/resume cycles, 100 fork/join runs with a killed branch, and duplicate wake/reply delivery with no duplicate authorized operation. Inject crashes before upload, after upload/before head commit, after head commit/before activation, and after a broker effect/before acknowledgment. Verify stale epochs fail; distinguish provider-idempotent effects from unresolved effects. Include one refusal to replay an uncertain non-idempotent effect.

**E — Measurement contract:** at least 100 warm and 100 deliberately cold-cache samples per available real test geography; a cold-cache sample is not automatically a cold-isolate sample. Record cache status, checkpoint bytes, restore class, execution/authority sites, client RTT, CPU, first guest-frame latency and complete task latency. Label any simulated delay, geography or tool. Publish p50/p95 and errors, without implying an account-wide SLO. Resource evidence comes from platform traces, not Worker clocks around synchronous Wasm.

**E — Budget discipline:** first bound the demo at 100 eight-branch runs and a hard application spend quota. That gives 800 branch restores; eight distinct stable adapter identities, rather than 800 one-shot identities, avoid unnecessary daily creation units. A 3 MB starting image implies at most **2.4 GB of branch image reads** across those runs before retries; compression/caches change actual transfer. Count coordinator activity, R2 operations, model tokens, Browser Run or native tools separately. There is no valid “the agent cost $0.000001” headline that omits its inference.

**I — Expert-reply defense:** identify Vercel `quickjs-wasi`, LangChain `quickjs-rs`, XS snapshots, Golem and Cloudflare's Computer/Agents/Workflows as prior art through the existing [landscape report](../v8/02-landscape.md). State that the captured runtime is QuickJS inside Wasm. The demonstration's contribution is the explicit cross-host, fan-out, join and authority contract. Publish enough code and a non-sensitive checkpoint that an unfamiliar engineer can restore it without a model API key.

## 6. Ranked shortlist and the bet

**I — Full ranking:** **1 F: temporary swarm**, **2 B: follow the data**, **3 A: follow the user**, **4 D: distributed live cells**, **5 E: URL computers**, **6 C: billion sleepers**, **7 H: continuation CDN**, **8 G: general device mesh**. This ordering favors an inspectable near-term result, growing model value, and a buyer problem over raw population counts.

**I — #1: Temporary swarm.** This is the clearest visible step beyond “a snapshot exists.” It makes topology an attribute of a program: one, many, one again. The initial implementation is small enough to explain and Cloudflare's primitives fit it well. Its business case must pass the single-strong-agent baseline; its systems case survives even if swarming loses, because the same machinery supplies controlled speculative execution, branch inspection and recoverable continuations. Keep inference and heap merging out of the magic trick.

**I — #2: Follow the data.** This has the strongest infrastructure buyer argument: avoid repeated WAN chatter and unnecessary data export. It becomes more useful as agents perform longer multi-domain tasks. It also has an unusually good falsification baseline in Smart Placement plus Hyperdrive. A win after that comparison would justify a location-aware continuation scheduler; a loss would save months of building one. The hard product boundary is capability/data policy at each destination, not selecting the nearest airport code.

**I — #3: Follow the user.** This offers the most accessible future: a person owns ongoing computation independently of the current device. Browser execution makes it more than a cloud failover demo, and a downloaded checkpoint gives the viewer something tangible. Start with foreground handoff and a stationary authority. The full planetary promise depends on mobile compatibility, durable acknowledgments and usable recovery when a device disappears. The narrow proof remains compelling without pretending mobile tabs are servers.

**I — The ONE I would bet on: F, “One → Eight → One,” shipped as a small portable-continuation adapter and demonstrated with A's phone/browser return.** It exposes the core contract in seventy-five seconds, uses Cloudflare's actual platform rather than imaginary VM migration APIs, and has a credible path into Agents/Computer instead of competing with their whole stack. B is the next experiment if an adopter has a real multi-domain workload. Billion-scale storage and every-URL OS language should be the extrapolation after the proof, not the first milestone.

## Five-line TL;DR

1. **F/I:** Cloudflare already supplies the planetary substrate and a Computer preview; the gap is portable continuation, topology changes and correct authority transfer.
2. **M-prior/E:** Real checkpoints span about 0.1–6.4 MB; a billion full R2 images cost roughly $1,500–96,000/month before activity, replicas and history.
3. **F/I:** DOs do not currently move; hints are advisory, one object is single-threaded, and Dynamic Worker identities/fan-out impose real economic and scheduling limits.
4. **E:** Test <250 ms prepared small-image wake and <2 s large-image cold-fetch cohorts; no honest universal “under X ms anywhere” follows from a warm memory copy.
5. **I:** Build one browser continuation → eight real read-only branches for thirty seconds → one downloadable continuation, with measured hosts, costs and rejected stale owners.
