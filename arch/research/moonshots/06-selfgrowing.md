# Software that grows its own substrate

Research date: **2026-10-27**. Lens: **self-growing software and agents as the substrate**. Eight proposals, ranked after evaluation.

**Claim labels:** **F** = sourced fact; **M** = previously measured in this repository, attributed and not rerun here; **I** = inference, proposal, or judgment; **E** = estimate or proposed experimental threshold. All external sources were consulted on **2026-10-27**; publication dates appear with the citations. There are **no new runtime measurements** in this report. Every video and tweet below is a proposed demonstration, conditional on the experiment working; targets must be replaced by actual results before publication.

## Thesis: missing behavior becomes a recoverable fault

**I — The 100x opportunity is to make implementation availability a runtime concern.** Today a program faults because a function, module, syscall, or workflow does not exist. Instead, the computer could park the program, acquire examples from an authoritative reference, grow the missing behavior, qualify it outside the proposer, and retry. After acceptance, ordinary code handles subsequent calls without inference. A capsule becomes the combination of a running program, the substrate grown for it, and the evidence that justifies that substrate.

**I — The ambitious end state is an operating environment whose application-specific implementation is initially empty.** Programs arrive first; runtimes, library operating systems, adapters, and applications grow behind them. A model release increases the set of behaviors that can be manufactured economically. The enduring asset is the independent behavioral contract, execution history, and accepted component library. A wrapper that merely asks a model to write a polyfill would be absorbed by better coding agents.

**I — “An operating system with zero lines written in advance” is a research direction, not an honest literal description.** An interpreter, isolation boundary, resource controller, effect broker, loader, and acceptance machinery must already exist. Count those lines. The testable claim is **zero prewritten implementations for the chosen application/OS API profile**, grown on top of a disclosed seed. Training-data knowledge and reused upstream components are prior work too.

## What GrowOS establishes, and the warning inside its result

**M — The phase-2 grown kernel runs 3,198/3,947 comparable compiled corpus programs byte-identical to Linux, versus 159 before: 81.0% versus 4.0%.** Held-out results are 644/792, or 81.3%. Eight accepted handlers contain 218 grown lines. The 74-line mmap handler alone accounts for 2,924 of 3,039 newly passing programs. It depended on 55 manually supplied safe kernel-helper lines; a separate human loader-placement change unlocked 50 programs. These are functional results on macOS/HVF, with N=1 transaction per target, not broad Linux conformance or a growth-success scaling curve. [Phase-2 experiment, 2026-10-27](../../jitk/grow/EXPERIMENTS-PHASE2-2026-10-27.md).

**M — The denominator and build conditions matter.** Of 4,127 compiled programs, 180 path-embedding rebuilds were excluded from like-for-like comparison; the lower bound is 77.5% over all compiled programs. The 81.0% result uses the documented image-base relink; unmodified stock-layout ELFs reach 73.2%. The grown tree is experimental, assembled separately, and all growth transactions used `--validate-only`. [Corpus results, 2026-10-27](../../jitk/scriptc-corpus/RESULTS-PHASE2.md).

**M — Four other handlers passed the gates but were excluded after inspection for environmental overfitting.** They mirrored paths and filesystem properties of the oracle container rather than implementing the guest archive. Held-out inputs shared that environment. Other profiles pinned process/environment values; sysinfo could report the oracle's 8 GB in a 32 MiB guest. Some targets required new trusted primitives; pipe2 and mprotect exceeded the one-file contract. [Failure classes and limitations, 2026-10-27](../../jitk/grow/EXPERIMENTS-PHASE2-2026-10-27.md).

**I — Generalization:** growing behavior can have enormous leverage when a small semantic gap blocks many programs. **The unit of trust must nevertheless be a versioned contract and environment profile, not “passed held-out.”** Matching an oracle machine can be the wrong target. A model cannot synthesize a capability the seed does not expose, and accepting more model-written code is not itself success.

**F — The existing controller already separates proposal from acceptance, keeps hidden artifacts outside the proposal repository, records attempts, checks unchanged programs, and grades known mutants.** Its mutant gate grades the tests; because mutants derive from canonical handlers, it is not an additional candidate-specific rejection gate. Repeated visible runs are not independent semantic coverage. Preserve these distinctions in the TypeScript version. [Grow controller contract, current repository source](../../jitk/grow/README.md).

## The old ideas to keep, and the promises to discard

**F — Tracing JITs supply the control pattern.** TraceMonkey recorded hot paths, specialized code to observed types, and used guards/exits when assumptions stopped holding. [Gal et al., PLDI, June 2009](https://www.cs.williams.edu/~freund/cs434-exemplar/gal-trace.pdf). **I — Transfer the guard and fallback discipline, not a claim of equivalent correctness:** a conventional JIT transforms an existing implementation; a grower invents an implementation under incomplete evidence. Branch-heavy code and fragile complexity were real limits in tracing; a Mozilla implementer described both in [March 2011](https://blog.mozilla.org/nnethercote/2011/03/24/the-javascript-interpreter-isnt-dead-yet/). Long-tail API interactions will be our equivalent.

**F — Demand paging and laziness supply the economic pattern.** Denning's working-set model relates resource demand to the portion a computation actually uses. [May 1968 paper](https://denninginstitute.com/pjd/PUBS/WSModel_1968.pdf). Launchbury makes delayed evaluation and sharing explicit in a heap semantics. [POPL, January 1993](https://launchbury.blog/wp-content/uploads/2019/01/semantics-of-lazy-evaluation.pdf). **I — A semantic fault materializes an implementation instead of a page or value.** Those earlier systems did not fail; they assumed the missing material was already determined. Here the difficulty is discovering it. Cache accepted behavior, avoid repeated expensive faults, and expose the slow first use.

**F — Synthesis already learned from examples and oracles.** FlashFill's precursor synthesized programs in a restricted string language; Sketch combined partial programs with counterexample-guided checking. [Gulwani, POPL, January 2011](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/popl11-synthesis.pdf), [Solar-Lezama, Program Sketching, published online August 2012](https://dspace.mit.edu/entities/publication/ba8c3c2f-ab29-4334-bcb1-abcb8da0f6a9). **I — Their success argues for explicit component boundaries and informative examples.** Their scope does not establish that arbitrary stateful operating environments can be inferred. Stronger models widen the proposal space; they do not eliminate underspecification.

**F — The closest new precedent is already surprisingly close.** `pi-world` describes an agent-grown QuickJS/Wasm application heap with checked immutable revisions and rollback. Its README distinguishes working functionality from designed pauses/forks/replay. [Current author repository](https://github.com/igouss/pi-world). **I — An agent changing a persistent heap is therefore insufficient differentiation.** The stronger proposal is independent oracle qualification, demand-triggered substrate growth, and cross-program/environment evidence.

**F — Node portability is also occupied.** Workers supplies built-in Node APIs plus some importable stubs; `unenv` supplies compatibility polyfills; WebContainers provides browser Node development environments. [Cloudflare, updated August 12, 2026](https://developers.cloudflare.com/workers/runtime-apis/nodejs/), [unenv, current source](https://github.com/unjs/unenv), [WebContainers, current product documentation](https://webcontainers.io/). **I — Compare with these solutions and reuse them when they win.** Our claim concerns how missing semantics are acquired and qualified, not inventing Node in a browser or implementing familiar APIs.

## A common implementation contract

**I — All eight proposals share this mechanism; none requires replacing V8 or inventing another workflow platform.**

1. **Detect a miss at an explicit surface.** A guest module resolver, API registry, or interpreter host-call boundary emits a structured demand. A missing global cannot safely be inferred from any arbitrary JavaScript exception. Keep ordinary application bugs distinct from unsupported behavior.
2. **Park or retry correctly.** An asynchronous guest demand may leave a serializable promise. A synchronous missing call or module-link failure normally requires discarding the attempted instance and replaying from a prior boundary with recorded inputs. It cannot magically await a model while preserving an arbitrary native stack. No unjournaled write may escape the failed attempt.
3. **Choose an oracle and its environment before sampling.** Pin Node/browser/Linux versions, fixtures, locale, scheduling profile, memory limits, and observable outputs. For a stateful API, compare operation sequences, mutations, aliasing, errors, and effect traces. Where specifications permit multiple outcomes, check the permitted relation rather than an invented exact byte string.
4. **Grow in a disposable branch.** The model receives public probes and permitted helper APIs. It cannot edit the supervisor, effect authority, grader, or sealed audit. It may request a new primitive; that is a separately counted seed change, not autonomous growth.
5. **Qualify and publish immutable artifacts.** Visible counterexamples guide iteration. Frozen validation and a fresh final audit stay separate; repeated hidden pass/fail queries themselves leak information. Use independently prepared stateful/environment probes and targeted mutants. Cache by code, oracle/profile, seed ABI, and evidence hashes. Incomplete qualification is a rejection or an explicitly scoped experimental result.
6. **Resume under a pinned revision.** Persist the runtime/component hashes with the capsule, journal cursor, and logical effect identities. Rollback code and guest state together. Effects already delivered to the world require broker reconciliation; copying or reverting RAM does not undo them.

**F — Cloudflare can host this shape.** Dynamic Workers load generated JavaScript and compiled Wasm modules with chosen bindings and outbound access control; TypeScript needs transpilation first. Ordinary Workers prohibit host `eval`, `new Function`, and byte-buffer Wasm compilation. A fixed QuickJS/Wasm interpreter can evaluate guest JS as data, or the loader can install a newly qualified child Worker. [Dynamic Workers, updated October 12, 2026](https://developers.cloudflare.com/dynamic-workers/getting-started/), [Workers standards, current documentation](https://developers.cloudflare.com/workers/runtime-apis/web-standards/).

**I — Deployment:** a TypeScript coordinator records jobs/revision ownership in a Durable Object; R2 stores immutable code, capsules, and receipts; Queues/Workflows run bounded growth jobs. Run Node/Linux reference oracles in a local process or controlled Container, not inside the candidate. Begin with a fixed Wasm interpreter and generated guest JS modules. Native Dynamic Worker execution is an alternative qualification target, not automatically the same heap representation.

**M — Carry forward the actual capsule constraints.** Quiescent QuickJS/Wasm transfer was demonstrated locally across Node, Chromium, workerd, and Dynamic Workers; that is not hosted edge qualification. Later examples reached 1.5–6.4 MB compressed; freeing objects did not shrink linear memory. The spike's QuickJS allocation accounting was defective, and measured glue ran 5–11x slower than direct V8. [Portability spike, October 25](../portability/02-wasm.md), [roadblocks, October 27](../v8/03-roadblocks.md). **I — Minimal runtime code does not imply a minimal heap, complete replay, or a safe public tenancy service.**

## 1. Fault-grown Node: a runtime that learns the API a program just requested

**Idea — I:** Run a Node-shaped program in a constrained JS capsule; each missing API becomes a growth job qualified against a pinned real Node oracle. **100x — I:** submit an npm program to Workers and its necessary Node environment grows until it runs, with explicit refusals for unsupported native/process semantics. “A Node.js that grows itself inside Workers” is the destination; a qualified Node API subset is the first deliverable.

**Lineage — F:** combine the trace-JIT guard discipline above with oracle-guided synthesis. Jha et al. queried inputs that distinguish candidate programs, using SMT over a component library. [ICSE, May 2010](https://people.eecs.berkeley.edu/~sseshia/pubs/b2hd-jha-icse10.html). **I — Then/now:** loop-free components and solver search bounded that work. Models can propose state machines, module glue, and tests across larger code surfaces; the authoritative reference remains outside the model. Unlike a compiler, this system has no complete source semantics to preserve automatically.

**Model-release leverage — I:** newer models may handle larger compatibility gaps and compose helpers with fewer retries. Every accepted reusable API lowers future growth work. The product expands from a small portable profile toward more packages as synthesis improves; it does not compete on the model's ability to type a polyfill. If native Workers or an existing shim already runs a package, use that route.

**Value — I:** agent execution platforms, edge migration teams, SDK vendors, and browser plugin hosts pay for programs running under a declared portable/effect-controlled profile, fewer compatibility tickets, and reproducible failures. Their purchase is tested compatibility and operational support, not generated source volume.

**First proof — E, 10 working days:** freeze ten small dependency-bearing programs and ten unseen programs from different packages. Select a bounded surface after a read-only dependency census: `path.posix`, `StringDecoder`, `EventEmitter`, and read-only files are candidate families, not a promise to fit all four. Disclose seed Buffer/byte transport and immutable-file helpers. Leave target methods absent, bundle without changing application source, and trigger growth from actual misses. Node provides results for public and fresh sealed operation sequences. A StringDecoder target must survive arbitrary chunk boundaries, invalid encodings, and restore while retaining an incomplete character; these are real API semantics. [Node StringDecoder documentation, current v26 documentation](https://nodejs.org/api/string_decoder.html). Run accepted components in Node-hosted Wasm and local workerd; qualify one hosted Dynamic Worker if deployment prerequisites exist. Report every miss, refusal, helper addition, attempt, token receipt, cold delay, and unseen-program pass. Compare with native Workers compatibility and conventional polyfill bundling.

**Demo + hook — I, 75 seconds:** a program fails on an absent decoder. Show the empty implementation, a live growth timer, an attractive wrong candidate rejected on a sealed stateful test, then the original program producing the same output as Node. A second package reuses the accepted component without a model call. Separate wall time from time-lapse. **Draft tweet:** “This program asked for a Node API our capsule didn't have. The runtime grew an implementation, checked it against Node on unseen call sequences, then retried the unchanged program. The next program reused it. A small compatibility subset, running in a Worker.”

**Kill test — E:** after two weeks and a fixed proposal budget, the grower unlocks **no unseen program beyond the conventional polyfill baseline**. Then this is a complicated way to assemble existing shims; stop selling it as a runtime product.

**Judgment — I:** strongest opening. It makes implementation growth visible and has an existing oracle. The full Node promise remains far away: native addons, process control, threads, sockets, scheduler behavior, and filesystem durability are separate architectural obligations.

## 2. Every capsule carries the runtime grown for exactly it

**Idea — I:** package a program with only the API implementations needed under its declared behavioral envelope, grown and qualified together. **100x — I:** replace a generic container/runtime image with a bespoke executable environment for every program, portable between browser and edge; its manifest says what happens when behavior leaves the qualified envelope.

**Lineage — F:** exokernels separated protection from application-specific OS policy in untrusted library operating systems. [Engler, Kaashoek, O'Toole, SOSP, December 1995](https://pdos.csail.mit.edu/6.828/2008/readings/engler95exokernel.pdf). Demand paging supplies locality; lazy evaluation supplies sharing. **I — Then/now:** application-specific libraries still needed someone to implement and maintain them. Agents can manufacture candidates; a content-addressed registry shares accepted fragments. This differs from tree shaking only if it synthesizes a smaller implementation of behavior, rather than merely deleting unreachable exports.

**Model-release leverage — I:** stronger models can discover larger equivalent simplifications and reason about cross-module invariants. Each model upgrade can rebuild old capsules against unchanged evidence. Existing capsules keep working on pinned artifacts. The compounding asset is a library of qualified semantic components with provenance; thousands of unsupported one-off forks would destroy that advantage.

**Value — I:** browser/offline applications, embedded tool hosts, agent platforms with millions of stored continuations, and software distributors pay for dependency reduction, portability, and reproducible runtime ownership. Security value requires a measured reduction in reachable capabilities and an intact outer boundary; fewer lines alone do not establish it.

**First proof — E, 1–2 weeks:** take six programs using distinct subsets of the same library surface. Compare three equally functional artifacts: ordinary bundling/tree shaking, a shared full polyfill layer, and grown per-program modules. Use unseen input families to test the declared profile, not just a recorded execution. Measure total engine + modules + state bytes, cold load/first execution, retained heap, and restore. Add a new input that needs an omitted operation and show a declared growth fault rather than a wrong result. **Minimal** means locally reduced under tested constraints; do not claim a global minimum or that a finite trace proves all future paths.

**Demo + hook — I, 60 seconds:** six files each carry a different runtime inventory. Restore one in a browser and one in a Worker, inspect their dependency manifests, then introduce a new operation and watch one environment grow. **Draft tweet:** “These capsules run the same library interface, but carry different implementations grown for their programs. We compared total bytes with tree shaking and a shared polyfill. A new behavior faults and grows the environment; it doesn't silently guess.”

**Kill test — E:** after including the shared engine, capsule state, and component/evidence storage, the grown form achieves **less than a 2x reduction in total transferred bytes** versus ordinary bundling on the frozen corpus, without a separate operational benefit. Demote it to a packaging feature rather than a company thesis.

**Judgment — I:** good second product surface, conditional on measuring the right denominator. Existing 1.5–6.4 MB state can swamp savings in a few kilobytes of runtime code. A shared runtime may beat bespoke copies; deduplicate honestly.

## 3. The blank operating system: applications grow the services beneath them

**Idea — I:** start with an empty implementation registry above a fixed capability monitor, then let programs grow a virtual filesystem, descriptor objects, pipes, timers, and process-like actors as needed. **100x — I:** an entire application operating system emerges from attempted use, with no prewritten implementations for its advertised OS profile; Linux or a specified model supplies the oracle.

**Lineage — F:** Kay described protected, message-passing computational cells and the biological inspiration of Smalltalk. [The Early History of Smalltalk, HOPL, April 1993](https://worrydream.com/EarlyHistoryOfSmalltalk/). Exokernels moved OS policy above a protection boundary. **I — Then/now:** these systems supplied flexibility, not a free source of new correct semantics. The grower could provide that source. “Software should be grown” is the lens's paraphrase here, not a verified verbatim Kay quotation. The essential shift is growing shared stateful abstractions, beyond GrowOS's one-file handlers.

**Model-release leverage — I:** gains in long-horizon programming could move the growth unit from one function to cooperating object types and protocols. Better models can propose a pipe buffer + descriptor table + readiness semantics together. Qualification difficulty rises too; no current result establishes that model ability outruns it.

**Value — I:** portable developer tools, browser IDEs, offline educational machines, and tightly scoped sandbox providers could depend on an inspectable OS personality that runs selected software without a full Linux image. Full workspace compatibility is an eventual aspiration, not the first customer contract.

**First proof — E, 10 days:** a fixed QuickJS/Wasm machine exposes bounded memory, clock input, and a tool channel; count the engine and monitor separately. Supply an in-memory object store primitive but no directory/descriptor/pipe policy. Three unchanged TS programs request file reads, directory creation, and producer/consumer byte transport. Grow a multi-module OS personality; compare command sequences and final tree/descriptor observations with a reference Node process using a temporary filesystem, or Linux where syscall semantics are advertised. Restrict scheduling to an explicit cooperative actor model; do not label it Linux process equivalence. Hidden tests change path names, directory structure, operation order, capacity and error cases. Persist at a pipe wait and restore to finish. No VM modification or KVM access is needed.

**Demo + hook — I, 90 seconds:** boot an empty OS panel. Launch three programs; filesystem, descriptors, pipe, and readiness nodes appear only after the corresponding misses. Publish prewritten versus grown line counts and every seed change. **Draft tweet:** “This virtual OS booted with zero implementations for its advertised file/pipe API. Programs asked for services; an agent grew them against a reference. The interpreter and capability monitor were prewritten and counted. The hard part was making separate grown services agree.”

**Kill test — E:** the first cross-service integration requires **per-program handwritten exceptions in the monitor** to pass the unseen sequence suite. That falsifies the claim that a stable seed can support meaningful OS growth at this scope.

**Judgment — I:** highest systems spectacle; lower near-term confidence. GrowOS's mmap helpers show that good seed primitives matter. A successful tiny library OS is a stepping stone, not “Linux grown from nothing.”

## 4. Software that rewrites itself toward a held-out oracle forever

**Idea — I:** operate a service as an immutable behavioral contract plus a continuously searched population of implementations; accepted revisions improve cost, latency, size, or compatibility while preserving the contract. **100x — I:** an old application becomes a standing optimization problem. Every new model release can rewrite its internals, runtime, and storage plan; customers keep its externally visible behavior and history.

**Lineage — F:** STOKE searched for faster loop-free binary fragments under correctness/performance constraints. [Schkufza, Sharma, Aiken, ASPLOS, March 2013](https://theory.stanford.edu/~aiken/publications/papers/asplos13.pdf). Autonomic computing organized self-management around monitoring, analysis, planning, execution, and shared knowledge—the MAPE-K lineage. [Kephart and Chess, January 2003](https://www.cs.tufts.edu/comp/250SA/papers/kephart2003.pdf). **I — Then/now:** constrained search limited the former; useful models of behavior and adaptation limited the latter. An agent can propose structural changes rather than only tune knobs, while capsules make failed candidates disposable.

**Model-release leverage — I:** more capable models enlarge the optimization search space without asking users to rewrite their application. A newer model can also suggest a better test generator, but does not get to weaken the incumbent acceptance contract. The model improves the factory; accepted deterministic code runs the service. There is no guarantee of endless improvement—“forever” means a persistent search facility with stopping rules, not perpetual measured progress.

**Value — I:** maintained legacy services, SDK/runtime teams, and high-volume data-processing products pay for lower operating cost and compatibility-preserving modernization. The service must produce enough savings to amortize synthesis, oracle execution, audits, and migration. This is stronger than a CI bot proposing optional refactors only if rollout and behavioral continuity are actually handled.

**First proof — E, two weeks:** use a deterministic TS document-transform or routing service with a pinned original as oracle. Record a public workload and two independently withheld input families. Give the grower a fixed search budget to replace modules and data representations; keep competing revisions rather than accepting only a linear hill climb. Require exact output/error/effect-trace agreement on the profile. Optimize one declared metric and impose caps on the others. Measure on fresh randomized order with setup excluded consistently; confirm the winner on an untouched workload. Then replay a parked capsule into the new revision, validating request digests. Old raw heap images remain tied to old builds; a migration needs replay or an explicit checked state converter. Demonstrate rollback after a fresh audit exposes a regression.

**Demo + hook — I, 75 seconds:** show a service family tree, a faster candidate failing a rare malformed-input case, a qualified revision winning on the sealed workload, and an old continuation completing under an explicitly verified migration. **Draft tweet:** “We kept this service's reference behavior fixed and let an agent rewrite its implementation. Some faster versions were wrong and rejected. The winner passed a fresh audit and reduced the measured cost. A new model gets the same contract and another chance.”

**Kill test — E:** the winner produces **no net operating savings after amortizing growth and qualification over the customer's actual execution volume**. A beautiful optimizer with negative economics is a research demo, not this product.

**Judgment — I:** best long-term model-release thesis. Start with pure transformations, where the oracle is cheap and the output relation is crisp. Whole distributed services introduce consistency, storage migration and external effects long before “rewrite forever” becomes a reliable promise.

## 5. Grow the oracle: a behavioral map of the software ecosystem

**Idea — I:** agents discover behavioral distinctions, propose discriminating probes, and turn reference executions into versioned compatibility contracts that drive implementation growth. **100x — I:** a living map of Node, browsers, runtimes, SDKs, and OS personalities becomes an executable compatibility layer; every upstream release automatically reveals what needs to grow or migrate.

**Lineage — F:** Daikon inferred **likely** invariants from traces, with coverage-dependent accuracy. [Ernst et al., February 2001](https://plse.cs.washington.edu/daikon/pubs/invariants-tse2001-abstract.html). McKeeman used generated inputs to find disagreements among comparable implementations. [Differential Testing for Software, 1998](https://www.cs.tufts.edu/comp/150FP/archive/bill-mckeeman/DifferentailTesting.pdf). Csmith avoided undefined/unspecified behavior to make differential compiler comparisons meaningful. [Yang et al., PLDI, June 2011](https://www.flux.utah.edu/paper/yang-pldi11). **I — Then/now:** hand-designed hypothesis spaces/generators constrained reach. Models can propose new state machines and probe families; independent execution, environment control, and adjudication remain the scarce infrastructure.

**Model-release leverage — I:** stronger models can identify more informative tests and minimize counterexamples across larger stacks. Failed implementations contribute reusable distinctions. New evidence can invalidate an old accepted component and trigger repair. Do not let the agent's generated expected answer become the oracle.

**Value — I:** runtime maintainers, package authors, cloud migration teams, and enterprise platform groups pay for actionable compatibility deltas and qualified replacements. A public substrate can be open; private production-shaped audits, managed qualification, and integration support are plausible paid products. Demand is a hypothesis, not measured willingness to pay.

**First proof — E, 1–2 weeks:** choose three bounded API families, one with state. Generate public probe suggestions from docs/traces; trusted adapters execute them against pinned references. Hold back environment variants and an independently prepared mutant bank. Show that the proposed probes detect bugs missed by a fixed baseline, then grow a replacement from the public observations. Split **input** and **environment**: rename and restructure files, vary locale/resource limits where relevant, and replay longer sequences. Test a known-correct implementation too; a generator that rejects the correct control is not stronger. Use Node for Node-specific APIs, browser/spec/WPT relations for Web APIs, and Linux only for Linux contracts.

**F — Multiple implementations are not automatic truth.** Independently written versions exhibited dependent failures in Knight and Leveson's experiment. [January 1986 paper](https://citeseerx.ist.psu.edu/document?doi=0f5029d3e21e188d0ed7b24764f72ec1a2f4910b&repid=rep1&type=pdf). Test262 explicitly acknowledges omissions/errors, and WPT supports cross-browser interoperability. [Test262, current project](https://github.com/tc39/test262), [WPT, current documentation](https://web-platform-tests.org/). **I:** a browser majority can flag a discrepancy; a spec contract or a chosen compatibility target must settle it. Three models agreeing on a test result is weaker still.

**Demo + hook — I, 60 seconds:** an accepted path handler passes familiar tests, then a generated hidden directory reshuffle breaks it. The system produces a minimal distinguishing sequence and repairs the handler without seeing the final audit. **Draft tweet:** “Held-out inputs weren't enough: the oracle and implementation shared the same misleading environment. We now vary the environment too. This system grows tests before it grows code—and records disagreements instead of voting them into truth.”

**Kill test — E:** on the blinded mutant/control bank, generated evidence offers **no improvement in bug detection at the same correct-control acceptance rate and oracle budget** over a fixed generator. Then keep a conventional differential harness; an agent oracle-factory has not earned its complexity.

**Judgment — I:** mandatory capability for the other bets, but a less dramatic standalone launch. It becomes a moonshot through ecosystem-wide scope and automatic repairs, not by renaming test generation.

## 6. API resurrection: grow a replacement from a surviving behavioral fossil

**Idea — I:** grow an API or application backend from a reference executable, recorded sessions, or an executable specification, retaining the quirks its clients depend on. **100x — I:** a deployed system can shed its original stack and vendor while preserving a user's workflows; the replacement grows only when a previously unseen client behavior demands it.

**Lineage — F:** specification mining extracts behavioral hypotheses; oracle-guided synthesis uses distinguishing queries; FlashFill's restricted examples-to-program workflow showed that a narrow domain could become a practical end-user feature. Gulwani describes the route to deployment in his [September 14, 2021 first-person account](https://blog.sigplan.org/2021/09/14/the-story-of-the-flash-fill-feature-in-excel/). **I — Then/now:** the missing piece for larger applications is not simply code generation but discovering enough stateful behavior. Models can propose adapters and schema mappings; capsules let old and new implementations replay the same history.

**Model-release leverage — I:** more capable models can translate tangled protocols, preserve error semantics, and infer larger state machines with fewer reference queries. A reusable fossil—a lawful recording with precise state/effect boundaries—survives model churn and can be recompiled repeatedly. If the old oracle disappears, the contract necessarily stops at the evidence collected; no model restores unknowable behavior with certainty.

**Value — I:** teams retiring an internal legacy service, maintaining a discontinued plugin, or moving a domain-specific app onto Workers pay for continuity and reduced infrastructure dependence. Begin with customer-owned systems and data, not a claim to clone arbitrary commercial SaaS from screenshots.

**First proof — E, 10 days:** record an owned TS service supporting create/read/update/list plus pagination and conditional updates. Split whole sessions and initial database states; a random split of adjacent requests would leak state. Give the grower public sessions and budgeted read-only/resettable oracle queries. Generate a Durable Object-backed replacement. Run held-out sessions from matched initial state, comparing status, bodies, ordering, version tokens, and final records. Repeat using **trace-only** evidence and disclose the loss of generalization. Demonstrate an unsupported behavior failing explicitly rather than being served by a lookup table.

**Demo + hook — I, 75 seconds:** two clients connect to old and grown backends and produce matched histories. Disconnect the original only after qualification, then reveal a behavior absent from the recordings and show the replacement's uncertainty/refusal. **Draft tweet:** “We retired our test service's implementation, keeping its recorded behavior and a reference during migration. An agent grew the Worker replacement. Whole unseen sessions matched; behavior we never observed remains explicitly unsupported.”

**Kill test — E:** the trace-only system fails **more than 10% of the preregistered unseen sessions** after the fixed growth budget. That kills the trace-only resurrection claim for this class; retain the reference-query migration version if it independently works.

**Judgment — I:** useful commercial wedge, lower novelty, and high risk of becoming ordinary migration consulting. The 100x form requires automatically handling new semantic demands, not one successful generated rewrite.

## 7. A malleable application that grows at the point of use

**Idea — I:** a user corrects a running application's behavior; the system forks its capsule, grows the requested behavior and needed substrate, checks preservation obligations, and lets the user adopt or undo the branch. **100x — I:** software evolves with every person and community instead of offering a fixed product menu; tools share persistent data and can exchange qualified behavioral extensions.

**Lineage — F:** Victor argues for visible flow/state and continuous reaction rather than destroying and rebuilding an application's world. [Learnable Programming, September 2012](https://worrydream.com/LearnableProgramming/). Ink & Switch argues for in-place modification, composable tools and communal creation; it explicitly says AI code generation alone does not solve malleability. [Malleable Software, June 2025](https://www.inkandswitch.com/essay/malleable-software/). **I — Then/now:** programming skill, deployment friction, composition, and persistent-state continuity limited reach. Agents address some skill costs; capsule branches address reversibility; neither supplies user intent or a shared data model automatically. `pi-world` is an immediate implementation precedent, not a distant analogy.

**Model-release leverage — I:** better models can turn smaller demonstrations into coherent extensions and preserve more interacting user customizations. The environment remains useful if models become nearly perfect coders: it supplies inspectable state, version history, direct editing, and boundaries among extensions. A chat box that repeatedly regenerates the whole app would be a weak bet and is demoted here.

**Value — I:** small operational teams, researchers, community organizations and power users pay for tools that fit their changing work without commissioning a new app. Adoption depends on reliable data continuity and understandable changes, not merely fast generation.

**First proof — E, two weeks:** start with a plain task/roster application and shared persistent records. A user demonstrates “split this shift across two people”; the app lacks both that action and its conflict rule. Grow the action and validation helper in a fork. Preserve unchanged reference behavior outside the explicitly changed surface, and test the changed surface against user-approved examples plus independent invariants and unseen combinations. Do **not** demand equivalence to the old app for the intentional change. Keep data migrations transactional and versioned. Adopt, add another extension, then undo the first without losing intervening records; reject a conflicting extension with a visible reason.

**Demo + hook — I, 90 seconds:** a real user points to the missing action, tries two grown alternatives against a fork of their data, inspects a conflict, and adopts one. A failed change leaves their original state intact. **Draft tweet:** “The user changed the running tool, including a validation rule the app didn't expose. We tried it on a fork of their state and kept the old behavior where they hadn't asked for change. Undo kept their data. The model writes the patch; the environment makes it usable.”

**Kill test — E:** in a five-user task study, **most users cannot explain what changed and reverse it without developer help**. Then the system fails the user-agency goal even if its code passes tests.

**Judgment — I:** high user value but crowded and hard to validate objectively. Treat it as a later application of a robust substrate, not a reason to invent a new app builder now.

## 8. The grower grows itself: agents manufacture their own computing substrate

**Idea — I:** an agent evolves its module resolver, editor, planner, component library, and public test generator by running candidate descendants in forked capsules against a frozen external audit. **100x — I:** give an agent a tiny stable seed and a goal; it grows the tools, runtime services, and applications needed to pursue that goal, including better tools for growing the next generation.

**Lineage — F:** self-hosting compilers preserve capabilities through successive builds; Thompson also demonstrated why source inspection alone cannot establish trust in that chain. [Reflections on Trusting Trust, August 1984](https://www.cs.cmu.edu/~rdriley/487/papers/Thompson_1984_ReflectionsonTrustingTrust.pdf). Varela, Maturana and Uribe characterized self-producing organization and a minimal simulated model. [Autopoiesis, May 1974, author-university record](https://repositorio.uchile.cl/bitstream/2250/160309/1/item_34548860810.pdf). **I:** autopoiesis supplies a design analogy about producing components that sustain further production; it is not evidence that this software is alive or autonomous from its compute/model provider.

**F — DGM is direct prior art.** It maintains an archive of self-modifying coding agents and reports benchmark gains with frozen foundation models. Its revised paper also reports cross-benchmark transfer. The SWE-bench diagnosis saw private test patches, according to Appendix C.3; that search signal must not be described as our sealed-audit design. [Zhang et al., submitted May 29, 2025; v3 March 12, 2026](https://arxiv.org/html/2505.22954v3). **I — Then/now:** DGM establishes bounded empirical self-improvement, not unbounded progress or self-written trustworthy infrastructure. Capsules add cheap reproducible state branches and lineage; runtime/API growth gives the evolved agent a broader substrate to change.

**Model-release leverage — I:** stronger models improve both problem solving and the search over agent/runtime designs. Archive old useful components and rerun them with the new model; do not assume last generation's prompts remain optimal. This is the most direct “models as substrate” bet, but also the easiest to overstate as recursive intelligence improvement. The model weights are external and unchanged.

**Value — I:** autonomous coding/execution platform teams could pay for a task-specific toolchain that improves with observed failures and remains reproducible. A one-off self-modifying demo has little product value; the result must transfer to independent future work and beat an unchanged harness at equal budget.

**First proof — E, 1–2 weeks:** fix a small TS growth agent, trusted supervisor, public task suite, and an external audit of new API-growth tasks. Permit descendants to change only editing/planning tools, module packaging, and public probe generation—not acceptance code, capability policy, model budget, or audit access. Keep a branching archive and compare 20 bounded descendants with 20 trials using the unchanged harness, counting all search/inference/oracle cost. A descendant must use its changed tooling to grow one further runtime component; rebuilding itself and executing that growth task demonstrates limited self-hosting. Judge winners once on untouched tasks; do not keep selecting on the “final” audit.

**Demo + hook — I, 90 seconds:** show an agent repeatedly failing at a stateful API task, growing a better byte/sequence inspection tool, then using that tool to complete a different unseen task. The code lineage and immutable grader hash stay visible. **Draft tweet:** “This agent improved the tool it uses to grow runtime APIs, then used the new tool on an unseen task. It could change its harness, but not its grader or authority. A bounded self-hosting experiment—not a claim of runaway self-improvement.”

**Kill test — E:** the evolved harness shows **no gain on untouched tasks at equal total search-plus-execution budget** against the unchanged harness. Benchmark-selected ancestry alone is not useful self-improvement.

**Judgment — I:** highest model complementarity, lowest near-term confidence. Defer until ordinary substrate growth and independent auditing work; otherwise it mainly evolves ways to exploit a weak scoreboard.

## Why the next model release increases the opportunity

**I — The durable abstraction is a factory with an oracle, not a repository of generated implementations.** Stronger models could expand what can be grown from pure functions to stateful APIs, multi-module OS services, and whole application protocols. Accepted components execute without ongoing inference; expensive first use can be amortized across later capsules. Better synthesis also increases demand for independent evidence because plausible wrong implementations get harder to spot by inspection.

**E — A useful accounting model:** cost per newly supported program is `(proposal cost + oracle cost + independent audit cost + seed-engineering cost) / newly passing unseen programs`. For continuing optimization, amortize those costs over actual future executions and subtract operating savings. If candidate acceptance probability is `p` and an accepted reusable component unlocks `g` unseen programs, an approximate independent-trial proposal term is `C / (p × g)`; retries are often correlated, so report actual receipts rather than fitting that formula to GrowOS's N=1 result. Stronger models may improve `p`, `g`, or both. Verification costs may grow as fast as implementation scope.

**I — Preserve the assets that a model release cannot replace by itself:** captured customer contracts, representative histories, controlled reference environments, independent audits, versioned artifacts, effect ownership, and deployment adapters. Code generation and prompt tricks are replaceable. If a future model writes a whole correct runtime in one call, this system should become a faster qualification/distribution channel for it. If customers can obtain the same qualified result from a standard coding agent and CI with equal effort, the product boundary has disappeared.

**E — Test the model-release thesis rather than assuming it.** Freeze the workload split, seed APIs, public evidence, final audit generator, and per-run resource limits. Compare at least two available model generations with repeated transactions, both at equal proposal count and equal total budget. Record acceptance, incorrect accepts on a fresh audit, unseen-program unlocks, helper interventions, tokens, wall time, and amortized cost. Do not call a higher acceptance rate progress if incorrect acceptance rises. This report makes no measured claim that a later model will always win.

## Ranking all eight

**I — Relative judgment, not a numerical forecast.** Order combines ambition, model complementarity, objective evidence, paid value, and a credible two-week proof.

1. **Fault-grown Node (#1):** strongest first product and public experiment; scope the compatibility promise tightly.
2. **Continuous oracle-preserving rewrites (#4):** strongest lasting model-release story; cheap pure-function oracles give it a tractable start.
3. **Runtime grown for each capsule (#2):** turns acceptance into a portable artifact; must beat ordinary packaging after counting the heap.
4. **Behavioral map/oracle factory (#5):** necessary compounding infrastructure; standalone demand and distribution need validation.
5. **Blank application OS (#3):** biggest systems hook, but shared state and seed expansion make autonomy easy to overclaim.
6. **API resurrection (#6):** a plausible paid migration wedge, with hard limits when the reference disappears.
7. **Self-growing grower (#8):** enormous upside and direct model complementarity; poor first project before the grader is trustworthy.
8. **Malleable user applications (#7):** real value, strong lineage, close existing prototypes, and the least objective oracle for intended changes.

## Ranked shortlist: the three to pursue

**1 — Fault-grown Node. I:** it converts the GrowOS result into a familiar developer failure: “this package needs an API the environment lacks.” A live missing call, a rejected implementation, an unchanged program succeeding, and reuse by another program are inspectable within a minute. The reference already exists, and the first version can remain above the trusted host boundary. Its credible 100x horizon is a runtime that grows compatibility on demand across the npm ecosystem. The decisive comparison is existing Workers support and conventional shims; being worse than those on familiar APIs is not rescued by an ambitious name.

**2 — Continuous oracle-preserving rewrites. I:** this most directly monetizes every better model release. A customer supplies behavior worth preserving and an operating objective; the factory keeps searching while the deployed service remains pinned. It can optimize old accepted modules from #1 before attempting whole applications. The capsule adds a reproducible starting point for candidate evaluation and a place to keep old revisions alive. Begin with deterministic transformations and prove net savings, then earn stateful migrations. The right headline is a measured improvement under a fixed contract, not an assurance that arbitrary software can safely rewrite forever.

**3 — Runtime grown for each capsule. I:** it makes the output of the first two concrete: a program, its exact qualified substrate, and a portable history. It extends exokernel/library-OS specialization into automatically manufactured implementations. Stronger models can reduce or reorganize that substrate without changing the contract. The experiment is meaningful only if total bytes, initialization, and state costs improve over ordinary bundling. Even if compression benefits fail, qualified runtime ownership may survive as a useful feature; it then deserves feature-level scope rather than the central thesis.

## The one I would bet on

**I — Build fault-grown Node, with the oracle factory as its core and the capsule as its output.** Spend the first two days freezing the module/sequence boundary and two independent evidence splits. Spend the next five days growing real missing behavior with all attempts counted. Spend the last three testing untouched packages, comparing conventional compatibility routes, and showing a hosted execution only if actually qualified. A successful decoder alone is a mechanism demo; unseen program lift is the bet. After that works, let each model release attempt harder gaps and improve previously accepted modules. This is a plausible path from GrowOS's local syscall result to software whose implementation follows demand, while its behavioral obligations accumulate.

## Five-line TL;DR

1. **M:** GrowOS's 218 grown handler lines helped move comparable corpus passes from 4% to 81%; human helpers and environmental overfitting materially qualify the result.
2. **I:** Treat a missing API as a semantic fault: park/retry, grow against a reference, independently qualify, cache, then run ordinary code.
3. **I:** Bet first on fault-grown Node; extend into continuous contract-preserving rewrites and runtimes tailored to each capsule.
4. **I:** Stronger models expand the factory's reach; contracts, independent audits, reusable components, and execution histories compound across releases.
5. **I:** Kill the thesis if it cannot unlock unseen programs beyond ordinary shims at useful cost; passing familiar traces is not sufficient evidence.
