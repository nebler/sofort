# Pain first: thirty developer failures, and three bounded community projects

Research date: **2026-10-28**. Lens: pain in TypeScript, Cloudflare, Vercel and their package/test/runtime ecosystem. Read [the brief](BRIEF.md) first, then the earlier rounds' TL;DRs in `v8`, `moonshots`, `moonshots2`, `teleport`, `flip`, `flip2` and `split`.

**I — Recommendation:** the best small project is a **workspace-aware reproducer reducer**, preferably an extension to an existing reducer. Turn a failing pnpm/npm workspace into a small independently runnable example while preserving its dependency-resolution failure. The two runners-up are reusable **agent reconnect/reset test scenarios** and a **resolution witness** comparing what a compiler, bundler and runtime actually loaded. These are conditional community projects, not established empty product categories. None needs GrowOS, jitk, a new kernel, heap transport or a new agent runtime.

**F/I — The central finding:** developers repeatedly lose time at boundaries: local versus deployed execution, package-manager graphs versus runtime imports, fresh versus cached installs, client state versus durable server state, and TypeScript's compiler versus tools embedding it. Owners are fixing many individual failures. The remaining plausible community contribution is to make those failures cheap to reproduce and independently diagnose. Better models can generate repairs; they do not remove the need to identify which concrete failure a repair addresses.

## Evidence method and limitations

**Labels:** **F** = directly sourced fact or explicitly attributed report; **M** = observation made during this research; **I** = inference/ranking/design judgment; **E** = proposed scope, time or threshold. Reaction counts below are **M**, collected from GitHub REST responses, not guessed from search snippets. No application/runtime benchmarks were run.

**M — GitHub census:** for every requested repository, requested the top **30 open issues**, excluding PRs, with:

```text
GET https://api.github.com/search/issues
  ?q=repo:OWNER/REPO is:issue is:open
  &sort=reactions&order=desc&per_page=30
Accept: application/vnd.github+json
```

The successful responses were dated **2026-10-28 13:43–13:46 UTC**. They contained **320 issue records** across the thirteen requested repositories. Also searched all states for pnpm and Turborepo, and searched TypeScript issue titles for `7.0`, `API` and `migration`; inspected the moved `microsoft/typescript-go` repository. The connected GitHub search omitted reaction fields, so the REST API was necessary. Search throttling returned 403 on an initial batch; the affected requests were retried successfully after the quota reset. Counts are snapshots, not longitudinal trends.

**M — Reading depth:** read selected issue bodies and comments, with special attention to maintainer statements and newer replies. Long TypeScript threads were additionally read through the connector's all-pages comments endpoint. For most short threads the REST response contained every comment. “No commitment found” below means exactly that in the inspected thread; it does **not** mean a platform has no private plan. Labels, open status and bot triage are not delivery commitments.

**I — Ranking:** the table is a triage ranking of **pain clusters**, not a global top-30 reaction leaderboard. Rank production correctness/progress loss first, then blocked builds/installs, then recurring ergonomics; use breadth of independent evidence and reactions as secondary signals. This deliberately prevents decades-old language suggestions from excluding every newer operational failure. The rank is judgment, not a prevalence estimate. Counts from different issues are not added: people overlap, emoji differ and repositories differ enormously in size.

**F/M — Important qualifications:** an open ticket is evidence of an outstanding report/request, not proof that its old reproduction fails on today's release. Most issues originating in 2023–25 were not rerun. The table states partial solutions and owner plans where found. New low-reaction reports remain low-confidence demand signals, even when their reproduction is detailed. The appendix preserves raw reaction leaders so the triage order is auditable.

**M — Forum coverage is incomplete:** `https://community.cloudflare.com/`, `/search.json?q=workers+after:2026-01-01+order:likes`, and `/top.json?period=year` returned **HTTP 403 Forbidden**; web access also failed. Several domain-restricted search queries did not yield a usable primary forum corpus. I did not invent forum likes, views or a forum-wide ranking. Public Cloudflare Discord messages indexed by Answer Overflow were readable and are analyzed below. Therefore this is the strongest evidenced shortlist from the accessible corpus, **not an exhaustive claim about all late-2026 developer pain**.

**M — Survey limitation:** verified the primary **State of JavaScript 2025** results, including its TypeScript balance and pain questions. Could not verify a separate primary “State of TS” survey with published pain-point data. Searches for that name mostly returned commentary; `stateofts.com` and `stateoftypescript.com` redirected to Michigan TypeScript's YouTube channel. No secondary article's numbers are presented as a separate TS survey.

## Corrections that prevent stale opportunity claims

## Three retained candidates

### A. Workspace repro reducer — the pick, conditional on a two-day baseline test

**I — One sentence:** shrink a failing workspace's packages, peer contexts and configuration into a small reproducible issue attachment, while retaining an explicit “works here, fails there” control.

**E — Thirty-second demo:** start with a trusted 100-package Next/Workers workspace whose filtered frozen install fails; show its dependency graph collapsing to `app → library ↔ peer`, replay the same failure from a fresh directory, then switch to the fixed manager version and watch it pass. Numbers and timings in this demo are targets, not observed results. The export should be runnable without the reducer itself.

**F/I — Gap and closest prior art:** [Repro Surgeon](https://github.com/pavangupta352/repro-surgeon) already reduces source, JSON fields and direct npm dependencies, preserves failure signatures and exports an independent verifier. Its published README explicitly excludes npm workspaces, pnpm/Yarn lockfiles, local dependencies and managed service startup. [FailTrace](https://github.com/LBarimi/FailTrace) repeats, minimizes and verifies failures; [ReproMin](https://github.com/robbyczgw-cla/repromin) reduces straight-line Playwright actions. [Turbo prune](https://turborepo.com/docs/reference/prune) and [pnpm deploy](https://pnpm.io/cli/deploy) produce deployable subsets, not a minimal graph retaining a specified resolver failure. **The extension is workspace/peer topology and control preservation, not invention of delta debugging.** [GReduce research](https://arxiv.org/abs/2402.04623), published 2024-02-07, is relevant to validity-preserving reduction; do not claim a new algorithm.

**F — Pain evidence/beneficiary:** ranks 2, 4, 13, 14 and 30. npm's cache/lockfile issue has **97 reactions** and override/workspace issue **92**; Bun's monorepo thread has **226**. Fresh [pnpm #17444](https://github.com/pnpm/pnpm/issues/17444), **0 reactions / 2 comments**, contains a hand-built local registry to expose command-dependent transitive resolution. [#17447](https://github.com/pnpm/pnpm/issues/17447), **0 / 2**, needs a precise combination of filtering, injected workspace dependencies, a peer-mutating hook and a lockfile. Their fixes are owner work; the repeated effort to construct and preserve such witnesses is the proposed community value. These small new counts do not establish a large market. Beneficiaries are package-manager maintainers and monorepo build engineers.

**I — Survives better models:** a model can delete files rapidly, but every candidate must still install and exhibit the same graph-sensitive failure. The reusable value is deterministic fixture orchestration, retained-version evidence and a recipient-runnable control, not an LLM's explanation. Better models also make the baseline formidable: if an ordinary agent with existing tools emits an equally good repro in minutes, this project loses.

**I — Why owners would adopt it:** npm, pnpm, Bun, Next and Workers each need users to supply repros; none owns the other tools' dependency rules. They can adopt exported fixtures without adopting another runtime or hosting service. Prefer extending Repro Surgeon or contributing a standalone workspace adapter over starting a competing general reducer. No explicit adoption offer was obtained.

**E — Two-to-three-week v1:** one manager, pnpm, one platform profile, a trusted Next/Workers workspace, and finite command failures. Import package/workspace manifests and retained lockfile identities; construct a disposable local fixture; remove workspace nodes, edges and selected configuration; retain a precise failure plus known-good command/version. Pin retained external package versions/integrities. Permit topology changes only when the named failure still reproduces, never silently upgrade dependencies to make installation succeed. Export source, reduced config, manager/runtime versions, graph evidence and a verifier with independent fresh-install checks. An offline HTML graph/report is enough for the demo; Cloudflare/Vercel deployment is unnecessary. Reuse an existing reducer engine. Browser races, private registries and arbitrary lifecycle scripts are out of v1.

**I — Expert reply that kills it:** “`turbo prune`/`pnpm deploy` plus one ordinary coding agent and Repro Surgeon already gets my real failure down to three packages; your graph rules mostly create invalid installs.”

**E — Kill test:** before building a UI, compare on **six independently authored public workspace failures**, at least two with peer/filter/hook interactions, using identical command/time budgets. Require useful independent repro exports for **at least four**, no wrong-error substitution on a fixed-control and an unrelated-error control, and **at least 2× less human investigation time** than the strongest existing-tool-plus-agent baseline. Count installation and reduction time. A smaller archive alone does not pass. If the closest project's maintainer already has this adapter underway, contribute tests or stop. The two-day phase determines whether a three-week build is warranted.

**I — Residual uncertainty:** the corpus establishes real graph-sensitive bugs and a documented limit in the nearest reducer. It does **not** yet establish that topology reduction is frequent enough, or sufficiently better than agents, to justify a maintained standalone project.

### B. Reconnect/reset scenario pack — a narrow community testing contribution

**I — One sentence:** supply reusable, versioned test scenarios that coordinate client disconnect, server acceptance, partial output, DO reset, history persistence and explicit Stop, then shrink a failing event schedule.

**E — Thirty-second demo:** a chat turn is accepted; disconnect before its first token; reset the local Durable Object; reconnect and press Stop. A split timeline displays client status, persisted turn state and provider attempts, showing the exact transition where they disagree. Replay the exported sequence after a fix and show the corrected terminal state. Use a scripted model; spend no model API calls.

**F/I — Gap and closest prior art:** [AI SDK testing](https://ai-sdk.dev/docs/ai-sdk-core/testing) already supplies mock models and delayed streams. [DotMock's chaos guide](https://dotmock.com/docs/guides/llm-chaos), last verified **2026-09-25**, covers seeded drops, malformed chunks, throttles and disconnects; [MSW SSE](https://mswjs.io/docs/sse/) mocks transport events; [Toxiproxy](https://github.com/Shopify/toxiproxy) injects network conditions. [fast-check model-based commands](https://fast-check.dev/docs/advanced/model-based-testing/) already shrink scenarios, and its [scheduler](https://fast-check.dev/docs/advanced/race-conditions/) handles race exploration. Cloudflare's own abort/evict helpers supply the runtime seam. **Only the maintained cross-layer scenarios/adapters are proposed.** Generic chaos, replay, model testing and a timeline viewer are occupied.

**F — Pain evidence/beneficiary:** [Agents #1918](https://github.com/cloudflare/agents/issues/1918), **2 reactions**, has two concrete production reports of dead-stub callbacks; [#2741](https://github.com/cloudflare/agents/issues/2741), **3 reactions**, isolates accepted-but-not-streaming cancellation. AI SDK's message conversion request has **24 reactions**. SDK maintainers and application teams integrating a custom transport are the beneficiaries. This is not evidence that every app needs another testing framework.

**I — Survives better models:** no reasoning improvement prevents a real disconnect or ensures an app's chosen cancellation semantics. Models can write adapter/tests more cheaply, which helps maintain the pack. The continuing artifact is an executable event history and explicit state assertions. Arbitrary model quality is not the oracle.

**I — Why owners would adopt it:** Cloudflare and Vercel want robust examples and regression cases that exercise their documented APIs. A small portable scenario interface can serve their test suites without replacing their SDKs. The two existing bugs may be fixed tomorrow; the pack must find useful cases across SDK versions and user adapters. Avoid becoming a durability implementation: [Vercel's resumable-stream](https://github.com/vercel/resumable-stream) and [TanStack's durable stream adapters](https://tanstack.com/ai/latest/docs/resumable-streams/advanced) already own that behavior.

**E — Two-to-three-week v1:** scripted HTTP/SSE model; one actual AI SDK Node app; one Agents/workerd app; six scenarios (disconnect before first frame, after partial output, during a tool, reset before callback, reconnect then stop, reconnect after completion). Event barriers coordinate real processes; fast-check chooses/shrinks ordering at the adapter boundary. Assert explicit user contracts: a disconnect alone does not imply cancellation; explicit Stop reaches a terminal state; a completed turn is discoverable; the application declares its retry/idempotency contract. Keep client and provider clocks separate. Reuse an existing viewer or export a small timeline. No claim of deterministically scheduling every workerd internal operation.

**I — Expert reply that kills it:** “Those six tests are already in the SDK; MSW plus the documented eviction helper adds the rest in an afternoon.”

**E — Kill test:** inspect current SDK tests first, then compare with the existing helpers plus a strong ordinary agent on two independently built adapters. Continue only if the pack reproduces **three distinct real cross-layer failures**, yields independently replayable schedules without a paid provider, and saves meaningful setup time in both apps. Stop if only one now-fixed Cloudflare bug differentiates it, or the fake model/clock rather than real app state creates the failure. Platform tracing is not a substitute for this test, but could absorb its UI.

**I — Residual uncertainty:** direct demand is low-count. This is credible as a contribution or example package; a separate project's adoption remains unproven.

### C. Resolution witness — retain only after testing the attw/publint baseline

**I — One sentence:** emit an evidence bundle showing which installed package, export condition, declaration file and executable file each tool selected for one failing import.

**E — Thirty-second demo:** click the same `import` in a small Next/Workers library fixture: TypeScript's declaration branch, Node's executable branch and the Worker bundle's branch illuminate separately. A packed consumer and a workspace consumer diverge. The export contains the exact versions, selected paths and two runnable outcomes, not just a color-coded compatibility guess.

**F/I — Gap and closest prior art:** [Are The Types Wrong?](https://github.com/arethetypeswrong/arethetypeswrong.github.io) already analyzes package type/runtime-resolution mismatches; [publint](https://publint.dev/docs/) checks package compatibility/configuration; [resolve.exports](https://github.com/lukeed/resolve.exports) evaluates conditional maps. Bundlers expose dependency/metafile analysis and package managers expose `why`/`explain`. These are the necessary baseline and likely implementation dependencies. **The residual hypothesis** is joining actual consumer/tool observations, installed symlink/peer context and fresh packed-consumer results in one small issue attachment. A nicer conditional-exports viewer alone fails the gap test.

**F — Pain evidence/beneficiary:** ranks 2, 3, 6, 13 and 30: Next's `nodenext` report **109 reactions**, npm's packed workspace omission **67**, Bun's native-addon tracking **276**. The tool must distinguish a resolution difference from unsupported APIs/native ABIs; discovering a selected file does not make that file runnable. Library and bundler maintainers benefit from one concrete mismatch witness.

**I — Survives better models:** the installed graph and actual loader behavior are external facts. Better models can consume the evidence and propose a fix, but cannot infer a private installation or runtime configuration from package names alone. Conversely, better models might already join existing output with negligible effort; measure that baseline.

**I — Why owners would adopt it:** tooling owners can accept small evidence bundles without claiming competitors' runtime semantics. Cloudflare could adopt fixtures for its bundler; attw/publint could adopt a runtime/consumer adapter. This is a community module, not a claim that the platform will never add the same diagnostic.

**E — Two-to-three-week v1:** Node plus one Worker build target, one fixture entrypoint, pnpm workspace and packed-consumer modes, no universal package census. Record actual executable/declaration paths, hashes, condition/config inputs, version/integrity identity and import outcome. Pair a TypeScript trace with a bundler metafile and a tiny runtime probe. Explain planned conditions separately from observed loading. Add Bun/Deno only after two adapters work. Do not execute unknown packages as a public service.

**I — Expert reply that kills it:** “attw, publint and the esbuild metafile already identify this exact branch; your bundle contains no new observation.”

**E — Kill test:** on five independently authored packaging/resolution failures, at least three must require an installed consumer or runtime fact not already supplied by attw/publint. A recipient must reproduce the mismatch with one command, and ordinary-agent-plus-existing-output must take materially more setup time. Kill it if the work is only formatting existing diagnostics; fold it into candidate A if the only useful distinction is workspace versus packed consumer.

**I — Residual uncertainty:** weaker novelty evidence than A; it may be the right feature of an existing package checker, not a project.
