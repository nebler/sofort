# Pi and the observed time profile of agent sessions

Research date: 2026-10-28. **Verdict: go-with-changes.** The portable agent loop is viable; “unmodified Pi CLI in a hibernating DO” is the wrong implementation target. Current Pi already has an experimental Worker-oriented durable harness. The local measurements support short commands by count, but do not establish 80–95% model waiting across active wall time.

Labels: **F** = sourced fact; **M** = measured locally; **I** = inference or interval attribution; **E** = estimate. Probabilities and experiment budgets below are estimates, not measurements.

**F.** CLI startup constructs configuration/model services and an `AgentSession`. A prompt is expanded through resources/extensions; the underlying `Agent` transforms internal messages to model messages, invokes its `streamFn`, consumes streamed assistant events, validates tool arguments, executes requested tools, appends results, and requests another model turn until settled. Tool execution can be sequential or parallel; file mutations additionally use a per-path queue. CLI compaction and branch summaries can make separate model calls. Usage includes input/output/cache tokens and provider cost fields. [Loop](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/agent/src/agent-loop.ts), [SDK](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/sdk.ts), [session](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/agent-session.ts).

**F.** `pi-ai` supplies OpenAI/Anthropic/Google/Bedrock and other providers through provider-specific streaming implementations. The normal SDK's `ModelRuntime.streamSimple()` resolves credentials, routing and request transforms before calling the selected provider. Native provider SDKs include `openai`, `@anthropic-ai/sdk`, `@google/genai`, AWS Bedrock/Smithy HTTP handling, and proxy agents. Provider selection matters: browser-safe fetch/API-key paths do not require all the OAuth, AWS credential-file, local HTTP callback-server or proxy machinery that appears in the full source tree. `pi-agent-core` accepts a supplied stream function; portable code can register only its required provider. [Model runtime](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/model-runtime.ts), [AI manifest](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/ai/package.json), [selective-provider smoke check](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/scripts/check-browser-smoke.mjs).

### Built-in tools: no shell requirement for editing

**F.** Default coding tools are **`read`, `bash`, `edit`, `write`**. Additional registered built-ins are **`grep`, `find`, `ls`, `powershell`**. `powershell`'s local backend is Windows-specific. The read-only tool set is read/grep/find/ls. Current CLI also supports MCP, tool search and codemode as built-in extensions; the SDK does not automatically install those extensions. [Tool factories](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/tools/index.ts), [SDK extension defaults](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/docs/sdk.md#codemode-mcp).

| Tool | Default implementation | Existing replacement seam |
|---|---|---|
| `read` | File access/read; image detection and optional resize; text truncation. | `ReadOperations`: read/access/MIME detection. |
| `write` | Recursive mkdir and UTF-8 write. | `WriteOperations`: mkdir/writeFile. |
| `edit` | Read file, exact targeted replacements with normalization/BOM/line-ending handling, write file, generate diff. | `EditOperations`: access/readFile/writeFile. **No subprocess or real shell is required.** |
| `bash` | Locate shell, spawn `bash -c`/fallback, stream output, timeout/abort/process-tree handling. | `BashOperations.exec`, plus spawn hook. |
| `ls` | Directory metadata/listing. | `LsOperations`. |
| `grep` | Spawn ripgrep by default. | `GrepOperations`, including search operation. |
| `find` | Spawn fd by default. | `FindOperations`, including glob operation. |
| `powershell` | Local Windows shell backend. | PowerShell operations/spawn hook. |

**F.** Default grep/find can discover or download native `rg`/`fd` executables. Bash output above thresholds spills to a local temporary file even when execution itself is replaced; a remote `exec` adapter alone does not remove every filesystem dependency. Extensions' `pi.exec`, user bash execution, package management, MCP stdio and OAuth helpers are additional process paths. [Bash](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/tools/bash.ts), [output accumulator](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/tools/output-accumulator.ts), [tool downloads](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/utils/tools-manager.ts), [extension execution](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/exec.ts).

**M.** In both Node and local workerd, the existing `createEditTool` changed a virtual file through precisely `access → read → write` supplied as operations; no shell was invoked. This directly falsifies a hard-shell dependency for Pi's text edit tool. It does not establish POSIX filesystem parity or large-file behavior.

### Sessions and extensions

**F.** CLI sessions use append-oriented **JSONL**, version 3, normally under `~/.pi/agent/sessions/<encoded-cwd>/`. Records have IDs/parent IDs and form a branchable tree, with model/thinking changes, messages, compaction and extension/custom entries. `SessionManager` reconstructs the active branch's model context. Persistence uses synchronous mkdir/open/read/append/write operations, plus asynchronous session discovery. `SessionManager.inMemory()` exists, as do in-memory settings and credential/storage seams; replacing the session manager does not replace all other file-backed services. Settings, auth, models, resources and temp output need separate treatment. [Session manager](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/session-manager.ts), [SDK storage contract](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/docs/sdk.md#sessionmanager-api).

**F.** CLI extensions are arbitrary JS/TS factories discovered from configured/project/global paths or supplied inline. They can register tools, slash commands, shortcuts, provider implementations and hooks over model requests, tool calls/results, context and session events. File-based TS loading uses **jiti**, filesystem resolution and `createRequire`; source-runtime loading also has Node loader-hook paths. Extensions can use any npm dependency/Node API their author imports. Thus “every API used by Pi plus every user extension” is unbounded; no finite builtin compatibility list proves arbitrary extension compatibility. A Worker host should bundle a deliberate extension set or use the durable registry, rather than assume arbitrary npm/git-installed CLI extensions run unchanged. [Extension loader](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/core/extensions/loader.ts), [extension API](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/docs/extensions.md).

### Which mode belongs in a Worker?

| Interface | Actual contract | Assessment |
|---|---|---|
| Interactive TUI | `process.stdin/stdout`, raw mode, resize/signals, terminal protocols, optional native clipboard. | Keep in client or execution host; inappropriate Worker brain. |
| Print/text or JSON headless | One-shot CLI; stdout text or JSONL events; process startup/exit and ordinary CLI services. | Useful execution-host command, not a durable Worker lifecycle. |
| RPC | Long-lived JSONL stdin/stdout control protocol; RPC client launches a child process. | Good external-process integration. **Not HTTP/Workers RPC**, and still a process/stdio lifecycle. |
| Coding-agent SDK | In-process `createAgentSession`, event subscriptions and injectable services/tools. | Correct choice **among CLI modes**. Can preserve much CLI behavior, with deliberate resource/storage/tool adapters. |
| `pi-agent-core` + selected `pi-ai` providers | Small agent loop with supplied model stream/tool implementations. | Smallest brain, but host must implement persistence/recovery and CLI conveniences. |
| **`pi-durable` + Cloudflare storage + ExecutionEnv** | Durable tasks/conversations, commits, explicit alarms and environment capabilities. | **Preferred current upstream starting point**, if its experimental API and different extensions are acceptable. |

[Mode contract](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/docs/cli.md), [RPC implementation](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/modes/rpc/rpc-mode.ts), [RPC subprocess client](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/coding-agent/src/modes/rpc/rpc-client.ts), [Durable host example](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/durable/README.md#sleeping-and-waking-up).

**I.** Proposed shape: DO SQLite stores session/task metadata; a file-capability adapter owns workspace versions; supplied tools issue durable runner jobs; runner completion arrives as an event and results are committed before the next turn. Use a persistent runner job/call ID so retries can retrieve the same outcome. The existing `pi-env` abstraction is helpful, but its Node SSH transport is not itself a Worker transport. A runner HTTP/service-binding adapter and workspace synchronization policy are still required. Workspace files are not automatically stored by pi-durable's conversation SQLite adapter.

## 3. Local portability experiments

**M.** Installed current published packages with lifecycle scripts disabled in scratch. Used existing **workerd 2026-10-25**, a loopback HTTP socket, compatibility date `2026-10-25`, and no account/deployment/model API. Processes were terminated after requests.

1. **Portable harness: PASS.** Bundled `pi-durable` + `pi-ai` faux provider + Chord context + MemoryStorage. A request created a conversation, submitted an input, completed a fake model turn, read its committed assistant entry and closed the harness. HTTP 200, settlement `done`. Unminified bundle: **911,879 bytes**, no external Node builtin imports in its bundle metadata. This was a memory-storage smoke test, **not** a deployed DO, SQLite restart, real provider or hibernation test.
2. **Coding-agent SDK import/session/edit: PASS with host wiring.** The ordinary SDK root initially hit bundler CommonJS `require`/`import.meta.url` integration failures. Supplying a `createRequire` banner and a fixed bundle file URL made it load. Explicit memory settings/session, a credential-store stub, `modelsPath:null`, no catalog-network refresh, a supplied resource loader and `noTools:'all'` created/disposed an `AgentSession`; an operations-backed edit also passed. Package source was unchanged. Final unminified SDK probe bundle: **13,327,471 bytes**. This is a broad root-export/lazy-import bundle, not an optimized minimum, and no SDK model prompt or real shell was exercised.
3. **Native artifact inspection.** Installed runtime packages contained six TUI `.node` platform builds, Photon WASM and QuickJS WASM. QuickJS's five `.so` extension files have WASM magic, not host ELF/Mach-O addon code. No mandatory `.node` addon was needed by either passing probe.

**I.** These results argue against starting with a general “grow Node until the unmodified CLI works” campaign. Existing seams already avoid much of the missing runtime. They also argue against declaring the SDK impossible merely because a source grep finds `child_process`: importable compatibility stubs and lazily exercised branches differ from working process execution.

## 5. Measurement: real local agent sessions

### Scope and method

**M.** Local-only analysis; no transcript contents, command strings, user identifiers, prompts or file paths were copied into this report or uploaded. Retained outputs contain aggregate numbers only. This is one machine/user's workload, **not Pi telemetry**, and model/harness populations differ.

- Claude source: exactly `~/.claude/projects/*/*.jsonl`, **219** files available at enumeration; **212** stable files included. Nested Claude subagent logs were intentionally excluded, avoiding double-counting their wall time against parent Agent/delegation tools.
- Codex source: recursively under `~/.codex/sessions/`, **319** files available, **304** stable files included; **310** completed/aborted turns with usable lifecycle timing, no unmatched active turn in the included files. These files need not equal human conversations; the observed population is largely one recorded turn per file. All 200 inspected recent source metadata records reported `vscode`.
- Fixed inclusion cutoff: file mtime before **2026-10-28 11:16:58 UTC**, one hour before the initial measurement. The final enumeration excludes files that resumed changing during the audit, as well as current research sessions. Zero malformed JSON lines or parser failures among included files.
- Coverage: Claude **2026-10-06–28**; Codex **2026-10-23–28**. **516 session files**, **24,396 matched/recorded shell invocations**. This is a census of eligible stable files, exceeding the requested 50-session sample.
- Claude excludes inherited entries marked `forkedFrom` (a source session/message reference), deduplicates message UUIDs within each file, groups assistant blocks by model message ID, matches tool-use/result IDs, and uses explicit `api-request` → final assistant-block timestamps where available. **12,402/14,583 model messages (85.0%)** had matching request starts. Other model intervals are attributed from the preceding input/result/model event (**I**, not direct inference instrumentation). A Bash duration is tool issuance → matching result: includes scheduling/permission/host delay and can stop before a background job finishes.
- Claude active episodes run from non-meta input (including system task notifications) to the final conversation event before the next input. There were **1,596 human-or-SDK inputs** and **1,072 system wake inputs**. Between-episode gaps are idle/input wait; they are not all human think time. Undetected interruption/suspension can remain inside active episodes.
- Codex uses `task_started`/`task_complete`/`turn_aborted` bounds, `item_completed.started_at_ms/completed_at_ms` for recorded model items and tool items, and matched function/custom-call outputs for controller-await intervals. Command distributions use the command item's recorded duration. Shell argv wrappers were unwrapped before classifying command text. No duplicated item IDs were found.
- All time fractions use **per-session interval unions**, then sum sessions. Concurrent sessions are session-hours, not elapsed calendar hours. Model/tool overlap is shown explicitly. Summing individual command durations would double-count parallel commands.

**Important limitation:** these are wall-clock traces, not CPU, network-wait or syscall traces. A model interval includes generation/stream delivery, not just time to first token; a tool interval can itself wait on network, a child agent, a timer or user input. Historical bytes read/written by arbitrary shell descendants are not logged.

Physical command-event union alone is **55.84 h**. Replacing process lifetimes with short RPC-return durations overstates how soon a runner can be retired.

**M/I.** Median per-file assigned Claude model share is **78.8%**, while its session-time-weighted aggregate is 53.1%. Median Codex residual-outside-awaited-tools is **91.9%**; again that is a residual, not a measured model share. The often-quoted range can describe selected medians or a controller-only accounting convention, but **is not established as the weighted fraction of active wall time waiting exclusively for inference** here. Idle dominates the long-lived Claude session-span denominator; it barely appears in the mostly single-turn Codex files. Neither denominator should be silently substituted for the other.

**F/I.** There is a separate architectural error in equating model waiting with DO hibernation: pending outbound I/O/connections or an unfinished event prevent hibernation; timers also prevent it. In-memory state is discarded on hibernation. A DO awaiting a live provider stream remains active/billable. It may release an execution host during that time, but does not hibernate through an ordinary awaited model fetch. Callback/deferred model execution is a different protocol. Pi Durable's stored sleeps and wake alarms help between runnable phases; they do not serialize a live JS continuation. [Cloudflare lifecycle conditions](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/), [upstream wake/recovery tests](https://github.com/earendil-works/pi/blob/c3d8ce44d3231c7e46071d2d859f41ca7d39d21b/packages/durable/test-workers/wake.test.ts).

## 7. Decision and the first three verifications

**Go-with-changes for this layer.** Prefer upstream **pi-durable + selected pi-ai provider + DO SQLite**, with explicit execution/file capabilities and replay-safe runner jobs. The coding-agent SDK is a viable alternate if preserving CLI session/extension behavior is essential; its minimal in-memory session/edit path already passed locally. RPC/TUI/headless CLI are not the Worker embedding interface. Do not make “unmodified full CLI and arbitrary extensions” or “hibernates while awaiting inference” initial acceptance criteria.

Run these first, in order:

1. **Workspace/runner coherence and actual I/O trace** — blocker 1; zero mismatches and measured bytes/dirty sets before designing the compatibility filesystem.
2. **DO wake/recovery with fake model and runner** — blockers 2–3; include crash-after-side-effect, request-ID deduplication and no-I/O idle phases. Upstream already has relevant tests to extend.
3. **One deliberately supported end-to-end Worker profile** — blocker 4; 100 fake model/tool turns, compaction/abort/spill included, process/TTY calls forbidden in the brain. Use the resulting timings for blocker 5's cost model.

Reproduction/audit artifacts are small local scratch files: `/tmp/split-pi/session-aggregates.json`, `shell-package-aggregates.json`, `node-inventory-ast.json`, `native-inventory.json`, `probe-summary.json`, and the analysis scripts. Large cloned/installed/build artifacts were removed after analysis. No transcript payloads were copied to scratch. No paid model/API calls, deploys, Docker or VM changes were made.

### Five-line TL;DR

1. **Pi has moved/renamed, and already includes an experimental durable harness with Cloudflare storage and remote execution seams.**
2. **Local workerd passed a fake durable model turn and a configured SDK session/edit; text editing needs no shell.**
3. **516 session files / 24,396 shell invocations show 83–87% of commands under 5 s, but a 4–10 minute p99.**
4. **80–95% inference waiting is not established for weighted active wall time; live model I/O also prevents DO hibernation.**
5. **Go-with-changes: verify workspace coherence, replay-safe recovery and one bounded Worker profile before building general Node shims.**
