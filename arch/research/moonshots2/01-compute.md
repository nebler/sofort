# The compute crunch: stop paying a GPU to rediscover a program

Research date: **2026-10-27**. Lens: **THE COMPUTE CRUNCH**.

**I — The bet:** make recurring agent work become ordinary software. An expensive agent discovers a useful procedure; the next execution consumes a parameterized program, dependency hashes and fresh observations instead of another long reasoning trace. The **100× ambition** is to make the world's agent compute 100× cheaper by amortizing discovery across executions, organizations and locations. “Never think the same thought twice” is a direction, not a claim that arbitrary thoughts have a sound global cache key.

**I — Why this survives the round-one objection:** every superhuman-model test below assumes models **100× more capable**, including the limiting case of a model that never makes an intellectual mistake. It still consumes accelerator capacity, reads context, waits for observations and pays network latency when invoked. A perfect model can generate a better reusable program; it does not make repeatedly executing a general model physically free. However, a perfect model might already choose to write that program itself. The product must capture, distribute, invalidate and operate the resulting work better than an agent plus a normal repository. Independent verification is useful engineering here, not the proposed source of scarcity.

**Evidence notation:** **F** = sourced fact, including explicitly attributed vendor measurements and forecasts; **M** = measurement performed for this report; **I** = inference or proposed design; **E** = estimate, scenario, target or experimental threshold. No new runtime benchmark was performed, so there are no new **M** performance claims. Calculated scenarios remain **E**. All web sources were accessed on **2026-10-27**; dated papers are pinned where revisions change results. Older sources below establish lineage; demand evidence comes from **2024–2026 publications**.

Required context read: round-one reports' TL;DRs and top bets, plus [the capsule landscape](../v8/02-landscape.md). **I:** this report deliberately moves the scarce resource from accepting generated work to avoiding repeated execution. jitk's tool-only boundary can expose dependencies; QuickJS/Wasm capsules can preserve orchestration; scriptc can compile a residual TypeScript program. None is a prerequisite for every idea.

## 2. What a defensible 100× claim requires

**I — Count five things separately:** dollars per completed useful job; accelerator work/time; HBM byte-seconds; end-to-end latency; and measured energy. Token counts help attribute cost but cannot substitute for these. Count build/search attempts, fallback inference, cache writes and refreshes, storage, network, tool fees and operations. Hold task success, freshness and authorized effects constant.

**E — Reuse ceiling:** let `h` be the fraction of baseline total cost eligible for successful reuse, `r` its residual cost ratio, and `a` all additional overhead as a fraction of baseline cost:

```text
new / old = (1 - h) + h*r + a
```

**E:** with `r = 0.001` and `a = 0.001`, avoiding **90%** of baseline cost yields **9.81×**; **99%** yields **83.40×**; **99.9%** yields **333.44×**. These are arithmetic scenarios, not measured hit rates. A 100× reduction therefore requires unusually repetitive workloads, extremely cheap hits, and very little irreducible cost. A large unchanged API/tool bill can make 100× total savings impossible even with zero model calls.

**E — A concrete CPU-versus-model scenario:** take **one million monthly invocations** of an admitted routine. Each baseline call has **1,800 cached input tokens, 200 fresh input tokens and 300 output tokens**. At the historical Sonnet 4.5 tariff of **$0.30 cached input / $3 input / $15 output per million tokens**, its model cost is **$5,640**, already allowing substantial prompt caching. The tariff is sourced; workload lengths are assumptions. [2025-09-29 launch](https://www.anthropic.com/news/claude-sonnet-4-5), [cache-price table, accessed 2026-10-27](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

**E:** suppose compilation plus qualification costs **$20**, storage/invalidation/extra control traffic **$10**, Worker CPU is **10 ms/invocation**, and **0.1%** of jobs fall back to the baseline model. A **$5/month** Workers plan includes **10 million requests and 30 million CPU-ms**, so the assumed million calls and **10 million CPU-ms** fit the allowance. Cost becomes **$20 + $10 + $5 + $5.64 = $40.64**, about **139× lower** for this modeled compute/control bill. [Workers pricing, accessed 2026-10-27](https://developers.cloudflare.com/workers/platform/pricing/). Cache warm-up charges are omitted from the baseline, favoring it. All candidate resource assumptions need measurement; this is not a benchmark or a complete business-workflow bill.

**E/I — Where it collapses:** with **10%** fallback the modeled cost becomes **$599**, only **9.4×** lower. If the baseline qualifies for batch discounts or a cheaper model, compare those too. Under a hypothetical **10×** reduction in the baseline model tariff with the assumed fixed candidate overhead unchanged, the first scenario falls to about **16×**. The model-proof property is removal of recurrent general-model execution; the exact 100× commercial advantage must be re-earned as prices fall. At large repeat counts, fixed compilation cost amortizes further. If a handwritten function already solves the problem, that is the strongest baseline and may be the correct product output.

**I — Store the right object:** a reusable program/plan is not a raw chain of thought, a replay journal is not fresh knowledge, a model's KV cache is not a portable QuickJS heap, and a cached read receipt does not authorize another write. Useful artifacts carry input schemas, dependencies, version/freshness rules, cost and compatibility metadata. Similarity can propose a candidate; explicit preconditions determine whether it may execute.

## 3. Eight bets

### 1. Trace foundry: turn repeated agent behavior into a residual program

**One sentence + 100× — I:** observe an agent solving a recurring task, parameterize the stable procedure, and ship ordinary TypeScript/Wasm with explicit fallback points. **100×:** one expensive discovery becomes a program executed across a million changing inputs; models run on novelty, not every row, page or tool transition. This is **program distillation**, distinct from distilling a large model into a smaller neural model.

**Worsening problem / payer — F/I:** D2's **4×/15×** token multipliers and APC's **50.31%** observed plan-caching savings establish expensive recurrence. They do not establish a 100× opportunity. Sell first to SaaS integration vendors repeatedly doing reconciliation, pagination, schema mapping and evidence collection: their gross margin deteriorates when a model re-plans a known connector on every invocation.

**Mechanism — I:** collect a tool-boundary trace and candidate task family; infer typed parameters, branches and read dependencies; emit a restricted effect-aware program. Separate mechanical work from genuinely new semantic decisions. Begin with structured APIs, not pixel-coordinate browser macros. Guard schema, connector version, pagination and freshness assumptions; fall back on changes. Hash the resulting source/runtime contract. Run on Workers or Wasm; use scriptc for compatible native hosts only if CPU profiling justifies it. A trace is evidence for synthesis, not a proof that every future input follows the observed branch.

**Superhuman-model test — I:** matters more if better models can discover larger reusable procedures and open more automated workflows. It loses standalone value if those models already create, maintain and retrieve the same programs through normal tools. Defensibility would be installed connector coverage, operational reuse data and distribution, not clever prompting or proprietary ownership of generated code.

**2030 shape — E:** a service inside an agent platform builds **100,000** tenant/version-specific procedure families serving **100 million jobs/day**; telemetry records fresh inference calls, reuse and invalidations. These are design-scale assumptions, not market forecasts. Inference hosts see discovery and misses; edge CPUs see executions; brokers see real tool effects.

**Lineage — F/I:** [Futamura's partial evaluation, 1971](https://fi.ftmr.info/PE-Museum/PE-Original-English1971.pdf), specializes an interpreter with respect to fixed inputs. **I:** the analogy is residualizing stable behavior; an LLM is not automatically a formally specified interpreter being partially evaluated. Specialization succeeded inside compilers but did not turn arbitrary changing workflows into robust programs. Better synthesis plus typed tools and versioned observations make a narrower transfer plausible. **F:** ReUseIt, **2025-10-16; v2 2026-01-24**, already synthesizes guarded reusable web workflows; AWM, **ICML 2025**, already induces reusable routines. [ReUseIt](https://arxiv.org/abs/2510.14308v2), [AWM](https://proceedings.mlr.press/v267/wang25bx.html). “We invented learning workflows from traces” is unavailable.

**Value — I:** charge for operating and updating reusable procedures or a share of demonstrated avoided spend. Buyers retain downloadable programs; otherwise an ordinary automation platform is an easier purchase. The differentiating promise is an automatic transition from agent discovery to low-cost production execution.

**First proof — E, 1–2 weeks:** select **three** recurring API workflows; freeze **30** discovery cases and **300** later cases with unseen parameters, empty pages, retries and a schema change. Use real model calls to discover programs; replay tools for controlled comparisons, then a small real read-only cohort. Compare fresh agent, prompt-cached agent, local APC-style templates, Code Mode, and a handwritten implementation. Report total paid calls, dollars, wall time, success, stale outputs, CPU and compilation cost. Target **100× fewer model calls on admitted stable cases**, **10× lower total pilot cost**, and explicitly measure the repeat volume needed for 100× after amortization. A pilot target is not a production guarantee.

**Demo + draft tweet — I:** show the first task being reasoned through, the emitted program, then fresh inputs executing with the inference meter flat; force an interface change and show fallback. “Let the agent discover the procedure once. Export the TypeScript and run fresh inputs on CPUs; call the model again when assumptions change. Our benchmark counts compilation, misses and ordinary-code baselines.”

**Kill test — E:** stop the infrastructure bet if routine family discovery needs ongoing human rewriting, unseen-input success drops by more than **one percentage point** versus the best agent baseline, or projected break-even repeat volume exceeds the buyer's observed stable-version volume. If handwritten code wins and users value the generated code, ship a synthesis tool rather than a perpetual runtime.

### 2. A reasoning CDN: distribute reusable procedures, not universal cached answers

**One sentence + 100× — I:** operate a network where agents fetch compatible public reasoning artifacts and tool-plan programs before generating their own. **100×:** the thousandth organization configuring the same public API reuses a maintained procedure at the edge rather than financing another independent discovery. This applies the CDN's amortization and distribution pattern to useful computational work.

**Worsening problem / payer — F/I:** D1's approximately **330×** token-volume increase and APC's measured plan reuse motivate the search, but there is no measured cross-company duplicate fraction. Infrastructure platforms and API vendors pay when repeated integration/planning costs or first-task latency limit adoption.

**Mechanism — I:** public artifacts contain a typed plan, executable subroutines, connector/schema versions, required capabilities, dependency manifests and provenance. Private inputs remain tenant-local. R2 holds immutable content-addressed packages; Workers cache and match them; a Durable Object coordinates one in-flight build per artifact key. Semantic retrieval locates candidates; a cheap deterministic compatibility check admits one or misses. Refresh live data on execution. Namespace private artifacts; do not make one tenant's context discoverable through another tenant's cache lookup. Meter misses and the work spent finding a hit.

**Superhuman-model test — I:** stronger models improve artifacts and expand the procedures worth sharing. If deriving a plan becomes cheaper than lookup plus maintenance, the CDN vanishes for that plan. It can remain valuable for connector compatibility, large generated modules and expensive discovery, even with perfect reasoning. A plain package registry is a serious substitute.

**2030 shape — E:** an API platform publishes **one million** public/versioned artifacts consumed by **10,000** organizations; most requests reuse programs, while a controlled origin produces new versions. Scope excludes a global repository of private chain-of-thought text. Hit rate is a measured outcome, not a design assumption.

**Lineage — F/I:** [Michie's memo functions, 1968](https://www.nature.com/articles/218019a0), reused previous computation. [HTTP caching, RFC 9111, June 2022](https://www.rfc-editor.org/rfc/rfc9111.html), supplies freshness, variants and invalidation concepts. **I:** caches succeeded for stable, addressable representations; arbitrary agent questions lacked stable equivalence and dependency declarations. Typed plans offer a more cacheable object than personalized answers. Global distribution is new proposed scope; memoization and APC are not new.

**Value — I:** API vendors sponsor official artifacts and freshness; agent platforms buy delivery, compatibility and avoided discovery. A claim to skim every cache hit is weaker than becoming the maintained distribution path for an API's executable integration knowledge.

**First proof — E, 1–2 weeks:** publish **20** procedures for public read-only APIs in a Worker/R2 registry. Evaluate **200** later requests authored independently from the discovery set, across held-out parameter combinations and connector versions. Compare a local skill directory, public documentation search, APC-style templates and fresh generation. Record accepted-hit fraction, wrong-hit fraction, lookup tokens, maintenance effort and end-to-end dollars. Target **5×** lower first-task planning cost after amortization before claiming a network effect.

**Demo + draft tweet — I:** a second fresh agent fetches the first agent's artifact, binds different public inputs, and executes without recreating the plan; an obsolete version misses. “A cache for reusable agent procedures. Fresh inputs and permissions stay local; versioned plans travel. Similarity finds candidates, explicit preconditions admit them. The question is whether independent users reuse enough to beat local skills.”

**Kill test — E:** demote to a registry feature if **under 20%** of held-out requests admit artifacts after exact preconditions, or if compatibility/refresh cost consumes the saved inference. Any private-context cross-tenant disclosure kills the proposed sharing boundary. Do not rescue poor hits by relabeling vaguely related advice as reuse.

### 3. Agent make: content-addressed, incremental execution of agent work

**One sentence + 100× — I:** turn an agent's work into a dependency graph whose unchanged nodes do not rerun. **100×:** a continuously updated analysis, repository investigation or account reconciliation computes only the affected frontier, even when the user asks a new question or fresh data arrives.

**Worsening problem / payer — F/I:** PEEK's **1.7–5.8×** benchmark-relative cost savings and D3's roughly **4×** prompt growth expose recurring work over persistent material. Buyers are research, coding and enterprise-agent platforms that repeatedly reopen substantially the same world. The problem is broader than identical prompts: changed questions often share extraction, normalization and tool subplans.

**Mechanism — I:** a node key includes canonical inputs, program/model version and configuration, tool schema, tenant/authorization scope, environment assumptions and dependency digests. Tool adapters expose ETags, commits, snapshot IDs or explicit freshness deadlines. A read of “latest” must revalidate; undeclared dependencies make the node non-cacheable. Model-output nodes may reuse a previously accepted artifact under a declared policy without claiming that a rerun is bit-identical. Clock/randomness are explicit inputs. Effects get a distinct intent/receipt ledger; a previous successful payment is never a reusable instruction to pay again. R2 stores values; DO/SQLite stores graph metadata and invalidation state.

**Superhuman-model test — I:** matters even for flawless models because the unchanged input/work relationship is physical. Stronger models may synthesize better dependency decompositions. It disappears as a separate product if existing build/data/workflow systems can express the task with equal developer effort. Start where dependencies are instrumentable, not arbitrary web research with invisible environmental state.

**2030 shape — E:** an organization's graph holds **100 million** reusable nodes; each incoming document or commit invalidates only dependent results. Agents submit work descriptions to that graph instead of starting isolated transcripts. Different task owners reuse scoped immutable artifacts without sharing credentials or human approvals.

**Lineage — F/I:** [Acar's self-adjusting computation thesis, May 2005](https://www.cs.cmu.edu/~rwh/students/acar.pdf), and [Build Systems à la Carte, September 2018](https://www.microsoft.com/en-us/research/publication/build-systems-la-carte/), provide change propagation, dynamic dependencies and the scheduler/rebuilder separation. **I:** these ideas succeeded where dependencies could be tracked; unconstrained agent tools and mutable external sources defeated hermeticity. Tool-only boundaries and versioned data make a bounded agent build graph feasible. Content hashes identify disclosed dependencies; they do not prove dependency completeness.

**Value — I:** sell lower repeated-job cost, rapid refresh and explainable invalidation, priced per maintained graph or completed job. The long-term asset is the accumulated dependency structure, not a proprietary transcript format.

**First proof — E, 1–2 weeks:** build a TypeScript engine over **100** versioned documents plus a fixture repository. Run **100** related tasks, mutate selected sources, then compare full rerun, answer cache, workflow step cache and dependency-graph reuse. Include permission revocation, connector changes and a new document that changes a previously empty search result. Aim for **100× fewer expensive node evaluations when 99% of the relevant expensive frontier is unchanged**; report graph overhead and the actual total-cost ratio rather than equating these metrics.

**Demo + draft tweet — I:** change a source and highlight the affected nodes; unrelated extraction stays cached, a dependent conclusion reruns. “Make, for agent work: content-address inputs, record dependencies, recompute what changed. We show hits, invalidations and fresh reads. A similar question is not a cache key; a payment receipt is not permission to pay twice.”

**Kill test — E:** stop on any silent stale answer under the declared dependency/freshness contract, or if conservative revalidation plus graph maintenance saves less than **2×** over conventional workflow caching on the target workload. If exactness requires hashing the entire mutable world before every lookup, the domain is wrong.

### 4. Context once: maintain an executable map of a recurring world

**One sentence + 100× — I:** keep a versioned index of what an agent already learned about a repository or corpus, and expose small query functions instead of repeatedly loading the world. **100×:** thousands of agents operating on one evolving codebase share reusable orientation and CPU-side queries; large models see only the facts needed for a new decision.

**Worsening problem / payer — F/I:** D3's prompts grew from roughly **1.5K to over 6K tokens**. PEEK already demonstrates context-map reuse; Cursor's **2026-09-23** work reduced cold cache misses **20%** and total token costs **7%**. Those are substantial existing baselines, not evidence of an empty market. Coding platforms and enterprise-search operators pay to reduce repeated exploration and prefix failures. [Cursor](https://cursor.com/blog/improved-token-efficiency).

**Mechanism — I:** combine three layers with separate accounting: immutable source objects; maintained maps/indexes/query programs with source spans and dependency digests; provider-specific prompt-prefix caching. Store facts such as module ownership, API schemas and discovered entry points with invalidation rules. CPU code executes search/filter/join; fetch raw source when the map cannot answer. Stable prompt ordering improves cacheability. Do not claim provider-independent KV tensors: reuse depends on exact model/runtime/cache semantics, while source-derived maps can be portable.

**E — Why transcripts inflate:** an assumed **50-turn** run with **10,000** fixed tokens and **1,000** new history tokens per turn sends `50*10,000 + 1,000*50*49/2 = 1,725,000` input-token appearances. Prompt caching can remove much of the repeated prefill cost; the count alone is not 1.725 million fresh-token computations. Maps target repeated exploration and unnecessary attention as well as cache misses.

**Superhuman-model test — I:** better understanding does not remove the bytes that must be read to acquire private, changing information. But a much better model may orient in one cheap query, eroding the map's value. The durable portion is maintaining indexes/functions and coordinating many consumers over the same versioned context; a summary prompt alone is readily absorbed.

**2030 shape — E:** one large repository serves **10,000** concurrent agent tasks through a shared context service; maps update on commits, while each provider adapter manages its own prefixes. Source/authorization versions bound sharing. The product is the context data plane, not a claim to merge different agents' hidden neural states.

**Lineage — F/I:** [Gupta and Mumick, materialized views, June 1995](https://homepages.inf.ed.ac.uk/wenfei/qsx/reading/gupta95maintenance.pdf), describes maintaining derived results as base data changes. **I:** DB indexes succeeded because the query/update language exposed dependencies; free-form semantic orientation and model-specific KV reuse did not have the same contract. Typed context maps plus source attribution provide a narrower contract. PEEK already occupies learned orientation caching; differentiation requires useful maintenance, query execution and shared deployment.

**Value — I:** repository/corpus owners pay for faster onboarding and cheaper repeated analysis across models, with access control and freshness attached. A token-discount reseller alone has weak margins and no stable moat.

**First proof — E, 1–2 weeks:** **50** independent questions over a real TypeScript repository, then a held-out changed revision; compare `rg`/symbol search, good native agent memory, exact prefix caching and a PEEK-style map. Count source bytes inspected, fresh/cached inputs, generated tokens, stale facts and total cost. Target **10×** lower orientation cost, with a separately reported **100×** target for repeated map-answerable lookups; do not advertise the latter as whole-task savings.

**Demo + draft tweet — I:** the second agent uses the map to reach a non-obvious entry point, a commit invalidates the relevant map record, and the next answer refreshes it. “Agents keep reopening the same repository. We maintain source-linked context maps and executable queries across runs, then measure against native memory and prompt caching. The useful artifact survives a chat; the facts still expire.”

**Kill test — E:** reject the independent platform if maintaining the map costs more than the saved exploration, if stale-map errors exceed the full-source baseline, or if the best conventional search-plus-memory baseline comes within **20%** of its total cost and latency. Better retrieval packaged as a short summary is not a 100× business.

### 5. Yield the accelerator: park orchestration and lease KV residency separately

**One sentence + 100× — I:** let an agent explicitly yield while tools run, park its application continuation cheaply, and tell a cooperating inference host when KV residency is worth retaining. **100×:** millions of pending agents exist as stored state and resumable work descriptions, while accelerator memory serves currently runnable work.

**Worsening problem / payer — F/I:** D5 establishes hours/week-scale orchestration; TokenCake's **16.9-point** utilization improvement and Continuum's **over 8×** job-completion result show that tool timing and KV scheduling can matter. The buyer for GPU savings is a model host/self-hosted inference operator; the buyer for parked application memory is an agent/sandbox platform. These are different sales.

**Mechanism — I:** a tool-only guest reaches a quiescent boundary; snapshot its compatible QuickJS/Wasm state or store explicit state; journal pending operation IDs externally. Use `yield(expected_wait, deadline, resume_key)` at the model gateway. A cooperating host chooses retain/offload/evict/re-prefill based on measured reload cost, predicted return and queue pressure; long waits go to cheaper memory/storage. Reserve no logical “one GPU per agent.” On completion, the broker wakes one owner and rebinds current capability grants. A capsule preserves application state, not a remote model's hidden chain of thought, GPU kernel, socket or KV cache.

**Superhuman-model test — I:** faster inference makes external waits a larger relative bottleneck; more long-lived tasks create more parked state. However, hosted APIs already multiplex calls, and ordinary durable workflows may park everything important. The idea matters only if a cross-layer yield signal improves real scheduling or a capsule materially reduces reconstruction work.

**2030 shape — E:** **10 million** mostly dormant agents, **0.1%** runnable at a time, imply **10,000** active application continuations in this scenario. GPU concurrency is determined separately by batched inference. Storage/wake rates, image sizes and KV reloads all need explicit budgets; sleeping population is not throughput.

**Lineage — F/I:** [Scheduler Activations, SOSP October 1991 / TOCS February 1992](https://homes.cs.washington.edu/~tom/pubs/sched_act.html), connected application scheduling knowledge to kernel resource allocation. **I:** the modern analogue links the tool runtime's waiting knowledge to the inference scheduler. Cross-layer cooperation is the obstacle. **F-local:** [the capsule landscape](../v8/02-landscape.md) documents Vercel quickjs-wasi/Workflow snapshots, LangChain quickjs-rs, Golem, and VM hibernation substitutes. Snapshotting an await is occupied territory; use an existing engine for the first proof.

**Value — I:** sell lower HBM occupancy and better completed jobs per accelerator-hour to inference operators; separately sell application parking/recovery. Without a serving-host integration, promise application-resource savings only. A JavaScript image cannot substantiate an accelerator-savings invoice.

**First proof — E, 1–2 weeks:** implement a Worker/DO/R2 continuation broker with **1,000** synthetic waiting sessions and an explicit-state baseline. Separately add a yield/return hint to a locally controllable serving adapter if hardware is available; otherwise label the GPU section unproven. Compare retain, evict, timed lease and tool-completion notification under bursty waits. Measure application RAM, KV byte-seconds, queue delay, recomputation and actual jobs/hour. Target **100× lower resident application memory for long sleepers** and **2×** serving improvement in an adverse workload; neither implies 100× GPU savings.

**Demo + draft tweet — I:** pending agents become files while a small runnable pool progresses; display separate application-RAM and GPU-KV meters. “A sleeping agent should not reserve a machine. Our tool runtime yields, parks application state and tells a cooperating model host when it will return. GPU savings require the host adapter; the capsule alone doesn't provide them.”

**Kill test — E:** drop the capsule-specific component if explicit JSON plus durable replay wins total cost/recovery time. Drop the accelerator product if modern serving baselines plus lease hints improve useful throughput by less than **20%**, or if offload/reload costs erase saved residency. Do not count lower application RAM as higher GPU utilization.

### 6. The agent query compiler: put loops and data near tools, collapse round-trips

**One sentence + 100× — I:** compile one model-produced tool plan into a typed DAG with CPU-side loops, joins, reductions and execution near the data. **100×:** a task involving a million records has a bounded number of model decisions; records and intermediate blobs never become a million model turns.

**Worsening problem / payer — F/I:** Anthropic's **150K→2K** tool-context example and LLMCompiler's **up to 3.7×/6.7×** latency/cost results show existing value. D5's **10 million tool calls/week** illustrates potential load, not how many were avoidable. Enterprise integration vendors and API owners pay for fewer model transitions, less data movement and fewer origin requests.

**Mechanism — I:** model emits a plan/program; the runtime resolves dependencies, runs independent reads concurrently, pushes filters/reductions to the data owner, and returns only decision-relevant results. Workers perform glue; Wasm/scriptc accelerate compatible CPU-heavy transforms when needed. A Worker adjacent to the user is not automatically adjacent to the database: compare regional placement and server-side query execution. Typed bulk APIs can reduce origin call count; concurrency alone cannot. Co-locate the deterministic phase, rather than attempting frontier-model inference on arbitrary edge CPUs.

**E — Critical-path arithmetic:** **100** otherwise unnecessary serial control round-trips at an assumed **100 ms** each add **10 seconds** before tool execution. Fusing them to one adds **0.1 seconds**: **100× less control RTT**, not 100× faster total work. If each step truly needs the preceding observation, that fusion is invalid. Network/tool/model time must be separated.

**Superhuman-model test — I:** matters more as decision generation accelerates and data movement dominates. A better model makes DAG generation and query pushdown easier; it cannot send fewer bytes without some representation of the computation. But **Code Mode already offers the central mechanism**, so the product needs cost-based placement, bulk connectors and cross-run operational reuse beyond a generic executor.

**2030 shape — E:** a gateway processes **one million** daily analytical/integration jobs, each ranging from a few records to millions; typed subqueries run at participating data owners and compact evidence reaches the model. Cloudflare supplies distribution and isolation, not permission to move private data between arbitrary regions.

**Lineage — F/I:** [Selinger et al., System R access-path selection, May 1979](https://people.eecs.berkeley.edu/~brewer/cs262/3-selinger79.pdf), separated declarative requests from optimized execution. **I:** query optimization succeeded under known relational semantics; arbitrary APIs hide selectivity, rate limits and side effects. Typed connectors and observed costs make a limited agent query optimizer plausible. **F:** Cloudflare's [Code Mode, 2025-09-26](https://blog.cloudflare.com/code-mode/), and LLMCompiler are direct modern prior art, not just distant analogies.

**Value — I:** charge for completed integration jobs and bulk connector execution, or sell to API owners who want fewer chatty agents hammering their origins. The CPU path should be exportable; the maintained connector/cost catalog is the harder asset to reproduce.

**First proof — E, 1–2 weeks:** build a cross-service inventory report with pagination and independent lookups. Compare ordinary tool loop, current Code Mode, one regional Worker, and a data-side query. Use **100** jobs with actual request traces; inject latency only as a separately labeled controlled experiment. Measure origin calls, bytes moved, inference transitions, CPU, wall time and rate-limit failures. Target **100× fewer model/tool control transitions on a mechanical loop**, and at least **2×** total benefit over Code Mode through placement or pushdown.

**Demo + draft tweet — I:** show identical final output and a request waterfall collapsing; display the origin-call count so concurrency cannot masquerade as less traffic. “The model describes the job. CPUs run the loops beside the data. We compare with Code Mode and count bytes, origin calls and full wall time—not just how many chat bubbles disappeared.”

**Kill test — E:** demote to an implementation feature if optimized Code Mode plus ordinary server-side queries is within **20%** of total cost/latency. Stop any transformation that breaks tool dependencies or rate limits. “Replace an LLM loop with `for`” is valuable behavior, but not by itself a new platform.

### 7. Deadline-aware agent capacity: buy flexibility, not just cheap electricity

**One sentence + 100× — I:** separate an agent's “must finish by” deadline from “run immediately,” then dispatch compatible work when compute and energy are available. **100×:** a large population of parked agents becomes a dispatchable demand resource, allowing more useful work on a constrained grid connection. This is a capacity ambition; **100× cheaper inference from energy arbitrage alone is not credible**.

**Worsening problem / payer — F/I:** D9's **485→950 TWh** central trajectory makes access to power consequential. Germany recorded **573 negative-price hours in 2025**, versus **457 in 2024**, with a **€89.32/MWh** annual average, per the regulator's **2026-01-05** release. **E:** 573/8,760 is about **6.5%** of the year. [Bundesnetzagentur](https://www.bundesnetzagentur.de/SharedDocs/Pressemitteilungen/DE/2026/20260105_Smard.html). Negative wholesale prices are neither free delivered electricity nor evidence of low marginal carbon everywhere.

**Mechanism — I:** jobs declare deadline, pause/resume boundaries, allowed regions, data residency, model/runtime compatibility and maximum restart cost. A scheduler uses capacity bids, tariffs and separate carbon forecasts; queue in DOs, keep artifacts in R2, wake at stable boundaries. Actual inference must run on a controllable fleet or an exposed flexible-price product. Workers alone do not let an application select the electricity source of a remote commercial model API. Include model loading, KV reconstruction, transfer charges and deadline uncertainty in every placement decision.

**Superhuman-model test — I:** improved models enlarge the batchable workload pool and may make agent jobs shorter, easier to pack and more valuable. Physical grid constraints remain. Conversely, if inference becomes a negligible part of total spending, or customers pay for immediate response, flexibility has little application-level value. The best buyer is a capacity-constrained operator, not every agent user.

**2030 shape — E:** a model host offers **100 MW** of enrolled flexible capacity whose jobs have explicit completion windows. **100×** means a narrow operator might support a much larger population of mostly dormant logical agents per fixed power allocation; it is not a claim to manufacture 100× more GPU-seconds from the same energy. Utilities buy curtailment; customers buy cheaper deadline-bound outcomes.

**Lineage — F/I:** [Liu and Layland, deadline scheduling, January 1973](https://cse.unl.edu/~goddard/Courses/RealTimeSystems/Lectures/LiuLayland73.pdf), supplies a scheduling lineage, not a theorem covering uncertain multi-resource agents. **F:** Google announced ML-workload demand-response agreements on **2025-08-04**. [Google](https://blog.google/inside-google/infrastructure/how-were-making-data-centers-more-flexible-to-benefit-power-grids/). **I:** scheduling did not stall; access to contracts, controllable placement, checkpoint semantics and jobs with slack limited who could exploit it. This idea must earn distribution where hyperscalers already have strong capabilities.

**E — Economic ceiling:** if electricity is an assumed **10%** of all-in job cost and scheduling cuts that component **50%**, total savings are **5%**, not 50%. If delay lowers accelerator utilization or increases model reloads, total cost can rise. More promising value is a grid-access/demand-response contract or using otherwise stranded capacity; measure that independently of a carbon claim.

**Value — I:** sell a deadline-bound execution tier and load-flexibility service to inference operators/utilities. Price/carbon objectives can conflict; publish which was optimized and whether carbon uses average or marginal intensity. A transfer is beneficial only if net compute, transfer and restart effects improve the chosen objective.

**First proof — E, 1–2 weeks:** replay **one month** of published price/carbon traces against a queue of **1,000** checkpointable TypeScript jobs with declared deadlines. Compare immediate dispatch, cheapest-window placement and deadline-aware scheduling. Measure actual CPU work locally, simulate accelerator/energy rates explicitly, then seek one operator's tariff and flexibility constraints. Target **20%** modeled reduction in the controllable energy component with no test deadline misses; do not label this measured GPU savings.

**Demo + draft tweet — I:** move a job's deadline and watch its scheduled window and full cost change; show a case where moving is rejected. “Some agent work can finish tomorrow. We schedule it around capacity and energy, counting restart and transfer cost. Wholesale price isn't the cloud bill, and energy savings aren't total-cost savings. The first customer needs real flexible capacity.”

**Kill test — E:** no standalone business if customers lack meaningful slack, the host exposes no usable pricing/capacity lever, or obtainable total economic value is below **10%** after operational costs and there is no contracted capacity payment. Rank low until an operator supplies real economics.

### 8. Speculate on reads: start likely tools before the model asks

**One sentence + 100× — I:** use recurring plans and in-flight intent to prefetch likely read-only observations, then accept a result only when the committed request and dependencies match. **100×:** eliminate most exposed tool waiting in extremely repetitive pipelines, while bounding extra work. This is primarily a latency bet; speculation can increase compute and origin load.

**Worsening problem / payer — F/I:** PASTE **v3, 2026-06-16**, already reports **43.5% lower average task time**. TomasuLLM **v2, 2026-10-01**, reports **1.31×** on its SWE-bench cohort and **1.35×** on its Terminal-Bench cohort. [PASTE](https://arxiv.org/abs/2603.18897v3), [TomasuLLM](https://arxiv.org/abs/2609.38201v2). As inference gets faster, these exposed observation stalls consume more of the critical path. Interactive agent platforms pay for shorter response times, not an unsubstantiated lower FLOP count.

**Mechanism — I:** consult a learned/stored plan to propose likely reads; run a small bounded lookahead on Workers or an isolated capsule branch. Key results by canonical request, version and authorization scope. Hold results until the actual chosen call matches; discard on divergence. Cancellation is best-effort and still costs money. No speculative payments, external messages or irreversible writes; even reads can incur fees and rate limits, so require connector-specific budgets. Deeper speculative chains require valid predicted observations, not just plausible next tool names.

**Superhuman-model test — I:** faster generation increases the relative latency of tools, while better prediction may raise speculation hit rates. It vanishes where the optimal program already batches independent reads or where genuine novelty dominates. An extra general-model call to predict the next general-model call may be an expensive regression; prefer reusable plans and cheap predictors.

**2030 shape — E:** an interactive platform runs **one million** simultaneous sessions with a declared maximum of **two** additional reads per admitted decision. The important operational metric is useful milliseconds hidden per extra dollar/request, with per-origin congestion feedback. Without those bounds a “faster” agent becomes an API denial-of-service generator.

**Lineage — F/I:** [Tomasulo, January 1967](https://courses.grainger.illinois.edu/ece511/fa2005/papers/Tomasulo.1967.IBMJRD.pdf), exploited independent operations while preserving dependencies. **I:** modern speculative/out-of-order systems add validation and delayed visibility; the old paper is not a proof of safe speculative web effects. Unlike registers, external systems do not generally roll back. Tool journals, scoped read contracts and isolated continuations make a limited agent version practical. PASTE and TomasuLLM already occupy much of this exact terrain.

**E — Ceiling:** if tool stalls are an assumed **80%** of total latency, removing all of them yields at most **5×** total speedup. A 100× total speedup requires over **99%** removable latency before overhead. Use “100× less exposed waiting on a narrow pipeline” only if that component is measured. Every discarded prediction belongs in the cost ledger.

**Value — I:** sell a lower-latency execution tier or integrate into the plan/CDN runtime. It is a weaker standalone compute-saving product than eliminating the repeated reasoning itself.

**First proof — E, 1–2 weeks:** use **200** held-out read-only workflows with a fixed **two-read** speculation budget, then inject variable latency and failures. Compare current parallel tool calling, Code Mode, simple prefetch and plan-driven speculation. Record p50/p95 latency, useful-hit rate, discarded requests, extra dollars, origin load and final-output equivalence. Aim for **2×** p95 latency improvement within **10%** added spend on a tool-dominated cohort; report misses and workloads that slow down.

**Demo + draft tweet — I:** a tool result is ready when selected; force a wrong prediction and display its discarded cost. “Prefetch for agents, with a visible waste meter. We run likely reads early and use them only when the real request and dependencies match. The benchmark counts extra API calls. Faster isn't automatically cheaper.”

**Kill test — E:** stop if it cannot beat ordinary batching/prefetch within the added-spend budget, if speculation materially worsens origin throttling, or if any stale/mismatched observation is accepted. No credit for making the happy-path animation faster while slowing concurrent sessions.

## 4. Execution priorities and the evidence that would change them

**I — Shared first artifact:** an instrumented tool gateway with dependency/receipt IDs and a per-job cost ledger. Use it to discover where a real buyer repeats work. Add the smallest necessary compiler/cache afterward. Start with one structured recurring integration family; avoid building eight services. The same artifact can distinguish compilation (#1), cross-user distribution (#2), exact incremental reuse (#3), context amortization (#4), waiting (#5), execution placement (#6) and speculation (#8).

**E — Proposed evaluation discipline:** freeze discovery and later evaluation sets; include version changes, zero-result searches, changing authorization, time-dependent reads and rate limits. Compare the strongest current model/harness, prompt caching, ordinary deterministic code, simple skill files, workflow engines and Code Mode as applicable. Use a fixed output contract and independently authored checks; even with a perfect-model assumption, operational equivalence and freshness still need observation. Report all attempted synthesis and maintenance cost. A cache warmed using the final test set is not evidence of generalization.

**I — Capsule decision is separate from product decision:** use snapshots only when the retained intermediate application state saves meaningful reconstruction or makes useful branching possible. For stable compiled routines, source plus inputs is usually the natural export. For dependency reuse, a Merkle graph may suffice. For sleeping orchestration, explicit state or a durable workflow may win. The existing capsule landscape makes “small file,” “await survives” and “fork it twice” insufficient differentiation.

**I — Unanswered diligence, in priority order:** how much paid work repeats under sound preconditions; how long those preconditions remain stable; whether another tenant can reuse the procedure; what fraction of cost remains irreducible tools/data; whether a cheaper/better model or handwritten code changes the break-even point; whether the buyer will integrate an external runtime. These determine the business more directly than a token-growth chart.

## Ranked top 3

**I — Full ordering:** **1 Trace foundry; 2 Agent make; 3 Reasoning CDN; 4 Agent query compiler; 5 Context once; 6 Yield the accelerator; 7 Speculate on reads; 8 Deadline-aware capacity.** This is a product/research judgment, not a measured market score. #6 has strong systems evidence but needs an inference-host buyer. #8 may have large infrastructure value, but a small TypeScript team cannot manufacture energy-price exposure or grid contracts.

1. **Trace foundry (#1). I:** strongest path to a discontinuous reduction in recurring model execution. It monetizes better synthesis and produces a familiar artifact the buyer can inspect and run. The ruthless baseline is a handwritten function, followed by the agent autonomously writing and remembering that function. Win on getting ordinary recurring work into that state automatically, keeping it updated and charging less than the avoided work.
2. **Agent make (#3). I:** strongest accumulating systems asset: a graph of reusable work and explicit invalidations. It can make each new question cheaper without requiring identical text or globally shareable data. Start where source/tool versions exist. The principal risk is incomplete dependency tracking, followed by graph overhead and substitution by ordinary workflow/data tools.
3. **Reasoning CDN (#2). I:** largest distribution moonshot, closest to Cloudflare's original economic pattern. It can turn one successful discovery into many independent users' avoided work. Its missing premise is cross-tenant admissible reuse; prove that before buying global-cache complexity. Begin as distribution for trace-foundry outputs and incremental artifacts rather than a standalone universal “thought cache.”

## The ONE bet

**I — Build the trace foundry for recurring API work, with a small dependency-aware artifact store.** The first product promise is: **“Your agent discovers it once; the next million executions are programs.”** The first two-week proof must show changing inputs running without repeated inference, an incompatible change causing a visible miss, and total economics against prompt caching, Code Mode and ordinary code. Publish how much repetition is required for 100× after all costs, rather than claiming the pilot proves the global multiplier.

**I — Expansion path:** compiled procedures become nodes in Agent make; widely reusable public nodes become the reasoning CDN; placement and yield become operational optimizations underneath. Better models feed this system better reusable work. If model vendors bundle the compiler, the surviving business must be the maintained integrations, dependency graph and cross-model distribution—not possession of the synthesis prompt. If the recurrence study fails, kill the global 100× thesis while keeping any useful generated programs.
