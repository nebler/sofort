# Classic computer science becomes central again

Research date: **2026-10-27**. Lens: **classic CS when the expensive function is a model call or an entire agent run**.

**Labels:** **F** = sourced fact, including attributed author/vendor results; **M** = measurement made for this report; **I** = inference/proposal; **E** = estimate, illustrative scenario, or proposed experimental threshold. All web sources below were inspected on **2026-10-27**; publication dates are given alongside them. No customer interviews or production model benchmarks were conducted. The one local experiment uses deterministic surrogates, not inference.

## Thesis: make intelligence an amortisable resource

**I:** The best revival is **a build system for expensive cognition**: explicit inputs, reusable intermediate artifacts, dynamic dependencies, demand-driven updates, and a planner that chooses whether to retrieve, execute code, ask a tool, or invoke a model. Stronger models should manufacture more of this graph and compile repeated work out of it. The goal is to avoid doing the same useful work across revisions, agents, and organisations.

**I:** This differs from round one's acceptance thesis. Even a model that never makes a reasoning mistake cannot make yesterday's price current, remove network round trips, make independent budgets infinite, or prevent a million individually sensible agents from repeatedly computing the same thing. Conversely, cheaper inference can destroy a particular optimisation's economics. Jevons is a hypothesis about demand, not a guarantee of a business.

**F/I — Context read:** Round one's top bets included occupied-software upgrades, immune repair, failure search, notarised computation, temporary swarms, fault-grown Node, and Oracle Foundry. Their useful inherited assets are explicit tool boundaries, recorded observations, and reusable state. Their dependence on imperfect models is deliberately reduced here. The [capsule landscape](../v8/02-landscape.md) also establishes substantial existing snapshot/durability competition. **I:** use an existing engine or source-plus-journal execution; do not make a new snapshot format a prerequisite for any experiment below.

## What is demonstrably getting larger?

- **F — Inference volume:** Alphabet reported **over 1.3 quadrillion monthly tokens**, more than **20× year-on-year**, in its **2025-10-29** earnings remarks; July's figure had been 980 trillion. This is Google's reported aggregate across its surfaces, not a measure of autonomous agents or a current October 2026 run rate. [Alphabet primary statement](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q3-2025/).
- **F — Physical demand:** the IEA's **2026-04-16** update estimates data-centre electricity consumption of **485 TWh in 2025** and projects about **950 TWh in 2030**, with AI-focused data centres' demand tripling. These are all-data-centre totals and a scenario projection, not inference-only electricity measurements. [IEA executive summary](https://www.iea.org/reports/key-questions-on-energy-and-ai/executive-summary).
- **F — Origin pressure:** Cloudflare's **2025-08-29** analysis found AI/search crawl growth of **24% year-on-year in June**, slowing to **4% in July**; Anthropic's July crawl-to-referral ratio was about **38,000:1**. The ratio is not a redundant-request rate, and training crawlers are not interchangeable with interactive agents. It shows an existing machine-consumption burden, not an uninterrupted exponential trend. [Cloudflare data](https://blog.cloudflare.com/crawlers-click-ai-bots-training/).
- **F — Software volume:** GitHub's **2025-10-28** Octoverse report, updated **2026-02-28**, reports about **43.2 million merged PRs per month**, **23%** above the prior year's monthly average, and **1+ million coding-agent-created PRs between May and September 2025**. Total activity is not all agent-generated, and correlation does not establish AI caused the growth. [GitHub primary report](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/).

**I:** These facts motivate experiments; none establishes the reuse fraction, customer willingness to pay, or future agent population. All 2030 fleet sizes below are **E — design scenarios**, not forecasts. Buyers pay for actual saved dollars, quota, elapsed time, or maintenance obligations, not token-count theatre.

## The old ideas, translated precisely

| Lineage | What the expensive-function version becomes | Where it belongs |
| --- | --- | --- |
| Memoisation | Reuse an identified result for the same declared request and dependencies; separately represent requests for fresh samples. | #1 |
| Dynamic programming | Merge genuinely equivalent subproblems; retain useful plans per state/resource constraint. The whole relevant state must be represented. | #1, #2, #5 |
| Acar / Adapton / Salsa | Track dependencies between explicit reasoning artifacts and update demanded descendants after changes. No access to a model's private internal reasoning is assumed. | #1 |
| Build systems à la carte | Separate scheduling from deciding whether an operation must run. | #1, #5 |
| Bazel / Nix | Separate an action/request identity from content-addressed output identity; maintain dependency closures. | #1, #9 |
| Dataflow / spreadsheets | A live operational answer is a maintained graph of cells, with visible freshness and demand. | #3 |
| Datalog / deductive databases | Put reusable structured observations and derivation rules in a shared relation store, rather than rereading every transcript. | #3 |
| SAT / SMT / constraints | Solve global allocation and feasibility over agent-proposed candidates instead of negotiating every combination in prose. | #5 |
| Levin search / Solomonoff induction | Allocate bounded search across candidate programs using a computable prior; do not claim to implement universal induction. | #5, #6 |
| Kolmogorov complexity / MDL | Replace recurring deliberation with a small executable explanation plus explicit exceptions, judged on future tasks and total cost. | #6 |
| Belady / LRU / CDNs | Evict or replicate results according to future reuse, recomputation cost, size, freshness, and origin load. Belady is an offline bound. | #4 |
| System R / materialised views | Plan a task across models, tools, code, and previously computed relations; maintain expensive model-derived views. | #2 |
| Transactions / sagas | Own real effects, reservations, retries, and compensations independently of an agent's conversational state. | #7 |
| Paxos / Raft / CRDTs | Agree on ownership and commitments; merge only data with declared convergence semantics. They do not establish factual truth. | #8 |
| Garbage collection | Reclaim generated applications and their managed resources from explicit roots and dependency graphs. | #9 |
| Virtual memory / demand paging | Make durable information addressable and load a bounded working set through explicit retrieval operations. | #4 |
| OS schedulers | Schedule scarce inference, memory, tool quotas, deadlines, and cancellation across competing agent jobs. | #5 |
| End-to-end argument | The application defines acceptable reuse and completed effects; lower layers accelerate that contract. | Cross-cutting |
| Worse-is-better | Begin with a narrow, inspectable interface that agents can use reliably; grow scope only after measured savings. | Cross-cutting |

## 1. Thought builds: Salsa/Adapton for agent work

**One sentence / 100× — I:** Build and maintain expensive reasoning as a dependency graph, so an input change rebuilds only the demanded affected artifacts. The 100× version is a shared computation fabric: thousands of agents consume one maintained industry map, repository analysis, or supplier assessment rather than independently regenerating overlapping work.

**Worsening problem / numbers / payer — F/E/I:** Google's reported 20× token growth is evidence of expanding demand, not of a 20× reuse opportunity. Consider **1,000** agents each maintaining an identical **200-artifact** dossier: **200,000** initial artifact evaluations versus **200** shared ones in the ideal same-authority case, before overhead. That **1,000×** ceiling requires exact shared inputs, compatible output contracts, and actual demand. Enterprise agent-platform owners pay for fewer inference calls and origin reads as their task population grows.

**Lineage — F:** Michie's [“Memo” Functions and Machine Learning, 1968-04-06](https://www.nature.com/articles/218019a0) proposes learning efficiency through retained function results. [Acar's thesis, May 2005](https://www.cs.cmu.edu/~rwh/students/acar.pdf) develops dependence tracking and change propagation. [Adapton, PLDI 2014, author artifact and paper](https://www.cs.umd.edu/projects/PL/adapton/) adds demand-driven, composable reuse. [Salsa's current overview](https://salsa-rs.github.io/salsa/overview.html) explicitly assumes deterministic functions of tracked inputs. [Build systems à la carte, September 2018](https://www.microsoft.com/en-us/research/publication/build-systems-la-carte/) separates scheduler and rebuilder. These ideas succeeded in their domains; **I:** broad adoption is constrained by instrumentation, graph overhead, and dependence granularity. Model calls make the avoided operations much more expensive, but stochastic results and hidden context complicate equivalence.

**Mechanism / difference now — F/I:** [Bazel's remote-cache contract](https://bazel.build/versions/7.1.0/remote/caching?hl=en) distinguishes action hashes from a content-addressable output store. [Nix's content-addressing manual](https://nix.dev/manual/nix/2.28/store/store-object/content-address) distinguishes content-addressed and input-addressed objects; do not describe all Nix derivations as output-content-addressed. For agents, key the request by code/prompt/schema identity, model/deployment identity available from the provider, sampling contract, tenant/authority scope, and versioned dependency observations. Store the actual response as an immutable artifact. Reusing a recorded sample is valid only when the caller accepts that sample; an independently sampled answer gets a new invocation identity. A model alias or temperature zero does not guarantee reproducibility.

**I:** Track dependencies at explicit TS functions/tool reads/artifacts. A node that sees an entire transcript depends conservatively on the entire transcript. Do not infer that an omitted citation means an omitted dependency. Changed observations dirty downstream nodes; recompute on demand; exact canonical output equality permits early cutoff. A model revision is an input change, but refresh only requested views. Run effects through #7, outside memoisation.

**Superhuman-model test — I:** matters more if capable agents maintain many overlapping long-lived analyses. It weakens if a cheap one-shot model can redo the complete job faster than validating the graph. Even a perfect model benefits from already computed current observations; capability does not remove their acquisition cost.

**2030 scale — E:** an enterprise operator maintains **10 million** artifact nodes with mostly dormant consumers; public-data nodes can be shared across organisations only under an explicit publication/licensing contract. Workers serve requests, sharded Durable Objects coordinate per-graph revisions and in-flight work, and R2 stores immutable artifacts. There is no global strongly consistent graph or automatic cross-tenant cache.

**First proof, 1–2 weeks — E:** implement a TS `derive/read/observe` API for a repository impact dossier and a supplier dossier, with explicit versions and single-flight work per key. Compare fresh execution, whole-run caching, hand-written incremental code, and the graph on at least **30 held-out revisions** per task. Include broad changes, changed dependency sets, deleted inputs, model upgrades, and unchanged extracted outputs. Count total billed inference, reads, graph cost, latency, and stale results. A QuickJS capsule is optional for a long local prefix; begin with ordinary structured state.

**Demo + draft tweet — I:** edit one dependency; only its impact path lights up; a second agent consumes the updated result without a repeated call. “A build system for agent work. Change one input, rebuild its dependants, reuse the rest. Exact artifact identities and actual costs are visible. No claim to edit a model's hidden reasoning.”

**Kill test — E:** stop the platform pitch if it cannot halve total recurring cost against the best simple incremental baseline on a buyer's real workload, or if most changes invalidate nearly everything. Any silent reuse across an undeclared dependency falsifies the soundness claim. A hand-maintained DAG winning the experiment still supports the economics, but weakens the need for a general runtime.

## 2. System R for intelligence: materialised views over model calls

**One sentence / 100× — I:** Accept a declarative task and plan its execution across exact code, indexes, model calls, tools, and maintained model-derived relations. The 100× version is an intelligence database whose optimiser amortises expensive semantic operations across all queries, tenants where authorised, revisions, and providers.

**Worsening problem / numbers / payer — F/E:** the IEA's projected near-doubling of data-centre demand motivates reducing total work, including data movement. For **1 million** documents, a **1%** selective exact metadata predicate can reduce subsequent model extraction from **1 million to 10,000 calls**, a **100×** reduction for that stage. It is not a 100× end-to-end claim: scans, retrieval, joins, and less selective queries remain. Analytics and operational-data vendors pay for predictable query cost and latency.

**Lineage / occupied ground — F:** [Selinger et al., System R, 1979-05-30](https://research.ibm.com/publications/access-path-selection-in-a-relational-database-management-system) describes cost-based access-path selection; the [original paper](https://web.eecs.umich.edu/~michjc/eecs584/Papers/selinger_1979.pdf) uses dynamic programming to retain useful partial plans. [Gupta and Mumick, June 1995](https://homepages.inf.ed.ac.uk/wenfei/qsx/reading/gupta95maintenance.pdf) develops materialised-view maintenance. This did not stall: databases won. **I:** the boundary was expensive opaque functions with weak cost/selectivity estimates and uncertain semantics. Crucially, [Palimpzest, 2024-05-23](https://arxiv.org/abs/2405.14696) already optimises AI workloads across cost, time, and quality; [LOTUS, first submitted 2024-07-16, revised 2025-03-01](https://arxiv.org/abs/2407.11418) already supplies semantic relational operators. “SQL plus LLMs” is occupied.

**Mechanism / difference now — I:** maintain `EXPLAIN` output showing measured cardinalities, model-derived columns' provenance, freshness, expected expense, and shared in-flight work. Choose whether to materialise a relation from its expected future uses versus refresh/storage cost. Prioritise **cross-query and cross-revision reuse plus origin budgets**, rather than another prompt router. Preserve logical operator contracts: moving a model call past a filter, splitting a join, or changing its context can change the answer. Apply only justified transformations; approximate plans must expose their own contract. Join selectivity errors can erase all savings.

**Superhuman-model test — I:** stronger models make semantic operators more useful; they do not make a million unnecessary reads free. Model-quality routing may lose importance while locality, cardinality, batching, and materialisation matter more. If one provider owns the whole workload and automatically performs these optimisations, a separate planner loses value.

**2030 scale — E:** a data-platform vendor runs **billions of versioned document-derived rows** and thousands of concurrent queries over them; events refresh affected partitions. Workers handle ingress, a hosted query engine owns planning/execution, and R2 holds partitioned artifacts. Begin with an ordinary SQL engine and a TS controller; do not promise a general distributed database inside one Worker.

**First proof, 1–2 weeks — E:** use **10,000** public or synthetic supplier records and **20** overlapping queries. Implement only predicate pushdown where valid, one materialised extraction column, one cross-query reuse rule, and adaptive replanning. Compare hand-tuned execution and an available Palimpzest/LOTUS implementation. Use an independent task-specific answer set; count its experimental evaluation cost separately and include runtime sampling costs in every plan.

**Demo + draft tweet — I:** show two plans and the bill; query two reuses an existing view; updating one source refreshes its partition. “`EXPLAIN` for expensive semantic queries: which rows reached a model, which results already existed, and why the optimiser chose to compute anything. Building on System R, Palimpzest and LOTUS.”

**Kill test — E:** demote to a feature if net savings are below **20%** against a well-tuned existing engine at equal task outcomes and latency constraints. Do not build a new query language unless users need a missing execution contract.

## 3. A living spreadsheet of shared agent observations

**One sentence / 100× — I:** Replace repeated agent rereading and status meetings with continuously maintained, provenance-bearing facts and derivations. The 100× version is an organisation whose agents subscribe to changes in a common operational model, with expensive model calls only at unstructured-data boundaries.

**Worsening problem / numbers / payer — F/E/I:** Cloudflare already measures large machine-read burdens, although its crawl data does not measure this specific workflow. In a scenario with **1,000** agents polling the same **100** inputs hourly, there are **2.4 million reads/day**; one shared hourly observer issues **2,400**, before notifications and freshness exceptions. This **1,000×** read ceiling requires the same lawful view and freshness requirement. Integration owners and API providers pay for fewer reads and fewer conflicting summaries.

**Lineage — F:** [Dennis's dataflow language, 1974; revised MIT report May 1975](https://dspace.mit.edu/entities/publication/728d8925-9eb0-4cb5-911f-6d5cba4ea4c8) makes noninterfering computation concurrent. [Microsoft's Excel recalculation documentation](https://learn.microsoft.com/en-us/office/client-developer/excel/excel-recalculation) describes dependency trees, dirty cells, and calculation chains. [Ceri, Gottlob and Tanca, March 1989](https://www.dcc.fc.up.pt/~ines/aulas/1617/PL/WhatYouAlwaysWantedtoKnowAboutDatalog_AndNeverDaredtoAsk.pdf) explains Datalog and deductive databases. [Differential dataflow, January 2013](https://www.microsoft.com/en-us/research/publication/differential-dataflow/) supports incremental iterative computation. **I:** these did not fail; expensive knowledge engineering and unstructured input limited their reach. Better models can propose schemas, extract observations, and author rules, while ordinary engines maintain declared consequences cheaply.

**Mechanism — I:** distinguish `observed(source, version, value)` from `model_claim(model, input_hash, value)`. A claim becoming widely repeated does not become an observation. Record multiple supports and retract a consequence only when its support semantics require it. Positive finite-domain Datalog is a tractable starting point; negation, aggregates, changing facts, and external functions need explicit evaluation rules. A general model call is not a monotone delta operator. Avoid uncontrolled “rules that invent new entities forever.”

**F/I — Coordination boundary:** [Hellerstein and Alvaro's CALM account, 2020-08-21](https://doi.org/10.1145/3369736) connects monotonic computation with coordination-free implementations under its formal model. **I:** accumulating attributed evidence can often converge without global agreement; declaring an incident resolved, asserting no blocker exists, or allocating the final item cannot simply inherit that property.

**Superhuman-model test — I:** matters more as more capable agents interact with the same changing world. It disappears as a distinct product if ordinary databases, change-data-capture, and event subscriptions provide the same experience. Its opportunity is an application contract for expensive observations, not a generic knowledge graph.

**2030 scale — E:** a logistics or software-operations platform maintains **100 million** attributed observations for **100,000** agents. Tenant-scoped Workers expose queries/subscriptions; partitioned relation engines update derived facts; a DO owns each scarce-resource decision. Human users see a small spreadsheet of current conclusions and their source versions.

**First proof, 1–2 weeks — E:** make a release-readiness sheet for **20** services and **10** consumers. Model calls extract structured notes once per document version; TS/SQL or an existing Datalog engine computes dependencies, affected releases, and notifications. Compare independent agents, shared SQL plus events, and the richer system; include deletion, duplicate delivery, and contradictory claims.

**Demo + draft tweet — I:** change one upstream service fact; several plans update without ten agents opening the same document. “The spreadsheet formula can be a model call, but its result still needs an input version, an owner, and dependants. Shared observations replace repeated reading; rules maintain the consequences.”

**Kill test — E:** kill a standalone platform if ordinary SQL/events achieve the same reduction with less integration work. Require at least **10× fewer origin reads or model extractions** in the target multi-agent workload, with explicitly bounded freshness.

## 4. Demand paging for context, backed by a computation CDN

**One sentence / 100× — I:** Give long-lived agents an addressable external memory and a cost-aware working set, with reusable fetched and derived pages near consumers. The 100× version is a context hierarchy spanning device, edge, regional storage, and inference service, so long-lived memory need not be resent in full at every step.

**Worsening problem / numbers / payer — F/E:** Google's historical token-volume growth makes repeatedly presented context worth measuring. If **100** turns each resend **500,000** tokens, input totals **50 million tokens**; a **25,000-token** working set is **2.5 million**, before faults and summaries: a **20×** presentation reduction. Longer contexts and provider discounts change actual savings. Agent hosts pay for billed input, first-token latency, bandwidth, and memory pressure; origins benefit only if page fetching is also shared.

**Lineage — F:** [Belady, 1966](https://www.bitsavers.org/pdf/ibm/IBM_Systems_Journal/052/belady.pdf) compares replacement policies to a theoretical optimum; [Denning, May 1968](https://denninginstitute.com/pjd/PUBS/WSModel_1968.pdf) describes working sets. LRU uses recency as a practical locality heuristic. [Nygren, Sitaraman and Sun, July 2010](https://groups.cs.umass.edu/ramesh/wp-content/uploads/sites/3/2019/03/network_overview_osr.pdf) describes the Akamai delivery platform. [HTTP caching, RFC 9111, June 2022](https://datatracker.ietf.org/doc/html/rfc9111) supplies freshness/revalidation and request-collapsing semantics. **I:** byte caching succeeded; semantic relevance and heterogeneous recomputation costs are the new complications.

**F — Direct prior art:** [MemGPT, 2023-10-12](https://arxiv.org/abs/2310.08560) explicitly proposes virtual context management. [PagedAttention/vLLM, SOSP 2023-10-23](https://doi.org/10.1145/3600006.3613165) addresses KV-cache allocation/sharing, a different layer. [SGLang, December 2023; revised June 2024](https://arxiv.org/abs/2312.07104) combines LM-program execution with runtime optimisations including prefix reuse. None should be presented as a new invention here.

**Mechanism / difference now — I:** use content-addressed pages, stable identifiers, explicit fetch tools, versioned summaries, and a cheap index of what exists outside the window. Ordinary API models cannot transparently fault on an absent token like a CPU on an unmapped address: the model/controller must request a page. Keep semantic memory paging, exact prefix/KV reuse, result caching, and source revalidation as separate mechanisms. Score cache entries by estimated avoided cost and reuse probability per byte, adjusted for freshness and authorisation; measure against LRU. Belady's future knowledge is an offline evaluation bound under matching assumptions, not an online algorithm. A CDN cache hit proves neither truth nor currentness.

**Superhuman-model test — I:** better retrieval decisions help; larger windows can reduce the need. Memory bandwidth and repeated data movement remain, but a provider may internalise the whole optimisation. Build only if cross-provider or customer-owned memory produces a measured advantage.

**2030 scale — E:** an agent platform holds **10 million** resumable sessions, each with **10 MB** of external memory: **100 TB** before replicas/history. Most sessions are dormant. R2 stores pages, Workers expose capability-scoped fetches, and serving providers own their KV caches. Arbitrary KV transport between different model builds is not assumed.

**First proof, 1–2 weeks — E:** run **20** long tasks against a fixed document corpus; compare full-context plus provider caching, ordinary structured retrieval, MemGPT-style paging, and cost-aware eviction. Include a late question needing an evicted fact. Report actual billing, all extra model turns, fault latency, and task outcomes, not only reduced prompt length.

**Demo + draft tweet — I:** the working-set meter stays bounded while the agent fetches an old exact fact, with versions and total bill shown. “Context paging with explicit page faults and source versions. Compared with full context, retrieval and provider prompt caching. No claim that swapping a summary is lossless memory.”

**Kill test — E:** stop if it cannot halve actual recurring spend at comparable task outcomes, or if fault churn destroys latency. A better model doing full-context work more cheaply is a legitimate loss.

## 5. A scheduler for cognition, with solvers instead of agent meetings

**One sentence / 100× — I:** Schedule agent jobs over token budgets, deadlines, tool quotas, and shared reservations, while exact solvers choose feasible combinations of proposed actions. The 100× version is a multi-resource operating system for millions of intermittent agent jobs, including bounded search that stops when more thinking no longer buys useful work.

**Worsening problem / numbers / payer — F/E:** growing token demand meets the IEA's physical supply constraints. With **1,000** agents each generating **100** speculative branches, **100,000** branches compete before any useful work is established. Separately, **100** agents choosing one of **10** resource-consuming plans create **10^100** joint combinations; this is a search-space count, not a solver runtime prediction. Platform operators pay for bounded spend, fair service, quota compliance, and reduced deadline misses.

**Lineage — F:** [Bellman's dynamic programming, November 1954](https://www.ams.org/bull/1954-60-06/S0002-9904-1954-09848-8/S0002-9904-1954-09848-8.pdf) decomposes multistage decisions. [Corbató, Merwin-Daggett and Daley, 1962](https://cseweb.ucsd.edu/classes/wi19/cse221-a/papers/corbato62.pdf) describes time-sharing and scheduling for interactive use. [Davis–Logemann–Loveland, July 1962](https://web.stanford.edu/class/cs357/DPLL62.pdf) supplies a SAT-search ancestor; [de Moura and Bjørner's Z3, March 2008](https://www.microsoft.com/en-us/research/publication/z3-an-efficient-smt-solver/) handles combinations of logical theories. [Dominant Resource Fairness, March 2011](https://www.usenix.org/conference/nsdi11/dominant-resource-fairness-fair-allocation-multiple-resource-types) addresses multi-resource allocation. These fields succeeded; **I:** useful-work utility and good formal encodings were the bottleneck. Models can produce structured candidate plans; a solver handles the resulting finite resource problem without repeatedly narrating negotiations.

**F/I — Levin and Solomonoff, used honestly:** [Levin, 1973](https://www.mathnet.ru/eng/ppi914) supplies the universal-search lineage; [Solomonoff, March 1964](https://www.raysolomonoff.com/publications/1964pt1.pdf) assigns algorithmic priors to descriptions. His [2003 account, section 3](https://www.raysolomonoff.com/publications/kollect.pdf) explicitly addresses universal probability's incomputability. **I:** universal search's asymptotic comparison is not practical fleet optimality: program-dependent factors can be enormous. Use a finite candidate library, a computable prior, measured yields, bounded quanta, and checkpointed continuations. Learned priors are useful engineering choices, not universal guarantees. Only tasks with a cheap recognisable completion condition suit this search mode; it is not a universal answer evaluator.

**Mechanism — I:** models propose jobs/actions in a typed schema; constraints encode actual budgets, capacities, deadlines, precedence, and geography. Use SAT/SMT for feasibility/encoded optimisation; use a scheduling policy for online admission and fairness. Keep solver time bounded and compare ordinary greedy allocation. Reserve budgets atomically through #7/#8. An API request already generating tokens may not support true preemption; schedule at call/tool boundaries and measure cancellation waste.

**Superhuman-model test — I:** stronger agents still cannot allocate the same last unit twice or bypass independent quotas. The search-budgeter shrinks when one good call suffices; the resource scheduler persists. Exact solvers can outperform model-based combinatorial deliberation even when the model is an excellent proposer.

**2030 scale — E:** an enterprise platform admits **1 million** jobs/day with a small active frontier; Workers ingest jobs, sharded DO queues enforce grants, and bounded Wasm/native solvers plan batches. No global solver invocation per token and no assumption that Cloudflare exposes GPU-level preemption.

**First proof, 1–2 weeks — E:** build a TS queue with **1,000** replayable synthetic jobs and a small real API-call cohort. Compare FIFO, a simple fair scheduler, DRF-inspired allocation, and solver-assisted batches under tool quotas and cancellations. Separately compare finite prior-weighted search with uniform search and one strong model at equal budget. Report completed useful jobs/dollar, deadline misses, starvation, and wasted calls; do not combine simulation results with real billing.

**Demo + draft tweet — I:** start a fork storm; interactive jobs keep their deadlines, one shared budget remains conserved, and cancelled work stops at supported boundaries. “A scheduler for agent work: quotas and fairness are infrastructure, candidate plans are data, and a solver picks feasible combinations. Search is metered; a better one-shot answer is allowed to win.”

**Kill test — E:** kill the sophisticated policy if it cannot improve useful completed work per dollar or deadline misses by **20%** against a simple scheduler. Retain basic admission and budget accounting; do not sell a theorem about universal intelligence.

## 6. Compression is executable understanding: compile recurring thought into code

**One sentence / 100× — I:** Detect a repeated model-mediated operation and replace it with a small executable procedure plus explicit fallback conditions. The 100× version is a reasoning compiler that continuously converts stable portions of an organisation's agent traffic into ordinary cheap software as new patterns emerge.

**Worsening problem / numbers / payer — F/E:** Google's token growth supplies the demand signal; GitHub's coding-agent PR count shows automated code production is already material. If generation/integration costs an assumed **$100**, a model operation costs **$0.01**, and execution costs **$0.00001**, break-even is roughly **10,010 executions**; at a million executions, the assumed operating-cost ratio is **1,000×**, or about **91×** including the initial $100. These are hypothetical unit costs, not provider pricing or measured speedups. Integration and drift-maintenance costs must also be charged. High-volume API/automation operators pay for eliminating repeated inference entirely.

**Lineage — F:** [Kolmogorov, 1965, original journal record](https://www.mathnet.ru/eng/ppi68) defines algorithmic information; [Rissanen, 1978, author institution's record](https://research.ibm.com/publications/modeling-by-shortest-data-description) selects models through description length. Solomonoff's 1964 prior is the related induction lineage. **I:** “compression is understanding” is a useful heuristic, not a theorem that short text is true or sufficient. Kolmogorov complexity is uncomputable in general; shortest code can also run disastrously slowly. Operational MDL must charge program, shared libraries/model, exceptions, and residual data, then separately account for runtime and maintenance.

**Mechanism / why now — I:** choose bounded transformations: vendor identifier normalisation, structured log parsing, schema mapping, routing, repeated calculations. Mine traces, propose a parameterised TS program or decision table, expose its accepted input domain, and fall back outside it. Compile to Wasm/native where supported, or run in a constrained QuickJS capsule. Try scriptc for the supported TS subset; deployment portability is an experiment, not assumed. Shared procedures serve multiple compatible agents; versioned input contracts determine reuse.

**I — Historical limit / new difference:** hand-written expert rules and program synthesis struggled with specification, coverage, and drift; they were also often simply uneconomical to author for small niches. Better models lower synthesis and maintenance labour. The durable value is amortisation and the collected workload/contracts, rather than asserting that a generated program is a novel learning algorithm. Avoid producing a new microservice per example: a parameterised shared implementation is the compression.

**Superhuman-model test — I:** stronger models should discover more reusable algorithms, making this more valuable. If direct inference becomes cheaper than executing and maintaining the program, do not compile that operation. Perfect reasoning does not imply that repeatedly interpreting the same format is the cheapest computational representation.

**2030 scale — E:** a workflow vendor maintains **100,000** shared specialised operators serving **billions** of invocations/month. Most traffic uses code; changed or genuinely novel inputs invoke models. Workers distribute versions, R2 holds immutable programs and evidence, and jitk is an optional stronger isolation tier for untrusted generated code. #9 prevents the compiler from manufacturing an immortal software population.

**First proof, 1–2 weeks — E:** select **three** recurring transformations with a pre-existing authoritative specification, reference implementation, or independently prepared expected outputs. Generate on one split, run a frozen program on a temporal holdout, include malformed/new-version inputs, and measure fallbacks. Compare a strong batched/cached model, handwritten code, and the generated operator. Charge generation, evaluation, fallback inference, operation, and one simulated format migration. No need to assume models are unreliable to justify removing repeated calls; evaluation determines whether the replacement implements the agreed operation.

**Demo + draft tweet — I:** a stream initially invokes a model; after compiling a repeated operator, the call counter stops rising except for explicit novel cases. “We turned a repeated model operation into a small executable rule with an explicit input contract and fallback. Here are future-period outcomes, the compilation bill, and break-even. MDL as an engineering objective, not a claim to compute Kolmogorov complexity.”

**Kill test — E:** kill the compiler product if its best candidate cannot reach **10× total-cost improvement** over the strong cached/batched-model baseline at unchanged task requirements and a plausible volume. Also kill if drift continually resets break-even, or if a few handwritten functions capture the entire opportunity.

## 7. A transaction manager for long-running agent work

**One sentence / 100× — I:** Put effect identities, budgets, reservations, and compensation outside agent runs so restarts and forks do not repeat commitments. The 100× version is a transaction fabric across participating agent-operated services, with explicit partial completion for everything that cannot be atomic.

**Worsening problem / numbers / payer — F/E:** GitHub's million-plus coding-agent-created PRs show agents already initiating substantial external work; it says nothing about duplicate-effect incidence. In a hypothetical **10,000** workflows/day with **20** external actions each, an assumed **0.1%** ambiguous-outcome rate creates **200** uncertain action outcomes/day. Even individually perfect decisions leave this crash-window problem. Automation, procurement, and integration operators pay for reconciliation, conserved budgets, and fewer duplicate commitments.

**Lineage — F:** [Gray, June/September 1981](https://www.cs.utexas.edu/~witchel/380L/papers/gray81vldb-transaction.pdf) explicitly discusses transaction virtues and long-lived/nested-transaction limits. [Garcia-Molina and Salem's Sagas, 1987](https://www.cs.princeton.edu/research/techreps/598) decomposes long transactions with compensating transactions. **I:** adoption did not stall; general external resources never became universally transactional or compensatable. Better models can author connectors, but cannot invent downstream idempotency or reverse an email.

**Mechanism — I:** a DO-backed ledger records stable business-operation identity, parent budget, intent, result, and workflow state. Use local transactions/outbox delivery, downstream idempotency where genuinely supported, and fencing checked by the resource owner. A branch exploring a different possibility gets a different proposal identity; a retry of the same commitment preserves its operation identity. Duplicate intent records alone do not deduplicate effects at a nonparticipating endpoint. On uncertain non-idempotent outcomes, reconcile or expose `unknown`; compensation is another fallible business action, not time reversal. Don't hold distributed locks during a long model call: read versions, propose, reserve briefly, commit against current versions.

**Superhuman-model test — I:** strictly survives perfect reasoning because crashes, network uncertainty, deadlines, and independently owned systems remain. It is commercially crowded: durable-workflow engines and payments/integration providers already own much of the surface. A generic “exactly-once agents” claim is both occupied and too broad.

**2030 scale — E:** a vertical operations platform processes **10 million** daily effect intents, sharded by account/resource. TS Workers run connectors, DO transactions own local records, and R2 stores larger immutable inputs. There is no atomic transaction spanning arbitrary independent DOs and third-party SaaS APIs.

**First proof, 1–2 weeks — E:** two TS connectors, one idempotent and one deliberately non-idempotent mock, plus inventory and budget simulation. Crash before dispatch, after application, and before recording the acknowledgement; restore a stale capsule; expire a reservation; fail a compensation. Compare with an existing workflow engine and ordinary idempotency/outbox code. The experiment must show known, compensated, and unknown outcomes separately.

**Demo + draft tweet — I:** fork a plan ten ways, commit one, crash in the acknowledgement window, then show one commitment or an honest unresolved outcome. “Agents can copy proposals; the broker owns commitments. Participating endpoints deduplicate, compensation is recorded, and non-idempotent uncertainty stays visible. Sagas for long agent work.”

**Kill test — E:** any duplicate commitment within the declared idempotent contract falsifies the implementation. Kill the new-platform thesis if an existing workflow engine plus a small connector adapter serves the buyer equally well.

## 8. Consensus for ownership, CRDTs for shared work

**One sentence / 100× — I:** Separate the many things agents may accumulate concurrently from the few decisions that require one authoritative order. The 100× version is a society of agents that shares evidence asynchronously but serialises budgets, ownership transfers, and commits only where the application requires it.

**Worsening problem / numbers / payer — E/I:** a fully connected group of **1,000** agents has **999,000 directed pairs**; at **10,000**, **99,990,000**. This is a topology warning, not a forecast or proof every multi-agent system needs quadratic communication. At an assumed **100 ms** round trip, **20** serial coordination rounds impose at least **2 seconds** before computation. Operators pay for reduced coordination traffic, partition tolerance, and bounded resource ownership as agent counts grow.

**Lineage — F:** [Lamport's Paxos Made Simple, 2001-11-01](https://lamport.azurewebsites.net/pubs/paxos-simple.pdf) concerns agreement on chosen values. [Ongaro and Ousterhout's extended Raft paper, 2014-05-20](https://raft.github.io/raft.pdf) specifies replicated-log consensus. [Shapiro et al., 2011-01-13](https://www.lip6.fr/Marc.Shapiro/papers/2011/Comprehensive-CRDTs-RR7506-2011-01.pdf) gives convergence conditions for replicated data types. **I:** all succeeded; the enduring limit is semantic fit. A converged data structure is not necessarily a valid allocation, and consensus among machines does not make an assertion true. Model majority voting is a separate technique.

**Mechanism / difference now — I:** evidence sets, attributed annotations, and compatible edits use existing CRDTs. Ownership and spending go through an authoritative resource owner/log with appropriate failure assumptions. Do not implement Paxos in agents; use an established store or platform primitive. A copied capsule does not copy a lease. Monotonic fencing tokens prevent an old owner only if the target resource rejects older tokens; lease expiry alone cannot stop a paused process from later sending a request. CRDT text merging cannot merge arbitrary programs or reconcile conflicting real purchases. Consensus protocols here assume crash-style failures, not adversarial model-written replicas; keep replication below generated policy.

**Superhuman-model test — I:** physics and independent control survive better reasoning. Its value grows with distributed agent work, but most applications should consume this as infrastructure. Avoid a new “agent consensus protocol” product unless the application needs a novel semantic interface.

**2030 scale — E:** **100,000** agents share partitioned case evidence; each case/resource has a small ownership group, not a world quorum. Workers relay bounded updates, existing CRDT libraries manage collaborative documents, and DO owners serialise resource decisions. Cross-owner atomicity remains #7's explicit problem.

**First proof, 1–2 weeks — E:** **100** simulated clients and two real browser clients edit evidence while disconnected; a separate quota ledger accepts commitments. Exercise duplicate delivery, reconnect, stale ownership, and concurrent allocation. Compare a central event log and ordinary pub/sub. Record operations/messages, convergence time, and rejected stale writes; use the platform's existing coordination semantics.

**Demo + draft tweet — I:** partition collaborators; evidence reconverges; a restored old executor fails to spend after ownership moves. “Share evidence without a global meeting; commit scarce resources through their owner. CRDT convergence and consensus solve different problems. Neither is a vote on truth.”

**Kill test — E:** kill a separate product if central events plus existing collaboration libraries have the same latency/availability and lower complexity. Reject the architecture immediately if it treats arbitrary heap merge or a model's assertion of ownership as a valid protocol.

## 9. A garbage collector for agent-generated software

**One sentence / 100× — I:** Make generated applications, tasks, dependencies, credentials, and cloud resources collectible through explicit ownership, roots, leases, and references. The 100× version lets organisations create millions of temporary software objects without accumulating millions of permanent operational obligations.

**Worsening problem / numbers / payer — F/E:** GitHub reports **43.2 million merged PRs/month**, up **23%** in its comparable monthly averages; that is software activity, not a count of abandoned services. In a separate scenario, **1 million** generated resources each retain an assumed **$0.10/month** idle cost: **$100,000/month**, before operator attention. At **1 MB** retained state each, one version totals **1 TB**. Cloud/platform teams pay to retire unused billable resources, reduce update fan-out, and stop repeatedly presenting dead code to humans and agents.

**Lineage — F:** [McCarthy's April 1960 Lisp paper, free-storage section](https://www-formal.stanford.edu/jmc/recursive/node4.html) describes automatic reclamation through accessible list structure. [Nix's garbage-collection manual](https://nix.dev/manual/nix/2.28/package-management/garbage-collection) already collects unused software store paths while retained profile generations preserve rollback. [Kubernetes' current GC contract](https://kubernetes.io/docs/concepts/architecture/garbage-collection/) already uses owner references, cascading deletion, and finalizers; [Crossplane's v1.20 managed-resource contract](https://docs.crossplane.io/v1.20/concepts/managed-resources/) already extends controlled deletion to external resources. **I:** neither software GC nor cloud-resource ownership is new. The proposed wedge is automatic lifetime accounting at the generated-program/tool boundary, including tasks, compensations, and rollback roots, for an edge-native population. It must beat these established control planes or integrate with them.

**Mechanism / why now — I:** every generated deployment receives a manifest: owner, entrypoints, resource IDs, dependencies, scheduled jobs, external consumers, retention obligations, and rollback pins. Maintain explicit roots for production routes, user pins, active tasks, pending effects/compensations, and retention policies. Mark a consistent generation, quarantine unreferenced managed objects, allow a grace period, then sweep idempotently. New references during collection require a write barrier/version check. Keep audit records independently of executable-lifetime decisions. Cycles without roots are collectible; timers and public endpoints count as roots until their owners retire them.

**I — Historical barrier / new difference:** unmanaged scripts, dynamic imports, external links, and arbitrary SaaS resources lack a closed reference graph. A model cannot prove an unseen external consumer absent. Therefore do not start by deleting arbitrary repositories or inferring deadness from access logs. Start with resources created through one managed runtime/tool broker, require authoritative manifests, and distinguish an explicitly leased temporary object from a durable one. Better agents can instrument and migrate their generated resources; the ownership contract supplies the decisive information.

**Superhuman-model test — I:** matters more if perfect programmers generate much more useful temporary software. Correct code can still outlive its purpose and consume storage, cron quota, secrets, updates, and human attention. If better agents manage lifetimes correctly themselves, sell the resource protocol/hosting integration or abandon the standalone collector.

**2030 scale — E:** a hosting vendor manages **10 million** temporary applications with shared immutable dependencies, a smaller rooted live set, and automatic retirement. Workers serve live routes; DO records own lifecycle transitions; R2 stores code/state with pins; jitk/QuickJS guests register resource creation through the one tool channel. Active secrets stay at the host and are revoked through their owner.

**First proof, 1–2 weeks — E:** create **1,000** local managed app manifests and a small Cloudflare test cohort using only dedicated test resources. Include shared dependencies, cycles, a delayed effect reply, a new reference during marking, a rollback pin, and an external-root declaration. Compare TTL cleanup, ordinary infrastructure-as-code destroy, and an owner-reference/Crossplane-style controller. Demonstrate reversible quarantine first and deletion only for explicitly disposable test resources; meter retained bytes, wakeups, and actual idle-resource charges.

**Demo + draft tweet — I:** spawn temporary apps, pin one, let their tasks finish, and watch only the unrooted closure retire. Restore the quarantined app and its references before sweep. “Garbage collection for a managed population of generated applications. Explicit roots, shared dependencies, pending effects and rollback pins. No access-log guess that your unobserved customer disappeared.”

**Kill test — E:** kill the general collector if resource creation cannot be mediated or unknown roots dominate. Kill the product wedge if TTL/IaC cleanup or an existing ownership controller produces the same savings with simpler contracts. One collected rooted object invalidates the safety claim for the managed domain.

## Local falsification: topology determines the incremental upside

**M — Method, 2026-10-27:** ran a dependency/memoisation surrogate at `/tmp/moonshot2-classiccs/graph.py`, Python standard library only. The graph has **200 document-extraction nodes**, **20 ten-document dossier nodes**, and **one portfolio node**. Extraction returns `(document ID, amount)`; dossiers and portfolio sum amounts. Keys are operation name plus SHA-256 of canonical JSON arguments. The fresh evaluator executes all nodes on every revision; the memoised evaluator reuses exact input/output results. Both traverse the graph, so the experiment does **not** establish Salsa's dependency-validation efficiency or distributed scheduling.

**M — Sparse trace:** after one cold execution, apply **100 unique edits**, each to a different document: **60** modify the extracted amount and **40** modify only an irrelevant note. Each relevant edit evaluates three nodes; each note edit evaluates extraction but produces the old canonical result, allowing downstream reuse. All **101** portfolio results match fresh execution. Fresh execution used **22,321 node evaluations** including cold start; memoisation used **441**. Warm-only evaluations were **22,100 versus 220**, a **100.45×** reduction; including cold start, about **50.61×**.

**M — Dense counterexample:** change all 200 amounts on each of 100 revisions. Both evaluators use **22,321 node evaluations**, a **1.00×** ratio; hashes and metadata make the memoised approach strictly more work in unreported CPU terms. No timing or dollar benefit is claimed.

**I — Decision:** a 100× reduction in expensive operations is mechanically plausible for a sparse, stable, suitably factored workload; it is not evidence of a general 100× LLM speedup. The manufactured equal-cost nodes, perfect structure, deterministic functions, absent network, and small state favour reuse. Real dossier synthesis may cost much more than extraction or read every document, destroying this advantage. The first real experiment must measure **cost-weighted affected work**, not celebrate graph-node counts.

**E — Economic model:** for a fresh run costing `C`, effective affected fraction `f` weighted by actual operation costs, and incremental overhead `H`, the recurring speedup/cost ratio is approximately `C / (f*C + H)`. A 100× result needs `f + H/C <= 0.01`. If a new model cuts `C` by 100× while `H` stays fixed, overhead's relative share grows 100×. Sharing across many agents and compiling stable nodes into code are the plausible paths beyond a fragile local cache optimisation.

**M — Reproduction detail:** initialise 200 documents with IDs `0..199`, amounts `100+id`, and note `initial`; group adjacent blocks of ten. For sparse revision `t=0..99`, increment document `t`'s amount when `t % 5 < 3`, otherwise set its note to `edit-{t}`. Dense revisions increment every amount. Evaluate both engines after every update and assert equal output. Cold counts are 200/20/1; sparse cumulative memo counts are **300 extraction / 80 dossier / 61 portfolio**. These details fully specify the fixture without requiring the temporary script to persist.

## Two architectural rules that survive all nine ideas

**F — End to end:** [Saltzer, Reed and Clark, 1981; revised November 1984](https://web.mit.edu/saltzer/www/publications/endtoend/endtoend.pdf) argues that some functions require application knowledge and lower-level mechanisms serve as performance improvements. **I:** a provider's prefix cache cannot decide whether a business answer is sufficiently current; a transport acknowledgement cannot establish that a downstream purchase happened once. The application supplies reuse, freshness, and effect contracts; the infrastructure makes honouring them cheap. This remains necessary with perfectly intelligent models because it is about ownership and system boundaries.

**F — Worse-is-better:** [Gabriel's original essay, published 1991](https://www.dreamsongs.com/WIB.html?source=post_page---------------------------), and [his historical account](https://www.dreamsongs.com/WorseIsBetter.html), describe the trade-off between implementation simplicity, completeness, and adoption. **I:** the useful agent-era interpretation is a small API that can be installed and explained by a model: `observe`, `derive`, `subscribe`, `commit`, `release`. Build one profitable vertical graph before a universal intelligence OS. This is not permission to weaken cache isolation, resource accounting, or effect semantics.

**I — Shared practical boundary:** Workers are the request/tool/control surface; Durable Objects coordinate scoped mutable ownership; R2 stores immutable artifacts. A DO is not a planetary transaction manager. Browser and QuickJS/Wasm execution can bring work closer to data; they do not move an external socket, model service, or authority grant inside a snapshot. jitk's single tool channel is useful for observing managed resources and dependencies. scriptc can reduce the cost of appropriate generated operators. Each should earn inclusion through a baseline comparison.

**I — Top 3, #1:** Thought builds most directly attacks the bill that gets larger as successful agents maintain overlapping work. It combines incremental computation, shared views, content identity, and demand without requiring new model internals. The difficult research question is not hashing; it is whether useful agent tasks expose stable, narrow dependency boundaries. **I — Top 3, #6:** A model can write the algorithm once rather than execute the algorithm in tokens on every request. It also has an unusually honest loss condition: a cheap batched model or a handwritten function may already be best. Use it as the optimisation backend of #1, not an unrelated platform launch.

**I — Top 3, #9:** The world can afford many more correct temporary programs than permanent maintenance obligations. ## The ONE bet

**I — Build Thought Builds for a continuously changing operational dossier, with code compilation as its second optimisation.** A customer asks for the same repository/supplier answer every day; many agents consume it; one relevant source changes. The product updates only the required computation and shows the exact avoided bill. Begin inside one organisation with explicit structured dependencies, immutable model responses, and ordinary state. Use a query-engine integration where it helps. Add capsules only if a measured long local prefix makes them worthwhile.

**E — First 14 days:** days 1–2 obtain two representative revision traces and freeze freshness/output contracts; days 3–6 implement the minimal TS graph and cost accounting; days 7–10 run held-out sparse and broad changes against fresh, cached, and hand-incremental baselines; days 11–14 show a second consumer sharing work, deploy a small Workers/DO/R2 demo, and publish the complete cost breakdown. If no customer trace is available, label the result a mechanism demo and do not infer demand from it.

**I/E — Continue only if:** at least one real workflow saves **2× total recurring cost** after graph overhead and a plausible route exists to **100×** through shared consumers, highly selective updates, or compiled repeated operations. Measure the same comparison again with a cheaper/stronger available model; also show hypothetical 100×-cheaper inference accounting. If a fresh run wins, remove the graph for that workload. The larger ambition is a shared, self-maintaining computation fabric; the first evidence must be one real update whose avoided work is worth paying for.

1. **I:** Make agent work reusable across inputs, revisions, and consumers; the expensive function now warrants build-system and database machinery.
2. **F/M:** Incremental computation has deep primary-source foundations; the synthetic sparse graph saves 100× warm node evaluations, while dense changes save nothing.
3. **I:** Bet on Thought Builds, then compile repeated reasoning into code and collect the temporary software/resources it creates.
4. **I:** Query optimisation, memory paging, schedulers, transactions, consensus, and CRDTs are enabling mechanisms with substantial existing prior art.
