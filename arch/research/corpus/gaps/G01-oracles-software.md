## 0. Findings

1. **F/I: There is ample public checking material.** §2 inventories **50 oracle candidates**, including finite suites, runnable references, generators, proof checkers and rebuild comparisons. Their existence does not establish that a new artifact is useful, untaken or fully checked.
2. **I: A reference that can be ported remains potentially valuable.** A port can create a smaller dependency graph, safer deployment, a new runtime target, better performance or a usable licence. The right question is what measured capability remains missing after using the reference directly. Portability alone neither proves nor erases that value.
3. **F: AI-assisted bootstrap work already exists.** There is a Claude-assisted [GHC source-bootstrap chain](https://github.com/andreabedini/ghc-bootstrap), a [Kotlin project marked WIP](https://github.com/movq/kotlin-bootstrap), and a [Resid DDC interpreter](https://github.com/larrydewey/resid-ddc). “Nobody uses agents for bootstrapping” is false. A project description is evidence of activity, not independent verification of its results.
4. **I: The strongest provisional pairing is a maintained, explicitly scoped DDC route for one underserved toolchain.** It overlaps G07 and has not cleared a target-specific novelty or feasibility test. A matching official binary is the comparison result; the diverse route, assumptions and exact build graph must be established separately.
5. **F/I: The spreadsheet runner-up is more occupied than the draft reported.** [GRID](https://hjalli.com/posts/building-a-high-performance-spreadsheet-engine-the-quest-for-compatibility-and-s/) uses saved values; [xlsx-corpus-bench](https://github.com/witanlabs/xlsx-corpus-bench) publishes comparisons against Excel across two public corpora. An entirely new open fidelity benchmark is not an established gap. Contributions to an engine may still have value.
6. **I: Last Copy remains a conditional interoperability project.** Publisher retirement is real, but an open importer already exists and perpetual licences can retain access. The report does not establish a fast-closing, exclusive oracle or an untaken reader project.

**I: No pairing below is a verified, untaken winner.** The recommendation is one short bootstrap/DDC feasibility spike shared with G07, plus two clearly downgraded alternatives.

## 1. What a pass actually establishes

| Oracle type | What a pass supports | Important limit |
|---|---|---|
| Finite conformance suite | Listed behaviors on the pinned cases and configuration | Passing tests is not full language/format correctness; skips and expected failures matter |
| Runnable reference | Agreement on the inputs and observable outputs compared | Shared bugs, undefined behavior, version drift, resource limits and environment can invalidate a comparison |
| File containing a producer's result | Agreement with that recorded result | A cache can be missing, stale, from another application or dependent on unavailable inputs |
| Differential generator/ensemble | A reproducible discrepancy worth investigating | Majority agreement does not identify the correct implementation; generators have coverage limits |
| Proof checker | The stated theorem under its definitions, axioms and trusted base | A theorem can describe the wrong requirement; it does not automatically cover the deployed artifact |
| Reproducible build | Equal artifacts for specified build inputs | Reusing a compromised seed can reproduce the same unwanted behavior |
| Full-source bootstrap | A documented route from declared seeds through source builds | It still trusts seeds, tools, sources and execution environment; it need not reproduce the vendor binary |
| Diverse double-compiling (DDC) | Under its assumptions, correspondence of a particular compiler executable to particular source | Neither universal compiler correctness nor benign source; equality alone does not demonstrate diversity |

**F: The DDC distinction is explicit in David A. Wheeler's account.** Different compilers normally produce different machine code. DDC uses a trusted compiler to build the relevant parent compiler source, then that result builds the target compiler source; the target-stage output is compared with the suspect executable. Its correspondence result depends on the trusted path, correct handling of the relevant source semantics and build inputs, and a faithful comparison. The 2009 treatment handles compilers that are not self-parented. [Wheeler's explanation](https://dwheeler.com/trusting-trust/), [dissertation](https://dwheeler.com/trusting-trust/dissertation/html/wheeler-trusting-trust-ddc.html).

**I: Practical acceptance contract.** Freeze the evaluator and relevant inputs, compare observable behavior, keep source-separated holdouts, report excluded cases, and test generalization beyond the triggering example. Performance, memory, startup and deployment constraints need their own gates. A ratchet preserves previously measured results on a pinned configuration; it cannot promise all future releases or inputs will pass.

**F/I: A current example of the testing limit.** Basis reports that an LLM-generated semantics passed its WHILE tests while mishandling long function names; a proof against the executable forced a correction. In plain terms, the tests missed an input, while the claimed theorem had to account for it. This is evidence for stronger checking, not evidence that ordinary tests or ports have no value. Its Lua/OCaml extensions are ongoing work, not completed general verification. [Basis, 2026-10-16](https://www.basis.ai/blog/ship-your-interpreters/).

## 2. Inventory: 50 public software oracle candidates

**F — Size method, measured in this audit.** `S` means **MiB of tracked blob contents in a GitHub source tree**, rounded to 0.1 MiB, excluding history, submodule contents and external/LFS payloads. It is an acquisition/implementation-scope proxy, **not a test count, executable size or memory requirement**. A `≥` marks a truncated API tree: only a lower bound was measured. Short commits identify snapshots in the linked repositories. Fixture counts below count files, not assertions. Where a numeric size was not measured, the row gives scope and says so. Source-tree measurements use GitHub's primary [`git/trees/{ref}?recursive=1` API](https://docs.github.com/en/rest/git/trees#get-a-tree), not search snippets.

**F — Access/licence key.** `local` means public source/data can be obtained and run locally; build dependencies still apply. Licences summarize the named material, with bundled notices/exceptions retained. Publicly downloadable is not synonymous with unrestricted reuse. Proprietary applications are public-access oracle candidates requiring a valid licence, not open-source or freely redistributable oracles. Some upstream runners use Python; proposed work here would use Rust/C/Go/TypeScript harnesses or reusable data, and no Python was used in this audit.

## 4. Current bootstrap landscape and genuinely unresolved questions

**F: The relevant research result.** Courant, Lepiller and Scherer's [Camlboot paper](https://arxiv.org/abs/2202.09231) ran an OCaml compiler through stacked implementations rather than constructing a production competitor. It reports a DDC result for OCaml 4.07 and about a person-month for the final design. In plain terms, a deliberately slow bootstrap implementation can be enough, but this demonstrated one version/configuration, not all later OCaml releases.

**I: Open flags, scoped to what this audit has not established:**

- **Candidate gap, low confidence:** a maintained, independently reviewed DDC route for a pinned current Zig or OTP artifact. No completed route was verified here; that is not proof none exists. Before growing anything, inspect current alternatives and the official build recipe.
- **Evidence gap:** which target artifacts reproduce exactly, what parent/compiler configuration created them, and which stage/file should be compared. A parser pass rate or fixed-point C output is not automatically a certificate for the shipped executable.
- **Trust gap:** the provenance of the chosen independent toolchain, generated code, libc/linker, build scripts and runtime. List actual trusted components rather than declaring “independent” from a hash match.
- **Opportunity gap:** whether a small maintained route materially improves an existing bootstrap project instead of duplicating it. No funding/team-absence claim is justified by the searches.
- **Spreadsheet residual:** whether an existing open engine has a concentrated, repairable failure cluster on fresh Excel truth that current maintainers/benchmarks do not already address. A public benchmark alone is no longer the gap.
- **Publisher residual:** a measured unsupported record/layout family on legally obtainable modern files. No corpus or baseline experiment in this report establishes that gap.

## 5. Three developed pairings, including reasons to reject them

### 5.1 Thompson's Mirror / G07 Seedless — maintain a diverse bootstrap route for one toolchain

**I — One sentence and value.** Grow a deliberately limited implementation that can execute a selected compiler's source, then publish a repeatable, scoped source-to-artifact correspondence check. A stranger's benefit: reduce dependence on an unexplained compiler seed for that specific release.

**F/Q — Seed.** Thompson's [1984 lecture](https://dl.acm.org/doi/10.1145/358198.358210) explains how a compiler can propagate behavior absent from its published source. Kelley's [2024 reply](https://ziggit.dev/t/building-self-hosted-from-the-original-c-implementation/6607) requests a bespoke Zig interpreter for bootstrapping. In the local SPLASH'25 transcript, Zhendong Su says **Q:** “if we do have a reliable oracle” for compiler building, it can be coupled with AI (`g1-03-acm-sigplan-splash-25-the-quest-toward-that-perfect-compiler.txt`, [49:00], line 53, checked). These are a specific use case and a practitioner seed, not evidence that DDC is universal correctness.

**I — What grows.** One implementation in C or Rust, limited to one pinned compiler workload; missing language constructs trigger additions. Retain the implementation, fixtures, exact stage recipe, input hashes and comparison receipts. Runtime speed matters only enough to execute the chain within the budget. Begin with one language; “every self-hosted ecosystem” is a long-term ambition, not a solo six-week scope.

**I — Oracle design and boundaries.**

1. Identify the actual parent source `S_P`, target source `S_A`, target artifact `A`, build options and environment. For a genuinely self-parented stage these sources can coincide; otherwise preserve the real parent/build graph.
2. Use a separately justified trusted implementation `T` to build/run `S_P`, producing `P'`. Use `P'` to build `S_A`; compare the corresponding target bytes with `A` outside the agent's writable environment. Map interpreter execution onto these stages explicitly.
3. Establish reproducibility separately. Prefer exact payload equality. If a package signature, timestamp or archive wrapper is excluded, report precisely which payload is covered and retain the excluded bytes. Do not silently normalize code-bearing differences away or call a normalized package a full official-binary match.
4. Record why `T`, its compiler/runtime and its input sources satisfy the intended trust/diversity assumptions. A different language, model family or a sandbox without the official binary is useful evidence, but none alone proves independence. Source availability also permits correlated implementations.
5. Keep conformance tests, held-out source variations and limits checks as secondary gates. A source-to-binary correspondence result does not prove all target programs compile correctly, or that the compiler source is benign. Bugs can be unexercised or preserve the compared output; correlated errors do not necessarily produce mismatches.

**I — Anti-shortcut policy.** Block direct use of target binaries in the candidate route, freeze the judge, review dependencies/embedded artifacts and retain logs. This reduces obvious output copying. It does not prove that an agent cannot specialize to known inputs, memorize outputs or smuggle a result through unreviewed dependencies. Accept only the correspondence statement justified by the actual route and assumptions. Do not describe a hash check as impossible to game.

**I — Tailwind and one-shot test.** Stronger models may implement more compiler-workload semantics and maintain more releases. The durable asset would be executed, reproducible routes with inspectable trust manifests, not source code an agent can regenerate. A future model with tools could eventually reproduce the entire run; the defense against commoditization is maintained coverage and useful evidence, not a claim that one-prompt completion is logically impossible. Demand and maintenance cost remain unmeasured.

**E — Six-week version and demo.** Days 1–3: reproduce a known Camlboot result as a **DDC** calibration, or a Go build as a **reproducibility** calibration, labeling them differently. In parallel inspect current Zig/OTP alternatives and select one exact artifact that an ordinary rebuild can reproduce. Week 1: implement enough parsing/evaluation to run a real compiler unit, with source variations beyond one fixture. Weeks 2–5: advance through additional units and dependencies, logging unsupported constructs. Week 6: demonstrate a complete scoped stage comparison if achieved; otherwise publish a plainly incomplete progress result, not a certificate. The ambitious demo is “this selected bootstrap payload was reproduced through this reviewed route”; equality to all official release files is a separate milestone.

**F/I — Prior art and what remains.** Camlboot demonstrates the tailored method; GHC/Kotlin show AI-assisted bootstrap activity; Resid demonstrates an independent interpreter/seed comparison; DDC4j/tcc-hardened already publish DDC machinery. Basis's ongoing OCaml work is adjacent funded activity. G07 proposes the same project. The possible residual is a **specific unsupported current toolchain/release route plus maintenance**, not invention of the mechanism. No target has yet been shown both vacant and feasible.

**E — Cheapest kill test.** Cap the investigation/growth spike at **10 days and $1–3k in model spend**, estimates rather than measured costs. Stop if current prior art already supplies the desired result, the official comparison cannot be made deterministic within the scope, the independent route cannot be accounted for, or a complete meaningful compiler unit cannot run and generalize to withheld source variations. A mismatch is initially a debugging result, not a backdoor finding. If the hard part is ordinary reproducibility work, reassess value with G07/G04 rather than relabeling it DDC.

**E — Scores:** Tail **5**, Cool **4**, Value **4**, Open **2**, Solo **3**, Demo **3**. **Decision:** provisional pick for a shared G01/G07 spike; not yet cleared for full implementation.

### 5.2 Open Recalc — repair a measured fidelity gap in an existing open engine

**I — One sentence and value.** Grow Excel-compatible formula behavior inside an existing Rust engine, judged on independently refreshed workbook results. The benefit is a reusable local calculation engine whose supported behaviors are measured, including for agent-produced workbooks.

**F/Q — Seed.** GRID's founder describes saved-result comparisons as part of engine development ([2024 article](https://hjalli.com/posts/building-a-high-performance-spreadsheet-engine-the-quest-for-compatibility-and-s/)). Joseph Kim's local transcript describes artifact tooling that can **Q:** “produce Excel models and PowerPoint presentations” (`p3-09-ai-engineer-how-openai-built-chatgpt-for-bankers-and-analysts-joseph-k.txt`, [08:00], line 12, checked). This supports a calculation workload, not the claim that agents have no engines today.

**I — What grows and its oracle.** Coercion, errors, date systems, arrays, names and function implementations in IronCalc or another existing engine. A reproducible mismatch triggers a patch; regressions and source-separated held-out workbooks must still pass. Keep per-function and per-workbook rates, plus absolute denominators; a high cell-weighted rate can hide complete failure on rare functions or entire workbooks.

**F/I — Correct the cached-value premise.** Microsoft's [SpreadsheetML documentation](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas) says `<v>` is an optional last-calculated value. It does not authenticate which application computed it or whether it remains valid. An “Excel” application metadata field is a filter, not proof. `fullCalcOnLoad` is a recalculation request, not proof that all existing caches are absent or wrong. Exclude or separately model volatile functions, external links, add-ins/macros, iterative calculation, dates/time zones and missing inputs. For authoritative current truth, recalculate with a licensed, pinned Excel version under a recorded policy; use saved caches only as explicitly lower-confidence historical evidence.

**F — Scale and closest collision.** FUSE's authors provide [249,376 spreadsheets overall](https://static.barik.net/fuse/index.html), mostly a different denominator from usable OOXML formula workbooks. The current [xlsx-corpus-bench](https://github.com/witanlabs/xlsx-corpus-bench) reports 10,544 FUSE and 5,426 SpreadsheetBench workbooks in its comparison universes, and uses fresh Excel recomputation. It explicitly distinguishes cache provenance from current engine fidelity. Its Apache-2.0 harness uses Python, so its data/methodology are prior art; adopting the harness unchanged would violate this brief. [basis1](https://basis1.tech/methodology) independently reports another cache-based corpus effort; those are author-reported measurements, not results reproduced here.

**I — Tailwind and one-shot test.** Better models may fix more interacting semantics; a future engine-writing prompt still needs independent execution to establish measured compatibility. But stronger models can also make these patches routine. The durable result is supported behavior in the engine, not merely a dashboard or benchmark that already exists.

**E — Six-week version and demo.** Week 1: use Rust tooling to inventory a modest lawful corpus, refresh a small adjudication sample with Excel, and compare IronCalc with a second engine. Weeks 2–5: fix one concentrated semantic family, keeping hidden cases and separate workbook/cell denominators. Week 6: demonstrate a formerly failing workbook cluster recalculating locally in Wasm and show held-out results. Do not promise “drop any `.xlsx`” or a drop-in replacement for every LibreOffice workflow.

**F/I — Prior art and residual.** [IronCalc](https://github.com/ironcalc/IronCalc) is MIT/Apache-2.0, and [NLnet's grant page](https://nlnet.nl/project/IronCalc/) records a 2024-02–2026-05 period; do not imply unverified funding through all of October 2026. GRID, LibreOffice, Gnumeric and other engines already exist. The public corpus benchmark itself is occupied. A specific upstream patch cluster or deployment advantage may remain, but neither was measured here.

**E — Kill test.** In two days, compare a stratified sample of roughly 500 eligible workbooks and count valid oracle results before failures. Stop the standalone proposal if an existing engine already satisfies the chosen deployment contract, prior work already addresses the cluster, or most discrepancies are cache/input provenance. Proceed only if a valuable, reproducible family generalizes beyond a few fixes. Aggregate 99% cell agreement alone is neither a kill nor a success criterion.

**E — Scores:** Tail **4**, Cool **2**, Value **4**, Open **1**, Solo **4**, Demo **3**. **Decision:** contribution-shaped; no standalone recommendation without a measured residual.

### 5.3 Last Copy — extend Publisher interoperability against recorded native exports

**I — One sentence and value.** Grow support for a measured unsupported family of `.pub` documents and compare it with Publisher's own PDF exports. The benefit would be opening those documents in a maintained local reader without the retired application.

**F/Q — Seed.** Microsoft's [current support page](https://support.microsoft.com/en-us/publisher) says Microsoft 365 removal began on or shortly after **2026-10-01**, and perpetual-version support ended **2026-10-13**; perpetual users can still access/edit their files. Thus “the oracle vanishes this month” overstates the case. The local Nerd Snipe transcript says **Q:** “You can reverse engineer and port over in ways that are actually functional” (`14-nerd-snipe-we-can-t-trust-gemini-4.txt`, [0:45:00], line 49, checked; speaker unidentified in captions).

**I — What grows and its oracle.** Record decoding and selected layout rules in an existing importer or a Rust component, triggered by lawful corpus failures. Run a valid perpetual Publisher installation in a recorded Windows environment; freeze PDFs, font inputs and export settings outside the candidate's writable area. Compare text, coordinates, page geometry and images under fixed tolerances, with separate categories for unsupported features. A visually close PDF does not establish editability, accessibility, exact print output or safe parsing.

**I — Tailwind and one-shot test.** Better models may decode additional record families faster. Native exports and documented examples remain useful evidence, but they are neither unique nor guaranteed to become unavailable. A future model might port an existing importer quickly; a repeatable fidelity gain on an unsupported real-file family is the proposed accumulated value.

**E — Six-week version and demo.** Days 1–3: obtain about 200 lawful, version-diverse sample files and benchmark current LibreOffice/libmspub against native exports. Weeks 1–5: fix one demonstrably unsupported record/layout family, reusing the existing importer where appropriate. Week 6: display native and new-reader exports for held-out documents and show content/layout differences. A complete `.pub` reader or 1,000 redistributable samples is not assumed achievable in six weeks.

**F/I — Prior art and residual.** [libmspub's primary README](https://github.com/LibreOffice/libmspub/blob/master/README) describes Publisher reading/conversion under MPL-2.0. This audit did not establish a precise modern-version ceiling; the interrupted draft's secondary claim that it stops at 2010 is removed. Nor did it establish that Publisher is the only usable reader, that Scribus shares the same coverage, or that no agent-assisted work exists. Finale is not developed as a second target: [musxdom](https://github.com/openmusx/musxdom) is concrete neighboring prior art, and its current importer/rendering ecosystem was not audited fully. The possible gap here is a measured Publisher feature family, not generic preservation or a novel format-foundry loop.

**E — Kill test.** Establish lawful application/corpus access before the spike. Stop if a valid oracle cannot be run, no valuable unsupported feature family appears in the baseline, or a short patch to the existing importer already solves the chosen use case. Run a two-day growth test on held-out documents before committing to a new implementation. Font rights and corpus redistribution remain unresolved access requirements, not a legal conclusion in this report.

**E — Scores:** Tail **3**, Cool **2**, Value **3**, Open **2**, Solo **3**, Demo **4**. **Decision:** hold; strong adjacency to the rejected preservation archive and G03 Format Foundry. Do not re-pitch it without the baseline evidence.
