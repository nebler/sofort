## Recurring themes and unresolved disagreements

1. **I — Proof must match the claimed behavior.** Reading some relevant documents does not establish exhaustive review (34, 00:00–02:00); a still screenshot does not establish an animation stopped moving (36, 08:00); a successful dashboard screenshot does not establish which login path was used (39, 04:00–06:00). These are different forms of a coverage/path/temporal evidence gap, not a request for another generic agent reviewer. [34](https://www.youtube.com/watch?v=TU8kwE7z1qY&t=0), [36](https://www.youtube.com/watch?v=kQguG4YS0d0&t=480), [39](https://www.youtube.com/watch?v=VNJ8P1GqxnA&t=240).
2. **I — Fresh-agent operability is observable behavior.** AGENTS.md changes, existing tools and new helper routes need trials in fresh contexts without hints. The same pattern appears in the long talk, podcast and tutorial, including E2B access discovery, credit tools and login routes. These are repeated descriptions from the same team, not independent customer counts (37, 29:00–30:00; 38, 33:00–38:00; 39, 01:00–07:00; 40, 02:00–04:00). [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=1740), [38](https://www.youtube.com/watch?v=3v7dIHh15dk&t=1980), [39](https://www.youtube.com/watch?v=VNJ8P1GqxnA&t=60).
3. **I — The environment can invalidate the result.** Snapshot versus checkout identity is explicitly uncertain in the tutorial; the Laravel portal changes HTTPS behavior; a refactor's token failure is environmental; target-macOS behavior requires a real Mac (39, 05:00–06:00; 42, 06:00–07:00; 41, 20:00–22:00; 37, 22:00–23:00). This favors narrow provenance and precondition checks over another environment host. [39](https://www.youtube.com/watch?v=VNJ8P1GqxnA&t=300), [42](https://www.youtube.com/watch?v=1Niex0BvwQk&t=360), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=1200), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=1320).
4. **I — Human intent is operational data.** Shared threads let others understand flags, patches and incidents without waiting for the author. Polished PR prose is a lossy substitute. This recurs in 35, 30:00–32:00/41:00–44:00; 36, 15:00–16:00/24:00–25:00; 37, 19:00–20:00; 38, 45:00–46:00. The broad implementation is already in Amp; a cross-vendor evidence bridge is only an inferred narrower opportunity. [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=1800), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=1140), [38](https://www.youtube.com/watch?v=3v7dIHh15dk&t=2700).
5. **I — “Done” extends beyond a commit.** Shipping, live-version checks, observing outcomes and replying to the customer are one task in their internal workflows (35, 45:00–56:00; 36, 18:00–23:00; 37, 27:00–28:00; 41, 15:00/22:00–25:00). “Issue done,” “server deployed,” “CLI published” and “the user's problem resolved” are different states. [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=2700), [36](https://www.youtube.com/watch?v=kQguG4YS0d0&t=1080), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=1320).
6. **I — Instrument first; observe enough; then change.** They ship logging-only changes, inspect actual usage and only then implement, sometimes waiting an hour or a day. Canary gains are checked against fleet data; benign error rates still coexist with a user regression (35, 45:00–48:00; 38, 19:00–21:00; 37, 11:00; 41, 00:00–01:00/10:00–11:00). Evidence sufficiency is more interesting than the already occupied scheduling/rollout loop. [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=2700), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=660), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=0).

The specific cross-system accounting objection appears in 35; the other videos corroborate the workflow, not that objection independently. [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=3180), [36](https://www.youtube.com/watch?v=kQguG4YS0d0&t=1320), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=1320).

[36](https://www.youtube.com/watch?v=kQguG4YS0d0&t=360), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=600), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=300).

[34](https://www.youtube.com/watch?v=TU8kwE7z1qY&t=660), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=1440), [38](https://www.youtube.com/watch?v=3v7dIHh15dk&t=2040).

[37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=1320), [38](https://www.youtube.com/watch?v=3v7dIHh15dk&t=2280), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=1080).
11. **I — Context importance is layer- and workload-dependent.** Baseten calls compaction a core technical problem for matters spanning tens of millions of tokens (34, 02:00–05:00/20:00–25:00); Ball says users should stop manually managing context (37, 08:00–09:00). These do not logically contradict: users can avoid manual context work only if the underlying memory system works. Their assertions should be tested separately, not flattened into “context is solved.” [34](https://www.youtube.com/watch?v=TU8kwE7z1qY&t=120), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=480).
12. **I — Cheap versus frontier is not a universal disagreement.** Harvey favors specialist/open/frontier mixtures for repeatable legal distributions (34, 09:00–10:00/35:00–36:00); Amp favors frontier models for open-ended building (36, 11:00; 38, 03:00–08:00). Ball explicitly accepts the cheapest model that meets evals for a known app workload (37, 07:00), and chooses a model for a mechanical task in 41, 06:00. Compare accepted-task cost and rework under a specified task distribution. [34](https://www.youtube.com/watch?v=TU8kwE7z1qY&t=540), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=420), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=360).
13. **I — No mandatory review is not no human review.** The slogan appears in 35/36/38, but Ball repeatedly inspects important files, asks for external judgment and manually exercises behavior (35, 36:00–41:00; 37, 14:00–17:00/33:00; 41, 20:00–22:00). The open question is what evidence and change scope justify each level of review. Generic post-merge integration and AI review are already occupied in the background research. [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=2160), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=840), [41](https://www.youtube.com/watch?v=0WeQLAZVJ8w&t=1200).
14. **I — Claims about discarding frameworks/skills coexist with reliance on them.** Ball and Slack criticize elaborate skill stacks, but use repo-specific skills, AGENTS.md and SvelteKit; Slack explicitly defends frameworks and reports local patches (35, 39:00/43:00–44:00; 37, 19:00; 38, 51:00/54:00–56:00). The useful distinction is tested, task-relevant affordances versus an unmeasured pile of instructions. [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=2340), [37](https://www.youtube.com/watch?v=Z7l1EHfCMU8&t=1140), [38](https://www.youtube.com/watch?v=3v7dIHh15dk&t=3240).
15. **I — Organizational limits survive stronger models.** Harvey names regulatory, customer-data, coordination and feedback-delay constraints (34, 11:00–17:00/30:00–36:00); Amp names permissions, team boundaries, budget constraints and finite market demand (35, 56:00–1:08:00; 38, 03:00–18:00). Tools can expose these limits, but cannot assume authority or make incentives disappear. [34](https://www.youtube.com/watch?v=TU8kwE7z1qY&t=1800), [35](https://www.youtube.com/watch?v=deiLxNZH_DM&t=3360), [38](https://www.youtube.com/watch?v=3v7dIHh15dk&t=180).

## Five most interesting candidates

These are **I — conditional project candidates**, not five certified market gaps. The ranking favors a surprising practitioner signal and a bounded artifact. None is a direct re-pitch of a kill-list item; occupied adjacent mechanisms and likely upstream destinations are explicit.

**1. Blind-eval evidence auditor (P01).** **Q:** Video 39's apparently simple success story contains its own warning: the trace does not show checkout revision or how instructions entered context, and the normal-login control has missing browser evidence (05:00–06:00). **I:** Build a small add-on that records trial revision, loaded instruction/context manifest, unhinted task, expected observable action and control result, then rejects unsupported “passed” summaries. Check execution logs directly where possible; do not make the authoring agent's self-report the oracle. **F:** [agentsmd-rl](https://github.com/findalexli/agentsmd-rl) already evaluates instruction following, so the interesting artifact is the validity/evidence check for a team's own mini-eval, likely an upstream integration. A one-day kill test is whether an existing eval/trace tool already catches all three failures: hinted task, wrong revision, unexecuted control.

**2. Commentary-versus-cases transfer benchmark (P05).** **Q:** Gabe says Harvey supplied the right long-tail cases, then trained on them, and neither reproduced the reasoning quality seen on famous cases; he suspects the extensive analysis written about famous cases (34, 18:00–20:00). **I:** Construct a small matched corpus comparing raw cases, raw cases plus human analysis, raw cases plus generated analysis and corresponding training variants, with complete retrieval held fixed. Judge transfer on unseen related fact patterns using lawyer-owned criteria. This tests a concrete practitioner hypothesis about the kind of information missing, rather than proposing another legal chatbot. **F:** [Existing legal RAG benchmarks](https://reglab.github.io/legal-rag-benchmarks/) already include gold explanations, so the ablation and transfer protocol must be compared with their papers before claiming novelty. The kill test is either finding the experiment already published or discovering that raw-case and commentary conditions leak the target answers.

**3. UI jitter witness (P08).** **Q:** Slack needed every frame to establish that an icon no longer moved (36, 08:00); Ball's later hover/tooltip bug required a recording, multiple diagnoses and side-by-side interaction testing (41, 03:00–08:00). **I:** A tiny tool could take a recorded interaction plus a temporal invariant—e.g., the icon's center remains within a tolerance while its container is stationary—and emit the displacement trace and violating frames. It should distinguish intended motion, capture artifacts and real jitter instead of producing only a visual similarity score. **F:** [Playwright already records video](https://playwright.dev/docs/videos); a dedicated checker was not established in the one search. This is an add-on-sized candidate with a very fast kill test: reproduce those two defect classes and compare existing visual regression tooling before building a product.

**4. Incident restitution reconciliation (P13).** **Q:** Amp can identify affected users and issue credits, but Slack says separate support, Salesforce/account and accounting records make doing this for 73 users onerous enough to skip (35, 54:00–56:00). **I:** Start with a reviewed impact list and reconcile each account/contact to the support notice and credit transaction, surfacing missing mappings, duplicates and unapplied credits. Keep discretionary compensation policy human-owned; the project is consistency across records, not deciding who deserves money. **F:** [Stripe already has the credit ledger](https://docs.stripe.com/billing/customer/balance), and the quick search did not establish a directly matching reconciliation product. The interesting signal is a specific cross-vendor obstacle named by a practitioner; the novelty confidence is low until support, incident-management and billing vendors are checked directly.

**5. Fix-live support receipt (P14).** **Q:** Slack explicitly calls out the bad experience of receiving “fixed” while the fix has not rolled out (35, 53:00); Ball checks served commit, CI and release-channel state before closing a CLI bug (41, 15:00/22:00–25:00). **I:** Connect a support issue to the relevant code version, service/region or flag cohort and published client package; emit a reviewable receipt only when the applicable release predicate holds, with “published” kept distinct from “installed by this customer.” **F:** [Linear/Intercom already automates issue-completion follow-up](https://linear.app/docs/intercom), so the narrow value is deployment truth and contradictory states, not another support bot. Amp has built its own version; the kill test is whether the target support/release stack already exposes an equivalent customer-specific predicate with one ordinary integration.

## Extraction limits

- **Q versus F:** Revenue comparisons, model failure percentages, company-size predictions, earlier legal training outcomes, Cloudflare problems and framework bug discoveries remain speaker claims. No transcript result was independently reproduced.
- **I — Independence:** Eight of the nine videos are from Amp, with several reusing the same examples. Repetition supports salience within that team, not broad market frequency.
- **I — Research scope:** This is a broad signal extraction and a one-query-per-candidate triage. “Unclear” is deliberately used instead of turning search non-results into novelty claims. Generic agent hosting, snapshots, scheduling, model routing, previews, AI review, generated apps and post-merge integration are not finalists.
- **I — Main uncertainty:** The clearest internal workarounds are already within reach of a good agent and existing tools. The five candidates need narrow evidence of repeat demand before becoming standalone products; several may be better as small upstream contributions or benchmark additions.
