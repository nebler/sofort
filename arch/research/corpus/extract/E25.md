## Recurring themes and cross-video tensions

All statements in this section are **I**, grounded in the cited Q blocks; source IDs resolve to exact files in the source register.

1. **A shared rule system scales better than enumerating outcomes.** LibreLane separates state/step/flow (`g2-11` 05:00–06:00); Nintendo composes vehicles and audio without dedicated whole-object implementations (`g2-18` 21:00–26:00, 56:00–59:00); Slang's graph prototype similarly moves repeated glue into a reusable execution structure (`g2-19` 26:00–29:00). This is a structural seed, not evidence that a new generic framework is unoccupied.
2. **An approximation's validity changes when the operating regime changes.** Early physical-design estimates trade accuracy for freedom (`g2-16` 04:00–05:00); separate tire curves need combined-slip correction (`g2-17` 46:00–53:00); Homa's virtual line-rate NIC stops being reliable at 100 Gb/s (`g2-20` 13:00–17:00). A useful artifact includes a domain of validity, not just code that runs.
3. **The check can be much more concrete than the generator.** DRC/LVS and pinned environments (`g2-11` 10:00, 12:00), clean-cook byte comparison (`g2-13` 35:00), controlled throughput reproduction (`g2-14` 12:00, 21:00), static timing as the golden result (`g2-16` 12:00–15:00), shrine test rooms (`g2-18` 30:00), and a graph reference interpreter (`g2-19` 28:00) are named or demonstrated checks. None alone validates every desired property.
4. **Effort plus an oracle appears, but current ownership often kills the broad project.** Hand integration of memory generation (`g2-11` 13:00–14:00), years of incremental-cook work (`g2-13` 33:00–35:00), serial ECO limitations (`g2-16` 10:00), and repeated multipass glue (`g2-19` 26:00–28:00) fit the search shape. The current-source triage below finds strong incumbents on the hardware and UE cases, and the Slang speaker is building the broad solution himself.
5. **More concurrency can make things worse.** Multiprocess cooks consume memory and expose dangling pointers (`g2-13` 06:00–07:00); extra observer cores increased context switches and lowered throughput (`g2-14` 13:00–16:00); a single network pacer bottlenecks short packets (`g2-20` 20:00–22:00). “Parallelize it” is not a sufficient acceptance criterion.
6. **Common dependencies collapse apparent redundancy.** One frontend served all transaction signers and shared administrators collapse identity domains (`g2-12` 26:00–27:00, 43:00–45:00). Shared maintainers and CI credentials similarly joined nominally separate organizations (`g2-15` 12:00–21:00). Defensive independence must include build, deployment, identity, and supply roots.
7. **The desired state is not necessarily the effective state.** Kubernetes field ownership retained provider mutations after a disable label (`g2-14` 07:00–09:00); a GitHub action tag could resolve to unexpected code (`g2-15` 21:00–31:00); nested Slang reflection/binding remained trial-and-error (`g2-19` 20:00–22:00). Readback and execution identity matter more than a plausible manifest.
8. **Convenient observability can mislead.** Updated packages did not imply safe code semantics (`g2-12` 25:00–26:00); four-core iperf did not reproduce the real workload (`g2-14` 10:00–12:00); GitHub event sources omitted necessary evidence (`g2-15` 23:00–24:00, 34:00); outstanding NIC bytes mix multiple states (`g2-20` 09:00–10:00, 28:00–31:00). Every proposed oracle needs stated blind spots.
9. **Physical correctness and believable experience are different objectives.** Wasim deliberately fakes engine controls and adds stabilization (`g2-17` 21:00–22:00, 01:06:00–01:09:00); Nintendo adjusts mass for thick stylized boards and tunes acoustics (`g2-18` 29:00–30:00, 47:00–50:00). A physics check can reject explosions or unit errors, but cannot certify fun or convincing sound.
10. **Data and access can defeat a solo implementation plan.** Proprietary PDK NDA access (`g2-11` 08:00), inaccessible physical tire facilities (`g2-17` 32:00, 52:00), maintainer-provided private logs (`g2-15` 13:00, 34:00), and console backends (`g2-19` 02:00–03:00) are real constraints. Public models and self-owned test environments must suffice for core value.
11. **Fair baselines are an unresolved recurring problem.** Guthaus explicitly strengthens conventional optimization before comparing ML (`g2-16` 17:00). Networking audience members challenge the default FQ-CoDel baseline and driver tuning (`g2-20` 28:00–32:00). The counterevidence belongs beside the claimed gain.
12. **Better models can consume the small tool rather than improve its durable value.** Woods drops alternate syntax partly because agentic coding changes usability priorities (`g2-19` 10:00), and researchers already ask Claude to inspect source (`g2-19` 21:00). Dai Zovi predicts automation will compress defensive response windows (`g2-12` 35:00–36:00). Documentation bots, diagrams, configuration UIs, and ordinary one-off ports are therefore retained as extraction signals but fail as stand-alone tailwind pitches.

**Within-share disagreements not to erase:** preventative architecture versus overreliance on detection (`g2-12` 33:00–36:00); model fidelity versus deliberately simulated experience (`g2-17` 08:00–09:00, 01:02:00–01:03:00; `g2-18` 29:00–30:00); conventional optimizers versus weak ML baselines (`g2-16` 17:00); “ring buffer wins” versus the Retina speakers' explicit request for both backends (`g2-14` 22:00); Slang enthusiasts versus users preferring CUDA or deprecated slang-torch (`g2-19` 24:00–25:00); and the unresolved Homa NIC/driver/FQ dispute (`g2-20` 28:00–32:00). These are conditional technical tensions, not claims that one speaker universally refutes another.

### 1. Dynamic mechanism compiler — a growing library of objects that remain interactive under attachment

**Seed — Q:** Takahiro Takayama: “kinematics have infinite mass”; Nintendo created “a testing room” for its mechanisms ([g2-18 transcript](../transcripts/g2-18-gdc-festival-of-gaming-tunes-of-the-kingdom-evolving-physics-and-sound.txt), 13:00–20:00, 30:00). **I:** Build a C++ mechanism IR whose implementations are dynamic assemblies with explicit actuator limits, attachment sites, material/mass rules, and operating envelopes. Models expand the retained executable library with doors, lifts, winches, compliant joints, and other mechanisms, while fixed tests place obstructions, connect loads, change step rates, and compose assemblies. The concrete value is that adding a mechanism does not reintroduce forced-motion failures into a systemic game. Jolt already supplies the primitives; the unestablished residual is the complete, checked mechanism family and its composition semantics, not the engine. The strongest objection is that arbitrary composition cannot be certified by finite simulation; reject or bound unsupported assemblies rather than claim universal physical correctness.

**One-shot test — I:** A simple gate generator/editor is prompt-sized and fails. The proposed value is the accumulated implementations plus human-owned physical contracts and stress domain; it survives only if materially different mechanisms cannot all be replaced by a small existing motor/constraint template.  
**Ambition rung — I/E:** Category-level reusable interaction substrate; a solo approximately 10× effort when limited to one engine and bounded mechanisms, rather than a complete game or physics engine.  
**Shape — I:** What grows: complete mechanism implementations and supported combinations. Oracle: an existing rigid-body solver plus independent constraint, actuator-energy, geometry, and stability checks; Nintendo's testing room is the practitioner reference, not a public oracle. Better models can implement more difficult mechanisms inside those fixed checks.  
**Six-week version / kill — E/I:** Three mechanically distinct components and one composed machine, surviving declared obstruction/load/step-size cases in a visible playground.
