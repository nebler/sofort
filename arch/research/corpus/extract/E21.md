## Recurring themes and disagreements across the share

All synthesis in this section is **I**; the cited observations/quotes are **Q** from the named transcript sections above.

1. **Useful specialization follows an explicit boundary.** Wagner's WIT/canonical-ABI boundaries address API × language effort (g1-11, 04:00–05:00). Kelley's I/O interface exposes scheduling/effects and moves buffering above dispatch (g1-13, 11:00–15:00, 20:00–25:00). Hansknecht's stable platform boundary removes most repeated relocation work (g1-16, 17:00–23:00). Wickham shows the inverse: opaque/escaped boundaries destroy optimization knowledge (g1-20, 19:00–24:00). A candidate should name which stable boundary its models extend, rather than claim that a generation loop alone is valuable.

2. **The scope of a local guarantee matters.** Gardner's foundations do not establish implementation conformance (g1-14, 31:00–37:00); Rain's local cancel safety does not establish application cancel correctness (g1-19, 13:00–20:00); timestamp monotonicity alone does not validate TigerBeetle operations (Kingsbury, g1-12, 24:00–27:00). The recurring opportunity is a concrete implementation satisfying a fixed external contract, with explicit missing assumptions. A generic “AI verifier” is already excluded by the kill list.

3. **Engineering effort is real, but often already owned.** Kelley cites 30,000 changed lines and seven redesign cycles (g1-13, 30:00–32:00). Rust-for-Linux's USB contributor is alone and short of time; compiler layout work lacks expert reviewers (g1-17, 06:00–07:00, 23:00–25:00). Hansknecht identifies DWARF and Mach-O as difficult missing pieces (g1-16, 24:00–31:00). Gardner describes maintaining old proofs while porting to a new foundation (g1-14, 11:00–18:00). These are effort-shaped seeds; none automatically establishes unclaimed ground.

4. **Oracles are present but narrower than the ambition.** ELF/DWARF rules constrain executable surgery (g1-16, 07:00–11:00, 24:00–31:00); documentation supplies Kingsbury's clean-room state model (g1-12, 25:00–27:00); Wasm's public suite is blocked by k23's absent host bridge (g1-18, 17:00–18:00); existing C USB code and a userspace interface could guide Rust work (g1-17, 06:00–07:00, 11:00–12:00). Format legality, example outputs, ABI compatibility, semantic preservation, and performance are separate checks. In particular, a Wasm engine conformance suite is **not** an oracle for arbitrary application rewrites.

5. **Cancellation can silently turn diagnostics and recovery into data loss.** Rain's harmless-looking timeout loses channel messages and `try_join` interrupts shutdown (g1-19, 00:00–01:00, 22:00–24:00). Kingsbury's interrupted/closed client crashes at the FFI boundary; his timeout discussion distinguishes definite and indefinite failure (g1-12, 27:00–30:00). Kelley wants cancellation to propagate through defer/error handling (g1-13, 15:00–17:00). The Zig and Rust accounts expose a design tension, not a controlled comparison proving one runtime correct.

6. **Execution context and progress are part of an interface.** Wagner's sync/async/shared ABI combinations require backpressure and task ancestry (g1-11, 18:00–29:00). Rust kernel contributors cannot simply resume arbitrary futures in interrupt context (g1-17, 16:00–21:00). Rain's progress cursor, persistent pinned futures, and request tasks preserve facts a plain drop would lose (g1-19, 28:00–32:00). Future interoperability cannot be judged from signatures alone.

7. **Memory cost hides in representation and lifetime choices.** Concurrent stacks make Kelley's stack buffers effectively part of a dynamic budget (g1-13, 01:00–02:00, 18:00). Rust future captures and KBox temporaries can consume large stacks (g1-17, 22:00–33:00). Kruckenberg predicts compilation under memory pressure (g1-18, 07:00). Wickham shows opaque escaping references blocking register promotion (g1-20, 19:00–24:00). The shared opportunity is reducing an actual retained-memory artifact, not simply moving it from stack to heap.

8. **Direct disagreement: future-size demand is not settled.** The Tokio maintainer reports no direct complaints (g1-17, 29:00), while embedded/custom-runtime users care and another contributor describes production stack-overflow workarounds that never became complaints (32:00–33:00). Absence of issue reports is weak negative evidence here; conversely, a pathological reproducer is not evidence of broad demand.

9. **Cooperation has performance benefits and progress liabilities.** Kelley wants caller-owned scheduling (g1-13, 03:00–07:00, 14:00–17:00); Obradovic cites lock-holder preemption and polling costs but adopts hybrid fallback against monopolization (g1-15, 10:00–13:00, 34:00–36:00, 54:00–56:00). Wagner explicitly notes poorly behaved cooperative code can block other tasks (g1-11, 21:00–23:00). “Cooperative is better” would erase the practitioners' actual tradeoff.

10. **Independent views expose combinations missing from local tests.** Four fuzzers missed intersection queries with out-of-order values (g1-12, 32:00–34:00); bit-level vs sector-level faults found different availability defects (34:00–35:00). Kelley's missing flush invalidated his apparently excellent code output (g1-13, 23:00). k23's Fibonacci test demonstrates linking but cannot substitute for the unavailable spec suite (g1-18, 17:00–18:00, 26:00–28:00). Do not sell test quantity as comprehensive semantic coverage.

11. **Observability is repeatedly hand-built at the boundary.** Component task ancestry is designed for cross-language stacks (g1-11, 19:00–21:00). Dataware implemented runtime sampling and exports data to existing tools (g1-15, 01:01:00–01:03:00). Kruckenberg explicitly changed his assessment of Wasm debugging quality (g1-18, 14:00–15:00). Gardner's group already has a student making symbolic debugging tool-independent (g1-14, 38:00–39:00). This is recurring pain, with substantial existing ownership.

12. **Measure the complete path and challenge attribution.** Roc's speed omits DWARF and some relocation cases (g1-16, 24:00–31:00). CMU participants question TonicDB's cross-engine/core-count comparisons (g1-15, 48:00, 52:00–53:00). Wickham repeatedly limits his cycle figures to estimated loop overhead (g1-20, 26:00–33:00). The defensible target is an end-to-end change with correctness and workload conditions attached.
