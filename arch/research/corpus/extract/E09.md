### Kill-list treatment

**I:** None of the five selected candidates below proposes a new durable-agent host, workflow runtime, agent compiler, classifier API, generic test selector, property-testing framework, coding orchestrator, agent web stack, preview host or per-user app generator. Those are extracted where voiced but remain occupied territory under the background brief. The narrow checks below are not novelty claims: several are best approached as an upstream fixture or a short empirical study. The earlier research's boundary-check emphasis is supporting context, not a reason to discard unrelated transcript signals; apparel, reading, office gear, language learning and organizational pain remain in the tables.

## Five most interesting candidates

### 1. Analytical integrity witness: supplied data → code → chart → prose

**Q:** Karpathy watches `NA` silently become `0.1` and then sees a prose conclusion say 1.7 trillion while the computed/plotted value is about 20 trillion (62 59:00–1:01:00). **I:** Build a small checker around a generated analysis that preserves the original table, records missing-value changes and conversions, and binds reported numeric claims to actual runtime values and units. Its output should be a concrete disagreement, such as “this missing observation became 100 million without an approved rule,” not another model's assurance that the analysis looks reasonable. **F:** [DataTriage](https://github.com/arysbey/DataTriage) already supplies explicit cleaning previews and action history. **I:** The unconfirmed opening is checking a different agent's end-to-end analysis without becoming the analyst itself. A first test is whether it catches these two demonstrated errors plus legitimate explicit imputations without flagging all transformations. This is the strongest lead because the failure is observable and the acceptance check can run without an LLM.

### 2. Research-set omission witness

**Q:** Karpathy's research table looks useful but leaves out xAI and includes entities he believes fail his requested category (62 43:00–44:00). **I:** Audit a report's entity set against an independently obtained candidate list and explicit inclusion rules, then show missing qualifying entries and contested inclusions with primary-source evidence. Start with bounded questions where the candidate universe can be checked—for example, a known registry plus a dated geographic rule—rather than promising universal completeness on the open web. **F:** [In-Cite](https://www.in-cite.com/features/completeness-audit/) already checks whether a manuscript fulfills its own promises. **I:** The distinction is discovering something the report never mentioned; another model rereading the same report cannot supply an independent completeness check. Status remains **Unclear**, and the first kill test is whether users find these omissions often enough to value a separate audit.

### 3. Web Serial reconnect transition witness

**Q:** A listener's ESP32-S3 smartwatch IDE loses its connection when flashing crosses into bootloader mode (53 31:00–33:00). **F:** [ESPP](https://esp-cpp.github.io/espp/web_apps.html) already documents automatic reconnection to permitted devices and separately handles a bootloader that appears as a different USB device. **I:** The opportunity is a small diagnostic harness that records browser/OS, runtime and bootloader identities, granted ports, disconnect/connect events, ownership by other tabs and the exact step that requires renewed interaction. It should distinguish a recoverable permitted-port reopen from an identity change or unsupported browser behavior. This directly tests the host's overly broad diagnosis before anyone writes an unnecessary desktop wrapper. It fits the builder's transition-testing experience, but reconnect itself is already shipped and the likely output is a shared browser/device fixture corpus, not a new flashing platform.

### 4. GPUI accessibility and visible-behavior conformance fixtures

**Q:** Scott already built a patched accessibility-tree tester, while his own app cannot easily enlarge text and native interactions do not come free (57 21:00, 27:00–30:00). **F:** [GPUI Kit](https://github.com/longbridge/gpui-kit/blob/8aa9f29c4c275320bd66d3e33c9eb9634cbadc70/docs/ACCESSIBILITY-UI-TESTING.md) now gives concrete macOS keyboard, focus, action and evidence instructions. **I:** Preserve that work and investigate only the gap between “the tree exposes a control” and “the control behaves correctly in the actual platform”: stale identities after rerender, focus after dialogs, read-only editing, undo boundaries and scaling/clipping. A tiny corpus could compare headless assertions, real accessibility actions and observed outcomes on the same control. Demand comes from a practitioner who wrote his own patch, but the broad testing tool is occupied; this is most plausibly an upstream conformance contribution, with cross-platform differences still to verify.

### 5. False-negative audit for semantic quality-check selection

**Q:** Adam proposes skipping accessibility review when a classifier decides no front-facing code changed (55 44:00–45:00); the hosts also experience costly browser verification (53 16:00–17:00). **I:** The interesting question is not how to skip more checks but how to expose an incorrect skip: shared styles, generated content, feature flags, dependency changes or a backend message can alter UI behavior without an obvious UI-file diff. Run the proposed selector in shadow against a small, owner-maintained accessibility/interaction corpus and show the first omitted check that detects a real regression. **F:** [CodeyBox](https://github.com/AdamFrisby/CodeyBox/blob/main/docs/quality/audit.md) already implements shadow selection and unsafe-skip accounting for general tests. **I:** Therefore the generic mechanism is taken. Keep this candidate only as a narrow semantic-selector evaluation or upstream adapter; kill it if existing shadow validation plus ordinary impact analysis catches the same cases at comparable cost.
