## Recurring themes across this share

All themes below are **I**, grounded in the cited **Q** signals; they are not additional verified market facts.

1. **The agent's missing information often matters more than raw intelligence.** Handoffs lose context (65 11:00–12:00; 68 05:00–06:00), generic data agents miss company semantics (68 15:00–16:00), and capable models encounter decisions absent from the user's map (70 09:00–13:00). Every's agents likewise need job-specific taste and recipient knowledge (73 21:00–23:00; 29:00). Potential seam: evidence of which assumptions survive a handoff or change.
2. **Temporary harness tricks need an expiry mechanism.** Cursor removed coding guardrails and tracks shim activation (66 03:00–06:00; 16:00); Anthropic removed 80% of a system prompt (70 06:00); Factory revisits its harness monthly (72 08:00–09:00). The reported bot deletes inactive shims, but no speaker describes a controlled proof that an inactive shim is obsolete rather than unexercised.
3. **Generation is moving faster than acceptance evidence.** Warp names review the painful stage (69 11:00), Bun needs sufficient proof and rollback confidence (71 16:00–17:00; 25:00–28:00), Stripe relies on hard invariants (75 04:00–06:00), and PlanetScale distinguishes recoverable schema changes from harder database operations (78 11:00–12:00; 16:00–17:00). The acceptance check must identify the intended behavior and actual executed artifact, not simply count green checks.
4. **Learning from repeated work is already hand-built, across domains.** Pi/Prime/Hermes examples modify memory/skills (63 07:00–11:00); Vercel mines recurring query shapes into about 100 skills (68 10:00–11:00); Warp proposes learning from corrected review comments (69 14:00); Every learns from editorial corrections (73 07:00–11:00; 20:00–23:00). The extraction does not claim skill generation is open. A narrower question is what invalidates a learned rule after its source schema, definition, audience or authority changes.
5. **Shared resources create causal effects that request-local views hide.** Independent CPU-cluster routing can overload the same engine (64 08:00); incast delays short RPCs behind large transfers (67 06:00); a request's batchmates change each token (76 04:00–05:00); device telemetry lacks workload mapping (77 03:00–04:00); combined database/queue/analytics workloads contend (78 09:00–10:00). Each asks for attribution across boundaries rather than another average utilization graph.
6. **Adaptive feedback can amplify the problem it is meant to solve.** Inference weights oscillate and disrupt caches (64 06:00–07:00), sender congestion control chases stale information (67 08:00–10:00), retries can cause storms (64 16:00–17:00), and overload protection needs cooperating callers (78 09:00; 14:00–15:00). A shared opportunity is counterexamples for specific policy combinations; general routing/control infrastructure already has owners.
7. **Optimize cost of a successful outcome, including context and people.** Multi-model context can be charged repeatedly (65 11:00), cheap models can thrash (65 14:00–15:00), harnesses change cost even when scores are similar (66 13:00), factory efficiency includes human time (69 13:00), and Shopify separates development capability from production economics (74 10:00–11:00). Token price alone is an inadequate denominator.
8. **Local/cloud execution is also an operational and attention question.** Sleeping laptops cannot support days-long agents (66 12:00; 17:00), Vercel packages execution/durability/connectors (68 12:00–14:00), Every abandoned maintaining personal agents and moved to managed primitives (73 03:00; 13:00–16:00), and Stripe already operates VM-based Minions (75 03:00). Generic cloud hosting is occupied and kill-listed.
9. **Human attention becomes the scarce queue.** Autonomous colleagues must communicate without overwhelming people (66 09:00), factory work gets stuck at human gates (69 08:00–11:00), permission prompts strand overnight work (71 22:00; 29:00), and Every faces editorial-trigger/inbox overload (73 06:00) plus the question of when an agent should interject (73 25:00–26:00). Timing has direct research prior art; see P07 below.
10. **Shared agents spread expert practices but complicate identity.** A data team serves many business functions (68 02:00–03:00), Every consolidates personal investment into one Slack coworker (73 11:00–12:00), yet requests still require different memories/access and delegated connector identities (73 16:00–20:00). Cursor similarly calls for person/agent-scoped permissions (66 12:00–13:00), and Stripe enforces granular semantic data boundaries (75 05:00–06:00).
11. **Stable primitives matter as features turn over.** Everything becomes a plugin (63 03:00–06:00); Cursor packages subscriptions for unrelated wakeup sources (66 15:00–16:00); Vercel uses skills/tools/channels conventions and adapters (68 12:00–14:00); PlanetScale's existing JSON, branch and deploy interfaces become agent interfaces (78 13:00–18:00). The interesting checks are at primitive combinations and lifecycle transitions, not a new wrapper around the primitive.
12. **Capability gains require repeated recalibration by humans.** Anthropic describes discontinuous tool/clarification/output abilities (70 03:00–08:00), Cherny finds frequent model changes difficult to internalize (71 18:00), Every manually work-trials each model (73 10:00–11:00), and Collison describes learning plans, goals and multi-day delegation (75 11:00–12:00). A task-specific change log is more actionable than a global leaderboard.
13. **More software is not necessarily more value.** Warp warns about efficient factories nobody wants (69 19:00–20:00), Anthropic says value remains hard (70 18:00), Factory asks if 300 features improve customers' lives (72 06:00), Shopify distinguishes ceiling from floor (74 01:00–03:00), and Stripe separates product count, quality per PR and incidents per time (75 03:00; 09:00). Measurement should retain those different denominators.
14. **New granular workloads invalidate old instrumentation assumptions.** Small RPC tail latency can idle a whole GPU barrier (67 03:00–05:00), prefill and decode need separate SLOs (76 07:00–08:00; 22:00), and accelerator percentages need explicit vendor/mode definitions (77 10:00–16:00). More precise measurement can remain useful even as model reasoning improves.

### 1. P01 — Evidence that a model-specific shim can be retired

**Q:** Katz already centralizes shims, logs activation and has a bot propose deletion when they stop firing (66 16:00); Anthropic removed much of a system prompt (70 06:00), and Factory rethinks harness design monthly (72 09:00). **I:** Build a retirement report distinguishing “this behavior no longer needs help” from “this workload stopped exercising it.” Record eligible opportunities as well as firings, compare shim-on/off behavior on preserved episodes, and retain human-owned outcome checks and a rollback trigger. The surprising seed is that deleting harness code is now recurring operational work. This extends the internal bot's acceptance evidence rather than recreating the bot. **Prior art/status:** Unclear for that exact pack; the deletion mechanism itself is already built internally (Q). **First disproof:** replay one known obsolete and one rare-but-needed shim; if simple counters already distinguish them reliably, the project collapses to an existing telemetry recipe.

### 2. P02 — A GPU telemetry upgrade contract that checks meaning

**Q:** HAMi's speaker reports GPU-operator changes breaking metrics, unsupported modes, missing workload identities and uncertainty about metric confidence (77 10:00–16:00). **F:** HAMi already documents metric compatibility and runtime identity joins; its per-Pod utilization design includes tests and a vendor-specific non-goal ([dynamic MIG design](https://project-hami.io/docs/developers/dynamic-mig), [utilization design](https://project-hami.io/docs/developers/gpu-utilization-metrics)). **I:** Run a tiny known workload before/after an operator/driver/HAMi upgrade and assert unit, scope, denominator, workload identity and “unknown versus zero” behavior. A series merely existing under the same name should not count as success. This is interesting because quietly changing telemetry can invalidate both utilization economics and incident diagnosis while the application keeps returning success. **Prior art/status:** Being built in adjacent HAMi work; the narrow deliverable should first be proposed as fixtures upstream. **First disproof:** existing HAMi/operator end-to-end tests already assert these semantics across supported release combinations.

### 3. P03 — Measure the small-message coordination tax before changing transport

**Q:** Ousterhout says millisecond compute phases can lose a significant fraction of GPU time to small synchronization messages, and asks users whether this actually limits their throughput (67 03:00–05:00; 17:00). **F:** Homa itself and performance tooling already exist ([repository](https://github.com/PlatformLab/HomaModule)). **I:** A read-only application diagnostic would correlate short-RPC completion tails, barrier critical paths and GPU idle intervals, then replay a measured message-size/incast distribution in a small transport experiment. Its output should separate observed waiting from an explicitly assumption-bound estimate of recoverable time; a 13× RPC benchmark does not imply a 13× application win. The seed is a specific workload transition, not a claim that TCP replacement is unbuilt. **Prior art/status:** Unclear for the application-level preflight; Homa and generic profilers are substantial prior art. **First disproof:** an existing profiler already produces this attribution for the target inference stack without bespoke instrumentation.

### 4. P04 — Prove the red/green test ran the intended executable

**Q:** RoboBun cannot submit a fix without a failing old-version test and passing new-version test, but Sumner also needs a special build/run command to avoid a stale debug binary (71 02:00–03:00; 08:00). **F:** Hermetic build systems already constrain test dependencies and runtime artifacts ([Bazel test specification](https://bazel.build/reference/test-encyclopedia)). **I:** For repos outside that discipline, emit a compact witness connecting source revision, build inputs, executable identity, command/process chain and both test outcomes. Detect the concrete false proof where “head passes” actually ran yesterday's binary or an installed system executable. This is small, directly motivated and independently checkable; it does not invent testing or prove that the patch satisfies all intent. **Prior art/status:** Unclear for a portable witness wrapper, with strong build-system prior art. **First disproof:** Bun's helper or existing build metadata already captures all necessary identity, making a report-only addition sufficient.

### 5. P05 — Invalidate a learned data skill when its meaning changes

**Q:** Vercel distills repeated queries into roughly 100 skills and credits company knowledge, not generic SQL generation, for its advantage (68 10:00–11:00; 15:00–16:00). Every likewise compounds real corrections into shared expertise (73 07:00–11:00; 20:00–23:00). **I:** Preserve each data skill's original queries, semantic definitions, joins and source versions; when those inputs change, identify the affected learned assumptions and run small owner-approved reference cases before promoting the skill again. The key failure is a query that still executes but now answers the old meaning of “customer,” “active” or “revenue.” This packages maintenance of learned company knowledge, rather than the already-taken skill-generation loop. **Prior art/status:** Unclear after a weak single-query check; data catalogs, semantic-layer lineage and skill stores may already cover most of it. **First disproof:** an existing catalog can connect generated skills to metric-definition lineage and invalidate them with semantic reference cases, without new machinery.
