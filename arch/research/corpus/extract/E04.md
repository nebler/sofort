## Five most interesting candidates

These are **I** project proposals anchored to **Q** practitioner evidence. “Interesting” is not “novel”: the shallow prior-art checks leave all five conditional. None is a repitch of the kill list's broad agent hosting, migration, generic replay, code generation, authorization or proof-generation categories. The scope boundaries below matter.

**1. Changed-opinion index for author bots (P09).** **Q:** GB actually tried a bot based on his writing and found it repeated years-old views; the same interview supplies a live example in revised TLM advice (18 1:39:00–1:40:00, 1:48:00). **I:** Build a small author-facing tool that groups claims about one subject, presents possible changes with dated excerpts, and lets the author mark “superseded,” “still applies in this context,” or “uncertain.” Retrieval returns the current approved view alongside relevant historical context instead of silently favoring a newer chunk. **F:** Graphiti already provides temporal facts/provenance, so the potential project is the reviewable opinion/applicability workflow, not a new memory engine. This is surprising because the failure is faithful retrieval of something the author really said. First check whether existing author-bot products already expose equivalent controls.

**2. Management incentive preflight from concrete failure cases (P10).** **Q:** WL has seen resource approvals create server hoarding, mentoring criteria create collected mentees, surveys become targets and level caps require upstream hiring changes (18 11:00–12:00, 55:00, 1:02:00–1:05:00). He describes incentive management as part of his actual executive work (1:27:00). **I:** Package these as executable or structured case reviews: enter a proposed policy, identify what behavior it rewards, list feasible workarounds, and require the policy owner to answer a few analogous historical cases. It should expose assumptions and counterexamples, not claim to forecast employees or produce personnel decisions. The interesting piece is a reusable corpus of real incentive failures with the policy's intended outcome kept separate from its measurable proxy. The one search found no close primary match; agent-based organizational simulation and management consulting are substantial unchecked prior art.

**3. Supported-combination coverage ledger (P05).** **Q:** Uday's actual concern is validating many combinations, including a narrow case such as Brazilian cash trips, and Capri/Match Guard derives live combinations from production data (19 1:07:00–1:10:00). **I:** The proposed extra layer compares a team-owned support matrix with captured, replayed and recently passing combinations, so “not seen” is visible separately from “tested successfully.” A new city, flag value or payment method could immediately show which supported interactions lack evidence. **F:** Capri already exists internally; Keploy supplies replay; NIST supplies combinatorial coverage methods. The candidate therefore has to be a small integration/report over business support claims and existing test evidence. The gap is an inference from the limits of observed traffic, not a complaint Uday explicitly makes about Capri. Check this exact feature in existing replay/experimentation tools before proceeding.

**4. Cross-screen design exception inbox (P07).** **Q:** Imprint's engineering-led design removed a bottleneck but created gaps, unclear responsibility and design-system misuse; WL wants designers reviewing exceptions and says they have not yet reached it (18 39:00, 1:14:00–1:16:00). **I:** For an implemented flow, collect the few unresolved decisions a component library does not settle: inconsistent behavior across screens, a missing pattern, changed user expectations or an intentional departure. The potential slice is semantic flow decisions and ownership after implementation, not another visual linter or UI generator. It is attractive because the practitioner names both the desired operating model and the current failure; it is also explicitly work Imprint is pursuing.

**5. A useful project must therefore join those evidence types in an actual coding workflow or supply a validated assessment design that those tools lack. This is interesting as a practitioner-proposed change to what counts as a software-engineering artifact, but the broad “grade prompts” pitch is already taken and observed process can still be fabricated or misunderstood.
