## Decision

**I — ONE pick: a public Package Behavior Atlas, built from real downstream executions across package releases.** Its unit of value is a reusable observation with an executable witness, environment, provenance, and a stated limit. Begin with JavaScript; ultimately cover npm, PyPI, and crates. The ambition is to make the ecosystem's effective behavioral specification available to everyone replacing, upgrading, or reimplementing its foundations. The small runner is expendable. The accumulating evidence is the project.

**E — Six-week commitment:** one person at roughly ten hours/week; 40 packages, eight releases each, three downstream contexts, two pinned Node environments, three repetitions: **5,760 bounded jobs**. Publish the observations, rejected cases, and coverage denominator; demonstrate a previously undocumented downstream behavioral dependency and have an outside maintainer reproduce a permitted witness. Expected cash spend **about $570**, with a **$1,000 stop limit**. Execution itself is about $171 including a 25% retry allowance; agent inference is budgeted at $300. These are workload assumptions to test, not purchased capacity or measured throughput.

**I — Runner-up:** continuous database/queue fault evidence. It has an unusually direct practitioner seed and a credible long-term purpose, but independent semantic models and vendor-specific fault assumptions make adjudication harder for this builder's available time. **Most crazy-but-not-impossible:** a continuously maintained record of the executable claims in published computational research. Literal universal coverage fails on missing inputs, rights, and extreme compute requirements; an expanding, explicit coverage frontier survives.

## The AlphaFold analogy, used carefully

**Q:** Richard Campbell, [After the AI Hype, 48:00](https://www.youtube.com/watch?v=uWnUnMphmPM&t=2880s): “published them for free”; “It will take us decades to even know everything that we've gotten from this data set.” He describes a collection of roughly 200 million predictions. **F:** AlphaFold DB supplies predictions with confidence measures and documented limitations; it does not establish universal experimental truth. Campbell's medical examples and universal-accuracy rhetoric are not premises of this report. [AlphaFold DB FAQ](https://www.alphafold.ebi.ac.uk/faq).

**I:** The transferable move is to amortize costly work across a field, release its results openly, and let unforeseen uses compound. Software requires a different object: an observation about a particular artifact, input, environment, and date. There is no universal fingerprint of an arbitrary program's complete behavior. A hash of one run can identify a trace; it cannot certify semantic equivalence. The four candidates below therefore publish bounded evidence and explicit unknowns.

**I — What agents change:** hardware could already run these experiments. The historical obstacle was engineer time per independently executable case: recover a build, discover a meaningful input, adapt a downstream workload, understand a failure, and reduce it. Agents can make those tasks cheap enough for a solo campaign. This is an economic hypothesis, with a cheap rejection experiment, rather than a claim that continuous testing was technically unavailable. If the human setup/adjudication cost remains linear and high, the solo opportunity disappears even when the cloud bill is tiny.

**I — Why accumulation matters:** a new release, runtime, driver, dependency resolution, or failure history creates a new observation. Historical records remain useful for attribution and comparison. Cache immutable results; add new coverage and selectively revalidate environments. Running identical immutable cases forever would waste compute. Future models may internalize old public records, but cannot obtain tomorrow's executions, a private consumer's observations, missing artifacts, or a maintainer's acceptance decision from yesterday's weights. This is a public utility argument, not a claim of a permanent proprietary moat.

## Candidate 1 — Package Behavior Atlas

### Seed and field-scale outcome

**Q:** Giorgio, Module Federation, [ViteConf 4:24–4:26](https://www.youtube.com/watch?v=PfyIEgLzNYI&t=15840s): “two engine under one API”; “more than 12 frameworks.” The supplied captions describe internal graph differences and checking multiple downstream configurations on every change. **Q:** Alex Rickabaugh, Angular, [9:14](https://www.youtube.com/watch?v=PfyIEgLzNYI&t=33240s): “even those bugs have users”; [9:20](https://www.youtube.com/watch?v=PfyIEgLzNYI&t=33600s): testing the compiler on Google's Angular applications. **Q:** Casey Muratori, [The Big OOPs conversation, 53:00](https://www.youtube.com/watch?v=LgvH67G4iL8&t=3180s): “unstable, unpredictable software.” These are independent practitioners; the two ViteConf speakers share a publisher.

**I — Vision:** a publicly downloadable experimental account of the software ecosystem. Ask what observable behavior changed between releases, which actual consumers rely on it, and which replacement implementations have been exercised against those contexts. A framework/compiler rewrite can consult and extend a shared behavioral frontier instead of rediscovering the same installed-base assumptions. Package maintainers, runtime teams, migration tools, and agent builders can all consume the same records without running the generating agent.

**I — Record:** artifact hash and source identity; dependency closure and override; consumer revision and permitted workload; runtime/OS/architecture; relevant inputs and observable effects; repetitions; setup failures; reduced witness; maintainer interpretation; execution date. Preserve both raw and normalized output. A normalization rule can hide a bug, so it needs its own version and review. Keep “different,” “breaking for this consumer,” and “accepted contract” as distinct assertions.

### Why now; one-shot test

**I:** Vite CI and Crater show that narrow ecosystem experiments were already possible. The newly plausible ambition is recovering and maintaining the heterogeneous long tail of meaningful consumer cases with one person's supervision: agents reconstruct old environments, extract observed calls, adapt bounded workloads, and reduce failures. The check is a real downstream execution against frozen acceptance cases, not the adapter author's prose or a second model's vote. Whether agents achieve the necessary labor reduction remains an experiment.

**I — Non-code value:** accumulated artifact/environment observations, independently useful witnesses, and relationships with consumers who accept the interpretation. A stronger model can write the runner and many fixtures; it cannot infer an unobserved hidden dependency or authorize the compatibility policy. Better models reduce the cost of adding evidence. They can also make easy public observations cheap to regenerate, so historical bulk alone provides weak protection. Continued coverage and actual use must justify the commons.

### Physics, economics, data, and law

**E:** the six-week matrix is `40 × 8 × 3 × 2 × 3 = 5,760` jobs. At six minutes/job on 2 vCPU/4 GiB, it needs 576 runner-hours; allow another 144 for setup/retries. Price: about **$570 all-in**, detailed below. At 30–80 W of allocated host power per active runner, 720 hours represents roughly **22–58 kWh**, excluding model inference and storage. This power range is a planning assumption, not provider telemetry.

**E:** a hypothetical archive of **100 million releases**, one six-minute observation each, costs about **$2.38 million** at the same public sandbox rate. Three consumer contexts × four environments × three repetitions raises this to **$85.7 million** before inference, retention, and engineering. These are planning volumes, not a registry census. A selected million-release monthly sweep with three contexts/two environments/three repetitions is roughly **$428,000/month**. Whole-ecosystem richness needs institutions or downstream sponsors; the initial useful slice does not.

**I:** do not enumerate the Cartesian product of every dependency version. Preserve real lockfiles, perturb one target at a time, and expand around observed interactions. State the sampling boundary. Content hashes can reuse identical artifacts, but setup failures, operating-system needs, native builds, and missing historical dependencies can make the six-minute mean wrong by an order of magnitude. Measure that mean in the rejection experiment.

**F/I:** deps.dev and archive services provide discovery inputs; registry source releases often omit upstream tests. Use licensed public downstream projects and their actual permitted tests. Retain license attribution and separate authored measurements from copied code, fixtures, and generated artifacts. Public visibility is not a blanket redistribution permission. [Software Heritage's reuse guidance](https://www.softwareheritage.org/software-heritage-faq/), [GitHub's license guidance](https://choosealicense.com/no-permission/). Begin without private applications; a later participant may publish permitted aggregate results while retaining its code, but that weakens public reproducibility and must be labeled.

### Six weeks; decisive demo; rejection

**I/E:** weeks 1–2: choose module loading, resolution, URL handling, and transformation packages from a real JS application graph; recover 20 trial contexts; fix the observation schema and two runtime environments. Use existing CI/test adapters wherever possible. Freeze acceptance cases before an agent adapts a version. Weeks 3–4: grow toward 40 packages/eight releases, run the matrix, and reduce stable differences. Weeks 5–6: independently rerun the strongest witnesses on clean machines, obtain a maintainer's interpretation for a permitted case, and publish a downloadable corpus plus queryable index. No novel runtime, orchestrator, or package manager is required.

**I/E — Demo target:** select a version pair with unchanged nominal API and passing package tests; show a real consumer outcome that differs, its earliest observed release boundary, and a small reproducer. The index exposes both the useful finding and the untested contexts. A single incompatibility hidden in an existing issue tracker is not novel evidence; the contribution needs a previously unrecorded exposure/consumer relation or recurrence, checked against existing tests and reports. If nothing new appears, say so and contribute the useful cases upstream.

**I/E — Cheapest rejection experiment:** two part-time days, **$40 ceiling**. Try 20 contexts outside existing Vite ecosystem suites and hide five known historical regressions from the setup agent. Require at least 14 useful executable contexts, recovery of four hidden regressions, and no more than ten minutes of human setup per successful context. Sample stable differences manually; stop if most are irrelevant serialization noise, setup artifacts, or already answered by existing ecosystem CI. During the full pilot, require at least two independent potential users to identify a concrete upgrade/rewrite decision the evidence would change. These are proposed thresholds, not statistical guarantees.

**I — Strongest objection:** behavior is infinite, consumer coverage is biased, and maintaining the adapters may cost more than rerunning ordinary tests. That objection kills the universal semantic certificate. It does not kill a finite shared body of useful observations, provided coverage and marginal decision value are measured. **Builder fit:** excellent TypeScript/compiler/Wasm adjacency; Rust is useful for reduction or isolation helpers. Host the index on Cloudflare, rent execution elsewhere. Do not spend the pilot building a VMM or growing a bespoke OS. This is outside GrowOS.

**I — Vision:** operators can retrieve a version/configuration/fault/workload history before choosing or upgrading a database or queue. Maintainers add a release and reuse an independently checked model plus the accumulated failure collection. Publish precise exposure: lost acknowledged state, duplicate effects, incomplete reads, recovery time, and unavailable results under a named fault contract. Retain repaired failures and test whether they return. This could change how reliability claims are compared across the field.

### Why now; one-shot test; closest attempts

**F/I:** Jepsen already states almost this exact aspiration and identifies months of expert work per analysis. Antithesis already supplies powerful continuing execution. The possible economic change is agents handling release packaging, adapter drift, version bisection, fault configuration, and witness reduction, while a small trusted set of independently reviewed semantic models is reused. A new fault injector or deterministic hypervisor would duplicate occupied machinery.

**I — Non-code value:** accepted API/fault contracts, real failure histories and minimized schedules, independent reproduction, and continuing maintainer/operator trust. A better model may build adapters, but it cannot declare a database's undocumented storage assumptions valid or turn an ambiguous timed-out write into an acknowledged commit. Those facts must be observed or settled by the protocol. The commons must allow disagreement about its oracle.

### Physics, economics, data, and law

**E:** six weeks can cover two engines × four releases × three fault families × 30 seeds × 20 minutes: **720 trials / 240 cluster-hours**. Three nodes per cluster, estimated at **$0.50/node-hour** for 4 vCPU/8 GiB with necessary VM privileges: **$360**, plus $90 replays, $300 inference, and about $100 for control, storage, and transfer: **$850**, **$1,500 ceiling**. The node price is a conservative planning allowance, not a quoted Modal VM product. Start with process termination, partitions, and supported recovery; raw disk corruption and clock manipulation require suitably controlled VMs and additional qualification. Provider sandbox pricing does not imply those capabilities.

**E:** allocated host power of 60–160 W/node gives roughly **54–144 kWh** including 25% repeat work. A much broader annual program—200 engines × 24 releases × six fault families × 200 seeds × half an hour × five nodes—costs about **$7.2 million/year** at the same node allowance, before semantic audits, support, and storage. This is expensive field infrastructure, not physically implausible. Passing sampled seeds is never a proof of reliability; repeats sharing seeds or executions are not independent statistical samples.

**I:** code and existing public harnesses are available for a starting slice. Configuration, acknowledgment semantics, client retries, and actual faults must be recorded. Separate loss of availability from safety violations. Never inject a storage fault outside an engine's advertised assumptions and rank the outcome as an ordinary contract violation. Self-host public releases on owned test capacity; respect each engine/harness license and publish only resolved, permitted disclosure material. Managed services and customer incidents add access terms and permission barriers rather than free coverage.

### Six weeks; decisive demo; rejection

**I/E:** choose two engines with usable existing Jepsen harnesses and a shared, narrow operation such as an acknowledged register or append history; compare each to its own documented model. Weeks 1–2 validate models using known failures and a deliberately invalid history. Weeks 3–4 run the release/fault matrix and classify infrastructure failures. Weeks 5–6 rerun findings, retain raw histories, and publish a cross-release record with vendor-specific assumptions. If a queue enters later, its delivery/acknowledgment model gets a separate checker; do not impose database linearizability on it.

**I/E — Demo target:** a previously unmeasured repair-survival boundary across releases and recovery settings, with a small reproducible history and an operator-relevant conclusion. It need not be a new vulnerability. An honest result that two promised fault models cannot be compared may be more useful than a ranking.

**I/E — Rejection experiment:** **$75/two days** to recover a known historical fault with an existing harness and validate its checker against a hand-constructed invalid history. Stop if the oracle cannot distinguish client/harness mistakes from engine failures, release adaptation consumes more than an hour of human attention per version, or the result changes no operator decision. **Strongest objection:** the expensive part was Kyle's independent model and judgment, not deployment scripts. **Builder fit:** strong systems/Rust/VMM fit, but that expertise creates a temptation to build testing infrastructure instead of a trusted corpus. Clojure/Jepsen reuse is more useful than rebuilding it in the preferred stack. Outside GrowOS.

## Candidate 3 — A public record of real defects, fixes, and recurrence

### Seed and field-scale outcome

**Q:** Ray Myers, [Code Worth Writing, 40:00](https://www.youtube.com/watch?v=mZgglPK8Rg0&t=2400s), describes “surveying 48 memory bug fixes” and says “Any fix is a missed convention.” His claimed 50 discovered bugs remain an attributed result. [Supplied caption span](/Users/noah/code/sofort/arch/research/corpus/transcripts/p3-20-software-should-work-code-worth-writing-ray-myers-ssw-2026.txt:44). **Q:** Adam/Uber and Chris/Faire, [factory discussion, 40:00–42:00](https://www.youtube.com/watch?v=0gDHnH89aQs&t=2400s), distinguish captured human feedback, unwanted comments, missed defects, and the aspiration that “recall approaches 100%.” [Supplied caption span](/Users/noah/code/sofort/arch/research/corpus/transcripts/p3-18-warp-from-coding-agents-to-software-factories-with-uber-and-faire.txt:44).

**I — Vision:** a million-scale, continuously refreshed epidemiology of observed software defects: original report, introducing interval when known, triggering input, executable failure, accepted requirement, repair, affected release interval, later recurrence, and competing explanations. Researchers could ask which failures survive test suites or return after rewrites; maintainers could check a fresh release against the historical cases that apply. Training and repair evaluation become downstream uses of this evidence rather than the reason to accept a questionable case.

**I — Bound:** an exhaustive inventory of every real bug is not attainable: unknown bugs and unspecified intent do not supply ground truth. The viable ambition is broad, open-ended coverage of independently supported observed defects. “Merged fix” is a candidate label, not proof. Preserve “not reproducible,” “expected behavior disputed,” “environment unavailable,” and “fix addresses only this input” as useful outcomes.

### Why now; one-shot test; closest attempts

**F/I:** Defects4J/BugsInPy already supply reproducible bug/fix pairs; SWE-bench-Live and SWE-rebench already add freshness; SWE-Factory already automates environment construction. OSS-Fuzz/CodeMender already joins discovery to checked patches. Thus a bug corpus generated by agents is not a newly available category. The residual candidate is a maintained record of defect lifetimes, trigger/exposure conditions, and recurrence across successors, with admission based on direct evidence and independently held acceptance conditions.

**I — Non-code value:** authenticated incident/report provenance, repeated executions, independent adjudication of intended behavior, and histories that accrue as releases arrive. Newer models can reproduce many easy public cases, and their vendors already fund large collections. A static set of patches is especially vulnerable to commoditization and contamination. Maintain the longitudinal record openly or contribute to an existing dataset; do not pretend an agent-written scraper constitutes the asset.

### Physics, economics, data, and law

**E:** six weeks: screen 200 bug-fix candidates from a few permissively licensed projects; target 60 admitted cases and at least ten successor-release trajectories. Budget six environment/test variants × three repetitions × ten minutes per candidate: **600 runner-hours**, plus 150 retry hours, about **$178**. Forty million input/four million output tokens cost **$120** at the stated model tariff. Allow $100 for storage/control: **about $400**, **$800 ceiling**. Estimated execution power: **23–60 kWh**. Screening can fail long before admission; do not quote $400/60 as a verified acquisition cost.

**E:** one million cases at the same 18-job execution budget plus 100,000 input/5,000 output tokens per case is approximately **$964,000**, before human adjudication and storage. If each admitted record needs 15 human minutes, a million records need **250,000 human hours**. That is the real scale warning. Reuse trusted upstream cases and record their provenance instead of claiming every imported case was newly adjudicated.

**I:** preserve original buggy/fixed trees, the executed artifact identity, and tests outside the repair agent's authority. Check failure before the patch, success afterward, and survival of relevant unaffected behavior. A fix that deletes the operation or changes the test must not silently pass admission. Reverting the relevant repair can support causal attribution, but cannot by itself establish that a bundled commit repaired the originally reported requirement. Distinguish original tests from new inferred tests; mark the latter provisional until independently supported. Unpublished security reports, private tickets, personal information, and restricted fixtures stay outside the public dataset without authorization.

### Six weeks; decisive demo; rejection

**I/E:** begin with ordinary non-security defects in a small JS/Rust selection. Weeks 1–2 implement admission through an existing dataset harness and validate known cases. Weeks 3–4 admit cases and test several later releases. Weeks 5–6 have an independent user rerun selected trajectories, publish rejected candidates, and compare the additional fields directly to SWE-rebench/Defects4J. The distinctive demo is a documented failure → repair → later return, with unchanged externally meaningful acceptance, or a precise difference between the claimed and experimentally observed affected-version interval. Do not require a newly discovered security bug.

**I/E — Rejection experiment:** **$50/two days**, ten cases. Ask a repair/testing researcher to use the extra temporal/exposure evidence for a real question. Stop the standalone idea if it reduces to ordinary fail-to-pass task curation, if relevant recurrence cannot be checked without rewriting the oracle, or if maintainers disagree about the supposed defect. **Strongest objection:** this is a crowded training-data business disguised as a commons, while independent labels remain expensive. **Builder fit:** good systems/compiler fit; weak advantage over established corpus teams. A contribution to existing collections is the default outcome. Outside GrowOS.

## Candidate 4 — Recompute Atlas: an executable record of published claims

### Seed and field-scale outcome

**Q:** Jonathan Blow, [language-design conversation, 1:10:00](https://www.youtube.com/watch?v=e6crOMC9WCE&t=4200s): “I want my software to compile 10 years from now on an island when I have no internet.” Campbell's [48:00 AlphaFold account](https://www.youtube.com/watch?v=uWnUnMphmPM&t=2880s) supplies the companion ambition of a freely reusable result collection whose consequences accumulate.

**I — Vision:** every eligible computational publication has a lasting claim-to-execution record: which released artifact and inputs produced which table/figure, under what environment and tolerance; what survives an offline rebuild or contemporary environment; what failed or became unavailable; which repairs were necessary and whether those repairs changed the method. Journals, scientists, and new implementations can retrieve evidence instead of independently spending days discovering the same broken download. Historical software remains an exercised capability, not merely preserved text.

### Why now; one-shot test; closest attempts

**F/I:** Software Heritage, Reproducible Builds, Code Ocean, ReScience, CORE-Bench, RECLAIM, and Artisan cover important parts already. The underlying activity was never absent. Agent-driven environment rehabilitation and reproduction scripts make a much broader, continuing coverage frontier plausible. The independent check must anchor to a predeclared published numerical result, original input, and a field-appropriate acceptance condition. A model interpreting another model's report does not supply that anchor.

**I — Non-code value:** preserved lawful inputs and toolchains, measured results, independently supported claim mappings, and observations of survival or loss over time. A stronger model can repair code but cannot infer a missing raw dataset, recreate an inaccessible historical service's true answers, or supply rights to redistribute a model checkpoint. Ten years of future survival cannot be demonstrated in six weeks; historical loss and present-day reconstruction can.

### Physics, economics, data, and law

**E:** six weeks: 20 CPU-bounded papers, one explicit claim each, three environment conditions, two separately prepared clean machines, three repetitions: **360 attempts**. At one hour/attempt on 4 vCPU/8 GiB, execution is **$171** at the sandbox reference rate. Forty million input/four million output tokens: **$120**. Optional GPU checks: **100 A100 hours × $1.79 = $179**. Allow roughly $180 for retention, transfer, repeat work, and control: **about $650**, **$1,200 ceiling**. Separately prepared machines operated by the same person are repeatability evidence, not independent scientific review. Obtain external reproduction of a small permitted subset if participants are willing.

**E:** execution power is roughly **22–58 kWh** for the CPU work plus **40–80 kWh** for 100 allocated GPU-host hours, excluding agent inference. At a hypothetical million-paper scale, eight vCPU-hours/paper would cost about **$952,000** at the CPU reference rate. A cohort instead needing 100 A100-hours/paper would cost **$179 million**. Neither average describes all research: some papers require enormous training runs, proprietary data, instruments, or services. A petabyte of retained inputs is another **$15,000/month** at the R2 storage tariff, before a geographically independent copy and curation.

**I:** kill the literal promise to reproduce all published research code. Missing inputs, rights, unavailable apparatus, and unbounded workload costs cannot be repaired by optimistic scheduling. Keep a public denominator with attempted, unavailable, over-budget, reproduced-with-original-artifact, and reproduced-after-repair states. A passing container is not scientific replication; a matching numerical result is not evidence that the research claim is scientifically true. Begin with open CPU-scale numerical/systems papers and permitted data, not restricted medical cohorts or frontier-model retraining.

### Six weeks; decisive demo; rejection

**I/E:** weeks 1–2 choose one accessible domain, audit existing capsules and reproduction reports, and freeze one published claim per paper. Weeks 3–4 recover original execution closures and run contemporary/offline conditions. Weeks 5–6 publish claim-linked artifacts, recipe patches, raw results, and the unavailable-input inventory. Reuse SWHIDs and accepted capsule formats; do not build paper discovery or another notebook platform. A useful demo shows a historical paper's claim surviving one environment transition but failing another, with a verified cause and a documented repair that preserves the method. The new contribution must be an unrecorded survival/loss observation, not repackaging an already verified Code Ocean run.

**I/E — Rejection experiment:** **$100/two days**, five old papers. Stop if no authoritative expected output or valid tolerance can be established, if missing rights/inputs dominate, or if the selected cases already have an equivalent continuing record. For the full pilot, require an outside researcher to use the evidence in choosing or extending software. **Strongest objection:** ongoing claim adjudication is a scientific institution, while the attractive automated portion is already being built by others. **Builder fit:** good for environment recovery, Wasm/Rust portability, and reproducible execution; weaker for scientific interpretation. Partner with an existing domain/reproduction community. Outside GrowOS.

## Other evidence commons considered seriously

A six-week extension using 200 rented A100 hours is roughly $358 for GPU rental plus CPU, inference, and data work; it does not purchase access to every vendor's NPU or physical devices. Pursue only if an application owner supplies a consequential unmeasured acceptance condition. Differing floating-point results are not automatically defects. **F/I — Compiler audits:** [Csmith/YARPGen experience documented by John Regehr in March 2026](https://john.regehr.org/writing/claude_c_compiler.html) includes a correction after a generated testing script incorrectly reported no miscompilations. Those are weak starting advantages for a solo public project. Add such worlds only after a concrete participant exists; do not call reconstructed synthetic scenes customer evidence.

**I — UI outcomes:** the earlier Storybook/human-task signals support genuine measurement. They do not establish that renting compute replaces recruiting users or observing use. Models can generate plausible sessions; that cannot substitute for the human-outcome asset the idea needs. No autonomous compute-only UI commons is recommended here.
