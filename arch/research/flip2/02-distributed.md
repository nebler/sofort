# Distributed AI compute: agents around recovery, parallelism and serving

Research date: **2026-10-28**. Lens: distributed training, inference serving and AI cluster operations.

**Labels:** **F** = sourced fact, including an author's measurement or a vendor's claim; **M** = measured in this investigation; **I** = inference, proposal or judgment; **E** = estimate, scenario or proposed acceptance threshold. There are **no M performance results** here. Arithmetic below is explicitly derived or hypothetical. Paper results are not our experiments.

**F — Required context read:** [round-two brief](BRIEF.md), [round-one method/template](../flip/BRIEF.md), the conclusions, bets and rejection lists of [01](../flip/01-systems.md), [02](../flip/02-networks.md), [03](../flip/03-scale-dist.md), [04](../flip/04-broad.md), [05](../flip/05-scale-code.md), [06](../flip/06-giants.md), and [the compiler/agent-JIT report](../moonshots2/02-compilers.md). This report does not propose another agent JIT or incremental-agent runtime.

## Finding

**I — The pain is substantial; the obvious products are occupied.** BSP, collectives, checkpoint/restart, gang scheduling and queueing did not die. They became the machinery of AI compute. Better agents can absorb the remaining work of understanding unfamiliar models, generating instrumentation, producing reproducers and maintaining adapters. They do not remove synchronization, network bandwidth, finite HBM or statistical uncertainty about convergence.

**I — The best conditional bet is recovery-equivalence maintenance:** given an existing training stack, preserve its declared training-state contract across a framework update or parallelism change, grow a small repair from a failing resume case, and check it against an independently captured uninterrupted/reference run. This is a narrower claim than building checkpointing, resharding, autonomous GPU operations or fault-tolerant training. All four already exist. Even the narrow bet has close research and repository precedents; it needs a customer-specific integration failure and a comparison with ordinary agents plus upstream tests before being called a business.

## What makes parallelism configuration difficult

**F/I — There are different communication and state contracts, not five independent integer knobs.**

| Axis | What is divided; dominant concern | What an agent must preserve/check (**I**) |
| --- | --- | --- |
| Data parallel, DP; FSDP/ZeRO | Examples replicated across model copies; model/gradient/optimizer states may also be sharded. | Correct gradient normalization, global sample count, reduction groups and optimizer ownership. |
| Tensor parallel, TP | Individual layer tensors/operations; frequent small-latency-sensitive collectives. | Shard axes, head divisibility, tied weights, vocab partitions and rank-to-link placement. |
| Pipeline parallel, PP; virtual stages | Layers/stages and microbatches; bubbles, activation lifetimes and P2P dependencies. | Schedule legality, optimizer-step boundaries, microbatch count and stage balance. |
| Expert parallel, EP | MoE experts and routed tokens; all-to-all, load imbalance, expert capacity. | Router semantics, expert identities, token drop policy and expert-DP/TP groups. |
| Context parallel, CP; sequence parallel | Long sequence work/activations; attention exchange and masking. | Position/mask semantics, sequence partitioning and activation/RNG ownership; distinguish CP from TP-associated sequence parallelism. |

**F — Concrete constraints:** NVIDIA's guide computes dense-model DP as `world_size/(TP×PP×CP)`; EP has additional group relationships, so blindly multiplying `DP×TP×PP×EP×CP` is generally wrong. Its example combines TP=2, PP=4, CP=2, EP=4 on a 32-GPU mesh with DP=2. Sequence parallelism requires TP>1 in this implementation. [Megatron Bridge parallelism guide, current documentation accessed 2026-10-28](https://docs.nvidia.com/nemo/megatron-bridge/latest/parallelisms.html).

**I — Additional search dimensions** include microbatch/accumulation, recomputation, sharding stage, offload, precision, collective algorithm, overlap, virtual pipeline stages and physical placement. **E:** ten knobs with four nominal values already give 4^10 ≈ **one million** combinations before per-layer choices; this is an illustrative upper-level search count, not a measured count of legal configurations. Changing batch size to make a configuration “faster” can change learning progress, so throughput alone is an incomplete oracle.

## Ten ideas, using the round-one template

### 1. Maintain recovery equivalence across stack and parallelism changes

1. **The idea / origin — F/I.** Grow and maintain the missing state adapters needed for an existing training job to resume with the same declared semantics. The old principles are consistent global state, [Chandy–Lamport, February 1985](https://www.cs.cornell.edu/courses/cs514/2008sp/CL85.pdf), and minimizing checkpoint/restart waste, [Young, September 1974](https://doi.org/10.1145/361147.361115), [Daly, 2006; online December 2004](https://graal.ens-lyon.fr/~abenoit/CR02/papers/daly.pdf). **I:** use the consistency principle, not a claim that writing model tensors implements Chandy–Lamport's channel-state algorithm.
2. **Why niche — F/I.** Checkpointing succeeded; the application-specific state inventory and upgrade/migration tail remained manual. **F:** PyTorch DCP documents canonical-name/optimizer-ID complications and supports load-time resharding already. This establishes a real integration surface, not an unimplemented primitive. [DCP documentation, updated October 15, 2026](https://docs.pytorch.org/docs/main/distributed.checkpoint.html).
3. **What flipped — F/I.** Frequent recovery and multidimensional layouts make state adapters recurring work. **F:** a concrete recent example is DeepSpeed PR #8889: universal checkpoint resume restored fused/capturable optimizer step tensors with the wrong device/dtype. It proposes normalization and regression tests; its existence is evidence of a repair task, not proof of silent corruption or a merged fix. [PR, October 2026, accessed October 28](https://github.com/deepspeedai/DeepSpeed/pull/8889). **I:** an agent reads model/state code and grows the smallest adapter from a failed resume comparison.
4. **Oracle — strong for bounded state continuity; weak for general convergence, I.** Capture canonical model tensors, optimizer moments/steps/groups, scheduler/scaler, RNG streams, data cursor, sample IDs and accumulation phase. Compare uninterrupted versus save/reload continuation at an explicit step boundary. Compare canonical full state before the next step; compare deterministic next-step outputs where achievable. Different reduction trees may require a predeclared numerical bound rather than byte equality. **Cheating:** omit difficult fields, relax tolerance, reset optimizer, replay only easy batches, compare two equally broken converters, or save after the injected fault. The agent cannot edit the capture/comparator, test timing or hidden fixtures.
5. **100× better model — I.** More model/framework variants make maintenance more valuable, and better models write adapters faster. A strong generic coding agent with good upstream tests can erase the advantage. The product must save repeated qualification work, not merely generate code.
6. **Prior art, 2025–2026 — F/I.** ByteCheckpoint already offers parallelism-agnostic state, framework/storage adapters and load-time resharding. [NSDI, April 2025](https://www.usenix.org/conference/nsdi25/presentation/wan-borui). Nguyen et al. already run **generate→validate→repair** to add VeloC checkpointing to six MPI applications, including single-rank fault injection and reference-output comparison. [June 29, 2026 preprint](https://arxiv.org/html/2606.30921v1). ShardLift already demonstrates local deterministic crash recovery and offline W4→W3 resharding, while explicitly excluding GPU/NCCL/FSDP interoperability. [Repository, accessed October 28, 2026](https://github.com/omar07ibrahim/shardlift). **I:** generic agent-generated checkpointing and a CPU kill-and-reshard demo are occupied. The residual hypothesis is maintaining real application contracts through existing-stack changes, not another checkpoint engine.
7. **Value — E.** Buyer: a model platform team repeatedly upgrading frameworks or changing meshes. A **$10K–25K bounded qualification pilot** is plausible only if it replaces demonstrably larger engineering/retraining costs. Ten such pilots are $100K–250K revenue, not a market-size estimate. No primary source here measures this exact adapter-maintenance spend.
8. **Two-week proof — E.** One engineer; TS orchestration plus Python/PyTorch bridge. Freeze one small training workload, three state-layout/update transitions and independently implemented reference capture. Inject missing optimizer step, swapped shard, stale data cursor, lost RNG and partially committed checkpoint. Agent repairs only adapters/integration. Hold out whole fault families and one version/layout transition. CPU/Gloo can test state logic; GPU layout/kernels/NCCL qualification needs an operator's existing hardware later. Do not claim that a CPU proof validates 100K-GPU recovery.
9. **Demo + tweet / killer / kill test — I/E.** Demo a job that resumes and trains but diverges because one optimizer field was restored incorrectly, then an accepted repair that restores the reference contract. Tweet: “This resume passed load(). It failed the next-step state check. An agent repaired the adapter; hidden state-loss faults still fail.” Expert reply: “DCP plus our regression suite and an ordinary coding agent already does this.” **Kill** unless three real integration failures close with zero accepted state-loss mutants and **≥50% less expert time**, including harness construction, than that baseline.

### 2. Turn an incident diagnosis into a minimized, executable reproducer

1. **The idea / origin — F/I.** Revive automated cause isolation: agent synthesizes missing instrumentation/probes, while delta debugging minimizes a failure-preserving input/environment difference. [Zeller–Hildebrandt, February 2002](https://www.st.cs.uni-saarland.de/publications/files/zeller-tse-2002.pdf). Join traces across ranks using low-overhead distributed tracing principles, [Dapper, April 2010](https://research.google/pubs/dapper-a-large-scale-distributed-systems-tracing-infrastructure/).
2. **Why niche — I.** Delta debugging needs a repeatable failure predicate and meaningful transformations. Distributed GPU hangs depend on timing, topology, proprietary firmware and workloads too large to rerun casually. Cheap source generation addresses probe plumbing; it does not make a full-cluster replay cheap or a hardware fault reproducible.
3. **What flipped — F/I.** Richer flight recorders, collective traces and topology inventory provide structured evidence. L4 demonstrates extraction of failure-bearing logs/nodes/stages; XPUTimer reports deployment across **6K GPUs for eight months**, including detection of a **2.66%** slowdown. [L4, FSE 2025](https://arxiv.org/abs/2503.20263); [XPUTimer, February 8, 2025](https://arxiv.org/abs/2502.05413). **I:** the agent's valuable action is to write a targeted, bounded probe and distinguish competing causes, beyond summarizing logs.
4. **Oracle — weak from logs; stronger from intervention, I.** Check whether removing/changing the suspect condition eliminates the failure and restoring it reproduces the failure, on a held-out environment. Distinguish “communication timeout observed” from “rank X entered a different collective.” **Cheating:** report the last rank to log, inject the purported fault into the reproducer, change the failure predicate, disable checks, or classify a timeout as a hardware root cause. Preserve original symptoms and mark unreproduced cases unresolved.
5. **100× better model — I.** Better models generate better discriminating probes and navigate unfamiliar stacks; they also make an ordinary terminal agent formidable. Value remains in evidence access, capture fidelity and safe, cheap interventions.
6. **Prior art — F/I.** **Directly occupied:** TSGuard, originally AidAI in June 2025 and revised for FSE in **May 2026**, is a multi-agent Azure incident diagnosis system with structured trial-and-error. It reports **19.8%** diagnostic-accuracy improvement and **63.4%** reduction in verification time against its stated baselines. [Current paper](https://arxiv.org/html/2506.01481v2). NVIDIA **Minerva/Sherlock**, October 26, 2026, grounds natural-language diagnosis in telemetry and a topology/workload knowledge graph, with MCP access. [NVIDIA](https://developer.nvidia.com/blog/how-nvidia-minerva-turns-telemetry-chaos-into-peak-gpu-yield). EROICA already performs production differential troubleshooting. **I:** only automatic production-to-small-reproducer conversion is a potentially distinct seam; search results do not prove it unoccupied.
7. **Value — E.** Cloud/model-platform SRE buys reduced expert investigation time and better vendor escalation packets. A **$5K–15K pilot** for ten reproducible historical incidents is a testable quote. Avoid pricing all idle GPUs as savings when the existing recovery system already restarts within minutes.
8. **Two-week proof — E.** Build ten local distributed fixtures: mismatched collective order, bad shape, rank exit, data-loader stall, wrong interface and injected latency. Give agent traces/config/source, not fixture labels. Require a standalone reproducer, reduction in necessary ranks/input and a repair or a justified unresolved result. Compare scripted flight-recorder analysis and a strong general coding agent with identical tools. GPU-specific faults remain explicitly outside the CPU demonstration.
9. **Demo + tweet / killer / kill — I/E.** “A thousand timeout lines became a two-rank collective-order reproducer; replay rejects the proposed wrong fix.” Expert: “You solved synthetic configuration bugs; real failures need vendor hardware.” **Kill** if genuine operator incidents cannot be reduced, if diagnosis quality depends on fixture-name leakage, or if no operator supplies ten sanitized real cases. **Disposition:** useful second-stage feature, reject generic GPU SRE copilot.

### 3. Generate and maintain SDC probes using algebraic checks and differential replay

1. **The idea / origin — F/I.** Let an agent extend detectors/reproducers when a new kernel, layout or precision path appears; use independent algebraic redundancy or deterministic reference replay as judge. [Huang–Abraham, algorithm-based fault tolerance, June 1984](https://graal.ens-lyon.fr/~abenoit/CR02/papers/abft2.pdf). **F:** Byzantine agreement addresses agreement under arbitrary faulty participants, a different contract from validating numerical computation. [Lamport–Shostak–Pease, July 1982](https://lamport.azurewebsites.net/pubs/byz.pdf).
2. **Why niche — F/I.** ABFT is operation/fault-model-specific; floating-point roundoff and fused kernels complicate generic checks. The original paper does not provide universal error detection. **I:** full redundant training is expensive; checksum preservation can miss structured/correlated corruption; agreement by identically faulty replicas need not imply correctness.
3. **What flipped — F/I.** AEGIS's production result in the evidence table establishes practical online detection. Meta separately reports numerical/SDC investigations taking **hours to days**, tracing **37 interruptions to seven hosts** in its 32K-GPU observations; its internal deterministic training tool compares checkpoints across servers. [FT-HSDP, §2.2, January 2026](https://arxiv.org/html/2602.00277v1). **I:** the labor seam is new failure-path reproduction and coverage maintenance, not “discover SDC exists.”
4. **Oracle — strong for injected faults within a declared model; weak for unseen real faults, I.** A trusted CPU/high-precision reference or healthy-device replay can adjudicate a captured operation; random projections/checksums provide probabilistic detection under stated assumptions. A loss spike is an alarm, not a complete SDC oracle. **Cheating:** drop silent-but-plausible mutants, widen tolerance, only test NaNs, make checker share the corrupted result, or overfit injected bit locations. Hide fault sites, magnitudes, timing and correlated faults; include healthy low-precision variation to measure false positives.
5. **100× better model — I.** Better agents can cover new operators and shrink reproducers faster. They cannot infer every undetected hardware error from an apparently normal loss curve. Independent computation/checking remains necessary.
6. **Prior art — F/I.** AEGIS is the direct incumbent for online training SDC detection; Meta has deterministic replay; NVIDIA NVSentinel already quarantines suspect nodes from health signals. [AEGIS, July 2026](https://www.usenix.org/conference/osdi26/presentation/lei); [NVSentinel fault quarantine, current docs accessed October 28](https://docs.nvidia.com/nvsentinel/v1.22.0/components/fault-quarantine/). **I:** an agent adding coverage could be an upstream contribution or lab tool; no evidence establishes an independent SDC-detector company opportunity.
7. **Value — E.** Training teams and accelerator vendors pay for trustworthy coverage of a named missing execution path, potentially **$10K–30K** for a bounded qualification effort. Payer value depends on real incidents and access to suspect hardware; aggregate training spend does not supply willingness to pay.
8. **Two-week proof — E.** Pick two small operators and one miniature training loop. Capture inputs and inject payload/metadata corruption behind a trusted runner. Agent writes probes and shrinkers, not the golden reference. Compare with fixed ABFT/random-projection checks and deterministic replay. Measure sensitivity by fault class, false positives and checking cost. No real-GPU SDC-rate or overhead claim without existing hardware and real faults.
9. **Demo + tweet / killer / kill — I/E.** “Finite loss, wrong update: an independent probe catches the corruption, and an agent reduces it to one operation.” Expert: “You detect your synthetic errors; AEGIS already handles production.” **Kill** if held-out corruption classes defeat coverage, if healthy rounding causes unacceptable quarantines, or if a lab cannot name a new path its incumbent detector misses. **Disposition:** research/coverage project; conditional top-three experiment, weak standalone business evidence.

### 4. Apply backup-task and tail-tolerance ideas to fail-slow training

1. **The idea / origin — F/I.** Diagnose transient slow participants, then choose rebalancing, migration, redundancy or restart using remaining-work and contention costs. MapReduce's backup tasks, [Dean–Ghemawat, OSDI 2004](https://research.google.com/archive/mapreduce-osdi04.pdf), and hedged/tied requests in [Dean–Barroso, February 2013](https://research.google/pubs/the-tail-at-scale/) are the lineage. **F:** the original MapReduce sort example took **44% longer** without backup tasks; not an AI-training saving.
2. **Why niche — I.** Backup tasks work especially well for independent/replayable units with a clear winner. A TP shard or PP stage participates in stateful collectives; speculative duplication needs matching state, communicator semantics and commit selection. Unbounded hedging worsens congestion. This is a semantic/capacity barrier, not merely missing code.
3. **What flipped — F/I.** GREYHOUND's measured fail-slow cost establishes the demand. MegaScale also finds stragglers missed by simple per-GPU GEMM checks. **E:** if a recurring synchronized step grows from 1.00 to 1.05 seconds, throughput falls **4.76%** across the entire gang even though one participant caused it. **I:** agents could maintain the mapping from symptoms to legal mitigations for unfamiliar hybrid layouts.
4. **Oracle — moderate, I.** Frozen workload and sample accounting; held-out fault schedules; productive progress per provisioned GPU-hour, including spares, migration and abandoned work. Verify data weighting and effective batch after rebalancing. **Cheating:** count only active GPUs, omit migrated work, change the batch/data distribution, or remove the injected bottleneck from the benchmark rather than mitigating it.
5. **100× better model — I.** Better policy generation helps, but deterministic low-overhead control remains appropriate inside the step loop. A model that reasons for seconds cannot be the scheduler for every microsecond collective event.
6. **Prior art — F/I.** GREYHOUND already diagnoses and applies graduated mitigation without human intervention. **Clockwork TorchPass** offers network failover and live GPU migration, with planned, preemptive and hard-failure paths. Its March 2026 comparison uses **64 H200 GPUs**, injected failures and a vendor-selected setup, not a 32K-GPU comparative production run. [TorchPass description](https://clockwork.io/blog/torchpass-workload-fault-tolerance/), [benchmark](https://clockwork.io/blog/keeping-distributed-training-running-through-failures/). **I:** agentic mitigation is occupied at the product/function level even when the controller is not an LLM.
7. **Value — E.** Fleet operators have a large savings pool, but an entrant needs a failure mode existing mitigation cannot handle. Hypothetical **3%** recovery of a **$1M/month** reservation is **$30K/month gross benefit**, before spare and deployment costs; not evidence this gain is attainable.
8. **Two-week proof — E.** Replay a fixed multi-stage training DAG with injected compute/link slowdowns; implement costed restart, remap and extra-replica choices. Let agent generate policy changes and compare with GREYHOUND-like thresholds and an offline lower bound. A CPU simulation can falsify policy logic, not demonstrate GPU speedup.
9. **Demo + tweet / killer / kill — I/E.** “The controller leaves a 200-ms blip alone and migrates a persistent slow stage; all spare costs count.” Expert: “Your simulator knows the straggler duration.” **Kill** if gains disappear without future knowledge, correlate with omitted network interference, or match existing controllers. **Disposition:** occupied; do not build a new generic straggler product.

### 5. Relax failure domains while preserving BSP's useful semantics

1. **The idea / origin — F/I.** Use replicas as fault domains, retain synchronous update semantics within the declared participating set, and recover a failed replica without stopping every accelerator. BSP models computation/communication separated by barriers, [Valiant, August 1990](https://web.mit.edu/6.976/www/handout/valiant2.pdf). Parameter servers separate workers from shared parameters with flexible consistency and elastic recovery, [Li et al., OSDI 2014](https://www.usenix.org/conference/osdi14/technical-sessions/presentation/li_mu).
2. **Why niche — I.** Neither died. BSP's determinable step boundary is valuable; dense allreduce often fits tightly coupled training better than a centralized parameter traffic pattern. Asynchrony/staleness changes optimization behavior. Parameter servers remain useful for sparse state, but agents do not prove that replacing a dense training collective with a server preserves convergence.
3. **What flipped — F/I.** At 100K scale, rebuilding the entire communicator becomes a material recovery cost; FT-HSDP's measured stalls demonstrate the consequence. **I:** an agent can integrate and qualify an existing fault-tolerant runtime for an unsupported model, rather than invent a new consistency regime.
4. **Oracle — strong for protocol safety in a bounded model; weak for final model equivalence, I.** State-machine checks can test membership epochs, no mixed-step reductions and clean joining/leaving. Convergence requires fixed-budget, multiple-seed loss/quality tests with sample accounting. **Cheating:** report steps while processing fewer tokens, skip difficult data, use a different learning-rate schedule without disclosure, or claim small-model convergence proves 100K-GPU quality.
5. **100× better model — I.** More capable agents help with protocol integration and proof maintenance, while more compute increases failure pressure. They do not eliminate the cost/quality tradeoff of changing participation or batches.
6. **Prior art — F/I.** **FT-HSDP/FTAR**, **torchft**, Google's slice-level continuation, Unicron and ByteDance **ByteRobust** already occupy elastic recovery and integrated fault-aware management. torchft's Manager explicitly manages quorum, process-group reconfiguration and checkpoint restoration; it warns that its own state must be saved. [torchft documentation, accessed October 28, 2026](https://meta-pytorch.org/torchft/manager.html). ByteRobust integrates diagnosis, warm backups and fault-aware checkpointing. [Robust LLM Training Infrastructure at ByteDance, SOSP, October 2025](https://i.cs.hku.hk/~cwu/papers/brwan-sosp25.pdf).
7. **Value — E.** Labs/cloud operators pay for recovered productive capacity and supported framework integration. A small entrant might sell **$10K–25K integration/qualification engagements**; building a replacement runtime needs substantially more than a two-week proof and access to the operator's cluster.
8. **Two-week proof — E.** Tiny deterministic training with two replica groups on CPU/Gloo; script membership changes and recovery epochs, then agent fills an unsupported model-state callback. Compare the unmodified runtime integration and a restart baseline. Record processed samples and state continuity. Scaling/performance remains untested.
9. **Demo + tweet / killer / kill — I/E.** “One replica disappears; the other continues; recovery never mixes membership epochs.” Expert: “You wrapped torchft and changed training semantics.” **Kill** unless the supported integration closes an actual gap and its semantics are accepted by the model owner. **Disposition:** use incumbent machinery; §1 is the integration wedge.

### 6. Repair parallelism configurations and their missing framework support

1. **The idea / origin — F/I.** Agent proposes a legal model/mesh/configuration adapter, then a compiler/runtime and measurement loop check it. Automatic parallelization is established in [FlexFlow, MLSys 2019](https://proceedings.mlsys.org/paper_files/paper/2019/hash/b422680f3db0986ddd7f8f126baaf0fa-Abstract.html), [GSPMD, May 2021](https://arxiv.org/abs/2105.04663), and [Alpa, OSDI 2022](https://arxiv.org/abs/2201.12023). FlexFlow uses simulation-guided search; GSPMD propagates tensor-sharding annotations; Alpa combines inter-/intra-operator planning.
2. **Why niche — F/I.** General search needs accurate costs, supported operators and expressible state/memory layouts. Alpa explicitly notes unavailable operator support when comparing contemporaneous systems. **I:** do not equate “compiler chooses a legal partition” with “complete training code needs no framework-specific work.” Hardware/software evolution continually invalidates cost models.
3. **What flipped — F/I.** Mist jointly tunes parallelism, recomputation, ZeRO and offload; on up to **32 L4/A100 GPUs**, reports mean gains of **1.32×/1.34×** over Megatron-LM in its FlashAttention-enabled comparison. [Mist, EuroSys, March–April 2025](https://people.mpi-sws.org/~cgiannoula/assets/publications/Mist_EuroSys2025_full.pdf). Its public artifact still documents multi-node OOM/idling requiring manual monitoring. [Repository, accessed October 28, 2026](https://github.com/CentML/Mist). **I:** agent-generated support for an unfamiliar operation plus held-out verification is more interesting than asking an LLM for TP/PP integers.
4. **Oracle — moderate, I.** Static divisibility/shape/memory checks; distributed-versus-reference forward/gradient/update comparisons; measured memory and throughput under fixed batch/precision/data contract. Simulator scores only screen candidates. **Cheating:** lower sequence length, change precision or token-dropping, omit optimizer state, exploit graph-capture warmup, or optimize only one homogeneous microbatch.
5. **100× better model — I.** Larger models and more hardware improve the need for mapping; better coding agents can remove missing-operator labor. Conventional search can still beat a model inside an already covered parameter space. No moat from “AI chooses parallelism.”
6. **Prior art — F/I.** Mist/CentML, GSPMD/XLA, Alpa, DeepSpeed AutoTP and NVIDIA Megatron already implement much of this. NVIDIA's current parallelism guide even links an operational agent skill. [DeepSpeed config, current docs](https://www.deepspeed.ai/docs/config-json/); [Megatron guide](https://docs.nvidia.com/nemo/megatron-bridge/nightly/parallelisms.html). FlexParallel's 2026 submission reports query-efficient tuning through **8,192 devices**; its status must be taken from the paper, not assumed accepted. [Manuscript](https://openreview.net/pdf?id=IjZdj6vL7G). **I:** generic autotuning is decisively occupied.
7. **Value — E.** Buyer is the team introducing a new architecture or porting an expensive run. A **$10K–20K** pilot for one previously unsupported operator/layout is plausible only with a real operator sponsor. Small configuration tweaks are likely framework features.
8. **Two-week proof — E.** Choose a tiny MoE/custom operation absent from one selected planner; implement the missing adapter with an agent and hold out shapes/layouts. Use CPU reference gradients and simulated costs; if a customer already provides GPUs, validate top candidates there without rental. Require actual semantic support gained, not just a larger YAML grid.
9. **Demo + tweet / killer / kill — I/E.** “A new layer failed the sharding check. The agent added its rule; unseen shapes match reference gradients.” Expert: “GSPMD/DTensor already handles that decomposition.” **Kill** if the operation is already supported, adapter effort is trivial with a normal agent, or performance requires changing the numerical contract. **Disposition:** conditional integration opportunity; no generic auto-parallel company thesis.

### 7. Synthesize topology-specific collectives, with independent schedule checking

1. **The idea / origin — F/I.** Agent writes a collective schedule or communication sketch; a symbolic checker establishes data movement/reduction coverage, then a runtime tests performance. [Thakur–Rabenseifner–Gropp, March 2005](https://www.cs.umd.edu/class/spring2021/cmsc714/readings/Thakur-MPICH.pdf) already selects algorithms by message size and process count, targeting short-message latency versus long-message bandwidth.
2. **Why niche — F/I.** Collectives succeeded; topology-specific engineering remains expensive. **I:** a ring allreduce has roughly **2(p−1)** communication rounds and **2(p−1)n/p** bytes per rank; tree/recursive schemes reduce startup depth, while reduce-scatter/allgather can retain bandwidth efficiency. These simplified α/β costs omit multi-rail contention, GPU SM use, offload and overlap. There is no universal “ring beats tree” rule.
3. **What flipped — F/I.** Topologies span NVLink, NIC rails, racks and buildings; EP adds all-to-all and concurrent communication. Meta's **NCCLX** explicitly co-designs transport, fine-grained overlap, inference collectives and fault localization for 100K+ scale. [Collective Communication for 100k+ GPUs, October 2025; revised January 9, 2026](https://arxiv.org/html/2510.20171v4). **I:** models can supply sketches or missing backend code; physical measurements remain scarce.
4. **Oracle — strong for a finite schedule's logical coverage; moderate for implementation, I.** Symbolically track provenance of chunks, exact-once reduction contributions, buffer aliasing and dependency order; test odd rank counts, nonuniform messages, in-place buffers and concurrency. Integer inputs expose coverage mistakes; floating-point reductions need declared ordering/tolerance. **Cheating:** benchmark no-ops, reuse expected buffers, omit synchronization, reduce fewer ranks, or win a microbenchmark by occupying SMs needed by the model. End-to-end measurement must include competing compute.
5. **100× better model — I.** More useful on irregular/new topologies and custom code, but solver synthesis is a strong baseline and better generic agents commoditize schedule authoring. New code does not make a simulated topology accurate.
6. **Prior art — F/I.** **MSCCL** already synthesizes collectives; **TACCL** adds human communication sketches, with reported gains on specific historical topologies. [NSDI, April 2023](https://www.usenix.org/conference/nsdi23/presentation/shah). **MSCCL++**, April 2025, supplies communication primitives, DSL and NCCL-compatible integration, reporting up to **3.8× collectives / 15% real inference** speedup against its baselines. [Paper](https://arxiv.org/abs/2504.09014), [DSL integration](https://microsoft.github.io/mscclpp/dsl/integration.html). **OptCCL**, SIGCOMM, August 2026, synthesizes optimized schedules at hundreds-of-GPUs scale. [Author abstract in official program](https://conferences.sigcomm.org/sigcomm/2026/program/papers/). **I:** solver/DSL synthesis plus an agent is occupied infrastructure, not a blank market.
7. **Value — E.** Accelerator/network vendors or operators of a genuinely unsupported topology pay for maintained kernels/integration. A **$20K–50K** joint engineering pilot is conceivable, conditional on hardware access; simulation-only gains cannot justify it.
8. **Two-week proof — E.** Reuse MSCCL-style provenance semantics; TS checker plus a small schedule DSL. Ask agent for schedules on ten withheld asymmetric/degraded topologies. Compare with ring/tree and a solver, including all synthesis time. No rented GPU: demonstration establishes legality and modelled cost only; physical performance is a separate gate.
9. **Demo + tweet / killer / kill — I/E.** “A schedule routes around a missing rail; the checker rejects a faster candidate that omits one rank.” Expert: “TACCL/OptCCL already finds this, and your cost model ignores congestion.” **Kill** if solver baselines win or gains vanish under contention-aware simulation. **Disposition:** contribute backend/sketch support, reject generic agent collective synthesis.

### 8. Co-schedule whole jobs for useful progress, rather than GPU occupancy

1. **The idea / origin — F/I.** Agent translates workload requirements into gang/topology/elasticity constraints, and an established scheduler optimizes placement. [Ousterhout, coscheduling, ICDCS 1982](https://web.stanford.edu/~ouster/cgi-bin/papers/coscheduling.pdf) explains why independently scheduling cooperating processes causes thrashing. Modern cluster gang admission is related, not identical to synchronized CPU time slicing.
2. **Why niche — I.** It is not niche in HPC. GPU clusters add heterogeneous devices, quotas, scarce contiguous topology domains and jobs whose speedup changes with batch/mesh. Gang placement prevents partial allocation but can create head-of-line blocking; an agent does not abolish fragmentation or fairness choices.
3. **What flipped — F/I.** Inference itself now has multi-role gangs: separate prefill/decode pools, TP/EP workers and elastic replicas. NVIDIA describes hierarchical gang scheduling and topology-aware orchestration through Grove and KAI. [Deploying disaggregated inference, 2026, accessed October 28](https://developer.nvidia.com/blog/?p=113609). **I:** labor lies partly in mapping new workload CRDs and restart contracts into these constraints.
4. **Oracle — moderate, I.** Constraint solver verifies placement/quota/gang invariants; replay tests utilization, queue wait, time-to-quality, fairness and starvation on hidden arrivals. **Cheating:** reject inconvenient jobs, ignore initialization/restart time, inflate declared priority, count stranded GPUs as useful, or benchmark only small backfillable jobs. Include every admitted and waiting job and charge transition costs.
5. **100× better model — I.** More workload variants make adapter generation useful. The real-time combinatorial decision can remain in a deterministic scheduler; a better model mostly improves contracts/cost estimates and explanation.
6. **Prior art — F/I.** Pollux co-optimizes allocation and training goodput, not merely device occupancy. KAI/Run:ai already implements gang placement, hierarchical fairness, topology awareness and GPU sharing. NVIDIA's **October 2026** open-source release also includes **Workload Map**, a contract for different Kubernetes workload types. [NVIDIA announcement](https://developer.nvidia.com/blog/nvidia-runai-is-now-open-source-as-part-of-nvidia-dsx-ai-factory-platform). **I:** even “agent writes scheduler integration for arbitrary CRDs” competes with this explicit abstraction.
7. **Value — E.** Platform operators can justify a **$5K–15K** supported adapter/policy engagement if a real workload currently strands capacity. A new scheduler company has high integration/switching costs and a strong open-source incumbent.
8. **Two-week proof — E.** Use an existing scheduler's dry-run or a constraint model with fixed fleet/arrival traces; agent creates a missing workload mapping and policies. Inject partial-launch, preemption and restart failures. Test legal progress and starvation before predicted utilization. No cluster deployment.
9. **Demo + tweet / killer / kill — I/E.** “The prefill gang no longer takes the last GPUs while its decode gang waits forever; other tenants keep their guarantees.” Expert: “KAI/Grove already does this.” **Kill** if the target workload maps directly to supported upstream objects. **Disposition:** occupied; narrowly useful integration work only.

### 9. Maintain a calibrated cluster simulator, rather than treating simulation as truth

1. **The idea / origin — F/I.** Use discrete-event simulation and measured operator/network costs to explore mappings, then let an agent explain residual errors and add missing model features. FlexFlow already uses simulation-guided parallelization; [ASTRA-sim 2.0](https://github.com/astra-sim/astra-sim) models hierarchical networks/disaggregated training and consumes Chakra execution traces. **I:** the revived task is model maintenance, not inventing simulation.
2. **Why niche — I.** Simulator usefulness is limited by trace fidelity and missing behavior: contention, overlap, launch overhead, network protocols, GPU internals and failures. Model construction/calibration is laborious. Agents can write features/adapters, but extrapolation to a different scale/hardware is still an epistemic problem.
3. **What flipped — F/I.** Alibaba **SimAI**, NSDI April 2025, integrates framework/computation/collectives and reports end-to-end iteration deviations **<3.9%** in tests through **1,024 GPUs**. [Paper, §§4–5](https://ennanzhai.github.io/pub/nsdi25spring-simai.pdf). Microsoft's **Vidur**, MLSys 2024, uses profiling plus predictive modeling for serving; the full paper reports request-level latency error **<9%** across tested settings. [Full paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2024/05/vidur_mlsys24.pdf). **I:** these errors can exceed the prospective gain from a 2% schedule change.
4. **Oracle — weak as final judge, moderate as a screen, I.** Hold out real traces by topology, workload and time; score candidate-ranking accuracy and calibrated uncertainty, not just mean relative runtime error. A separate physical measurement must accept optimization. **Cheating:** train/test on near-identical profiles, add per-workload fudge constants, ignore rare tails, or let agent alter simulator to make its proposed policy win. Keep independent observed timings immutable and separate simulator/model edits from policy evaluation.
5. **100× better model — I.** More capable agents can maintain more simulators and propose better experiments. They cannot learn an unobserved hardware regime from no evidence. If all optimization happens only inside the simulator, better models can simply exploit it faster.
6. **Prior art — F/I.** ASTRA-sim, SimAI and Vidur directly occupy the simulator product/function. NVIDIA AIConfigurator already searches serving configurations from performance models; Dynamo's current planner uses live forward-pass metrics to tune estimates and has **experimental simulation-only retuning**. [AIConfigurator guide](https://docs.dynamo.nvidia.com/dynamo/v-0-7-0/user-guides/finding-best-initial-configs), [current planner guide, accessed October 28, 2026](https://docs.dynamo.nvidia.com/dynamo/dev/knowledge-base/modular-components/planner/planner-guide). **I:** a generic agent “digital twin optimizer” overlaps an active incumbent roadmap.
7. **Value — E.** Network/accelerator vendors and cloud capacity teams could buy a **$10K–25K** calibration project for a missing domain. Access to independent traces is the prerequisite; no evidence here supports a simulator-as-a-service market size.
8. **Two-week proof — E.** Existing public trace/profile corpus, grouped holdout by topology/workload. Agent adds one missing overlap or interference effect. Freeze observed data; compare against conventional regression and manually specified features. Evaluate whether the revised model correctly ranks untouched candidate schedules. No new GPU experiment is required to falsify the maintenance idea, but hardware validation is required for deployment gains.
9. **Demo + tweet / killer / kill — I/E.** “The model's fastest schedule loses on an untouched trace; an agent repairs the overlap model, and confidence shrinks only where data supports it.” Expert: “You fitted residuals, not physics.” **Kill** if held-out ranking does not improve or the signal is smaller than model error. **Disposition:** useful research component; not an independent oracle or generic company bet.

### 10. Tune serving policies using queueing, working sets and a fixed service contract

1. **The idea / origin — F/I.** Agent proposes a batching/routing/cache/pool policy; an independent workload replay and the serving engine measure completed useful service. The old ideas are [Little's law, June 1961](https://pubsonline.informs.org/doi/abs/10.1287/opre.9.3.383), [Kingman's heavy-traffic analysis, October 1961](https://www.cambridge.org/core/journals/mathematical-proceedings-of-the-cambridge-philosophical-society/article/abs/single-server-queue-in-heavy-traffic/81C55BC00A68FE6D5385638AA0B0AF37), and [Denning's working sets, May 1968](https://denninginstitute.com/pjd/PUBS/WSModel_1968.pdf). These succeeded; AI creates a new resource combination, not a resurrection of forgotten queueing.
2. **Why niche / new obstacle — I.** Each request alternates compute-heavy prefill with often bandwidth-limited token-by-token decode; continuous batching changes service time as batch composition changes. KV-cache residency couples admission, cache hits and memory capacity; disaggregated prefill/decode adds a network transfer and separate queues. Tool waits turn agent sessions into intermittent memory demand. Simple M/M/1 models do not capture this coupled, nonstationary system.
3. **What flipped — F/I.** **DistServe (2024)** reports up to **7.4× requests** or **12.6× tighter SLO** under its evaluated constraints; **Sarathi-Serve (2024)** uses chunked prefill/stall-free batching, reporting **2.6× capacity for Mistral-7B/A100**, up to **5.6×** on its pipelined Falcon-180B setup. [DistServe](https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin), [Sarathi-Serve](https://www.usenix.org/conference/osdi24/presentation/agrawal). **Mooncake (2025)** reports **59–498%** effective-capacity increases over baselines on real traces, and production gains of **115%/107%** requests on A800/H800 clusters. [FAST paper](https://www.usenix.org/conference/fast25/presentation/qin). These are different comparisons, not multiplicative gains available to a new tuner.
4. **Oracle — strong for a frozen replay/service contract; weak for future traffic, I.** Preserve model/weights/precision, input and output requirements, cache identity, admission policy, TTFT, inter-token latency and task completion SLOs. Count **all arrivals**, rejects, timeouts and incomplete sessions; include warmup, KV movement and idle reserved capacity. Compare outputs/logits or declared quality bounds, not only token rate. **Cheating:** shorten generations, force EOS, silently truncate context, discard long requests, let p99 exclude timeouts, leak future output length, reuse stale/cross-model KV, or sacrifice a tenant. Keep hidden burst/long-context/tool-wait traces and per-class SLO floors.
5. **100× better model — I.** Better reasoning reduces search labor; more useful agents can increase correlated bursts, long context and tool waits. Faster/cheaper models can change the economic bottleneck entirely. Queueing and HBM management remain runtime obligations, but the best policy may be conventional control, not an LLM deciding every token.
6. **Prior art — F/I.** **vLLM/PagedAttention** explicitly applies virtual memory to KV management. [September 2023](https://arxiv.org/abs/2309.06180). Mooncake, **SGLang**, **NVIDIA Dynamo/AIConfigurator**, **llm-d**, Alibaba **Llumnix**, and commercial **Fireworks** already cover substantial routing, cache and disaggregation functionality. SGLang implements RadixAttention for KV reuse; Llumnix migrates requests and their states; llm-d integrates KV-aware routing and disaggregated serving. [SGLang, NeurIPS 2024](https://papers.nips.cc/paper_files/paper/2024/file/724be4472168f31ba1c9ac630f15dec8-Paper-Conference.pdf), [Llumnix, OSDI July 2024](https://www.usenix.org/conference/osdi24/presentation/sun-biao), [llm-d launch, May 20, 2025](https://developers.redhat.com/articles/2025/05/20/llm-d-kubernetes-native-distributed-inferencing). Fireworks describes a fully disaggregated engine and prompt-aware routing. [Vendor product page, accessed October 28, 2026](https://fireworks.ai/platform/disaggregated-inference-engine). Agent-specific scheduling is also occupied: **SMetric**, July/September 2026, balances first-turn requests and preserves locality for follow-ups; **TOPAS**, August 2026, jointly schedules prefix residency and workflow critical paths within SGLang. [SMetric v2](https://arxiv.org/abs/2607.08565v2), [TOPAS](https://arxiv.org/abs/2608.25523). **I:** adding “for agents” does not recover novelty.
7. **Value — E.** Inference operators buy SLO-qualified capacity or lower cost per completed task. A genuine **5%** reduction on a **$1M/month** reservation is a **$50K/month gross pool**, before migration, software and risk costs. The tuner needs better net results than Dynamo/engine-native tuning and a normal optimization agent, rather than a percentage of all inference spend.
8. **Two-week proof — E.** Reuse Vidur/public traces or an existing engine's replay interface. Agent emits policy code/configuration; independent runner evaluates steady, burst, long-context, cache-miss and tool-wait workloads. Include an adversarial scheduler that drops long requests to prove the metric penalizes it. A simulation-only success must be labeled simulated; real KV transfer, kernels and outputs require later existing-hardware validation. Do not build a new serving engine.
9. **Demo + tweet / killer / kill — I/E.** “The tuner wins on cost per completed agent task while keeping long-session p99; a cheating short-request scheduler fails the gate.” Expert: “Dynamo already tunes these knobs, and your simulator omits KV transfers.” **Kill** if held-out gains are below uncertainty, quality/tenant floors regress, or a built-in sweep matches the result. **Disposition:** occupied as a platform; workload-specific contribution or evaluation integration only.

## Calculations that constrain the agent opportunity

**F/I — Checkpoint timing is already an optimization problem with a solution.** In a simple constant-cost, rare-failure model with useful interval τ, checkpoint stall C, mean failure interval M and restart cost R, the first-order wasted fraction is approximately:

```text
waste(τ) ≈ C/τ + τ/(2M) + R/M
τ* ≈ sqrt(2CM)
```

**F:** Young supplies the classical first-order approach; Daly analyzes higher-order corrections and model assumptions. **E:** C=10 s and M=1,800 s gives τ*≈190 s, checkpoint-plus-lost-work overhead ≈10.5%, before recovery; R=60 s adds another ≈3.3 points in this approximation. **I:** asynchronous staging, tier-specific failures, correlated outages and membership recovery violate the simple model. Agents can estimate costs and repair instrumentation; they should not rediscover this formula by spending production GPU time. [Young 1974](https://doi.org/10.1145/361147.361115), [Daly 2006](https://graal.ens-lyon.fr/~abenoit/CR02/papers/daly.pdf).

**E/I — KV arithmetic clarifies why paging alone is insufficient.** A conventional uncompressed KV representation uses approximately `2 × layers × KV_heads × head_dim × bytes × cached_tokens`, before layout/allocator/replication effects. For a hypothetical 80-layer, 8-KV-head, 128-head-dimension BF16 model, that is **320 KiB/token**, or **40 GiB for 128 Ki tokens** for one logical session across its shards. This is an illustrative architecture calculation, not a claim about every 70B model; MLA, quantization, sliding windows and cache sharing change it. Paging reduces fragmentation; it does not eliminate these bytes. Disaggregation pays to move them, cache misses pay recomputation, and retaining them reduces batch capacity.

**F/I — Queueing gives constraints, not a sufficient scheduler oracle.** Little's `L=λW` relates long-run population, arrival rate and residence time under appropriate stability/accounting conditions; it does not determine p99 or service policy. Kingman's heavy-traffic approximation makes the `ρ/(1−ρ)` sensitivity visible. **E:** that factor rises from **4 at 80%** to **19 at 95%** utilization, holding variability/service scale fixed—**4.75×** queue amplification in the approximation. **I:** continuous batching changes those other quantities, so this is a warning against GPU-busy optimization, not an LLM-serving prediction. [Little 1961](https://pubsonline.informs.org/doi/abs/10.1287/opre.9.3.383), [Kingman 1961](https://doi.org/10.1017/S0305004100036094).

## Oracle hierarchy and limits

| Check | Strength and appropriate use (**I**) | Remaining failure / agent shortcut |
| --- | --- | --- |
| Shapes, divisibility, type/placement constraints | Strong rejection of structurally invalid configurations. | Legal configuration can compute the wrong update or run slowly. |
| Symbolic collective provenance / bounded protocol model | Strong within explicit schedule/protocol semantics and fault assumptions. | Backend code, transport behavior, memory races and unmodelled failures remain. |
| Bitwise deterministic differential replay | Strong for the same numerical execution contract and captured state. | Changing topology/order/kernel invalidates a blanket bitwise promise; identical bugs can agree. |
| Numerical bound against independent reference | Useful for local operations/updates with predeclared bounds and diverse inputs. | Loosened tolerances, correlated reference bugs and untested shapes. |
| Short loss curve | Weak smoke test; catches catastrophic divergence. | Missing state/data can hide for many steps; one seed and smooth loss do not establish convergence. |
| Multi-seed time-to-quality / full evaluation | Necessary for meaningful optimizer/participation changes; expensive. | Data leakage, benchmark selection and finite confidence; cannot be called a cheap universal oracle. |
| Simulator / trace replay | Cheap candidate rejection and diagnosis; useful for held-out policy comparisons. | Model error, missing physical effects and adaptive overfitting; requires independent physical acceptance. |
| SLO-qualified completed work per provisioned GPU-hour | Operational objective when quality, arrival accounting and tenant floors are fixed. | Dropped/shortened work, tail exclusions and spare/transfer costs hidden from denominator. |

**I — Agent hook:** the slow outer loop—collect evidence → propose a discriminating experiment or bounded code change → run independent checks → accept/refuse → retain a regression case. Existing deterministic machinery belongs in the fast inner loops: collective transport, per-token scheduling, membership epochs and checkpoint commit protocols. The separation follows latency and trust requirements, not a presumption that model reasoning is inherently unsuitable.

**I — Commercial constraint:** the largest labs have both the pain and the strongest in-house tooling. Smaller labs may lack operators, but also lack the spare cluster budget needed to validate changes. A credible entrance needs an operator willing to provide sanitized incidents, an already available test environment and an identifiable unsupported transition; none was obtained during this research.

## Verification and prior-art boundaries

**F — Research method:** primary papers, official conference pages, author manuscripts, project documentation/repositories and vendor engineering descriptions were consulted on **2026-10-28**. Dates above identify publication/revision dates when available; undated living documentation is marked by access date. Vendor claims are labeled F as claims, not independently reproduced results. No accounts, deployments, GPU rental, Docker, VM use, experiments, commits or pushes were performed; no scratch files were needed.

**I — Scope of absence claims:** the search does not establish an empty market. The bet below is deliberately conditional on a real integration workload these do not already solve.

## Ranked top 3

1. **I — #1: recovery-equivalence maintenance for an existing stack.** Most attainable independent reference, a concrete recurring source of state bugs, and a CPU-scale falsification path. The differentiator must be cross-update/application qualification and accepted repairs, not checkpoint generation or a kill-and-reshard demo. **Confidence:** medium on the technical experiment; low on an unoccupied business.
2. **I — #2: incident-to-minimal-reproducer conversion.** Better models help turn unfamiliar cross-layer evidence into actionable executable tests, and the artifact has value beyond a plausible explanation. TSGuard, Minerva and internal tools make generic diagnosis a poor bet. **Confidence:** medium on configuration/software incidents; low on reducing intermittent physical faults without privileged access.
3. **I — #3: SDC probe/reproducer coverage maintenance.** Strong independent local checks are possible, and real corruption remains expensive to investigate. AEGIS and internal deterministic tools already occupy detection; the specific gap must be an unsupported execution path or a reproducible new fault class. **Confidence:** medium on a bounded fault-injection study; low on a standalone product or extrapolated real-SDC coverage.

**I — Remaining order:** #6 unsupported parallelism adapter; #9 simulator calibration; #7 collective backend/sketch support; #10 workload-specific serving tuning; #4 fail-slow mitigation; #5 new elastic training runtime; #8 general scheduler. Low rank reflects incumbent coverage and validation access, not low technical importance.

## The ONE bet

**I — Build a repair loop that keeps one training application's recovery contract correct through a real stack change.** Start with an existing DCP/ByteCheckpoint/DeepSpeed integration, an uninterrupted reference and a named update or mesh transition that currently fails. Agent inspects the missing state/layout semantics, writes a small adapter repair and receives only independently produced failure evidence. The output is a maintained patch plus executable continuation/regression evidence. It is not a new checkpoint format or a promise of universal bitwise reproducibility.

**E — Two-week decision:** days 1–3 obtain a sponsor's three genuine resume/update failures and freeze state/sample contracts; days 4–6 implement independent capture, canonical comparisons and hidden mutants; days 7–10 run budget-matched structured-repair versus ordinary-agent-plus-upstream-tests tracks; days 11–14 test a withheld transition, measure expert time and review accepted patches. Include optimizer, data cursor, RNG, partial publication and parameter-identity failures. Charge harness work and failed candidates. A CPU-only result is sufficient to reject the idea but insufficient to certify a GPU deployment.

**E — Continue only if** at least three real blockers close, no accepted patch loses declared state or violates sample accounting on the held-out suite, expert time falls **≥50%**, and the sponsor will pay **$10K–25K** for the next bounded qualification. **I:** if DCP/ByteCheckpoint tests plus a normal coding agent match it, upstream the useful tests and stop the separate-product thesis. Better models strengthen both sides of that comparison; they do not guarantee a moat.

## Five-line TL;DR

1. **F/I:** 16K–100K-scale training really pays for interruptions, restart and stragglers; distinguish fleet size, job size, measured recovery and modelled goodput.
2. **F/I:** BSP, MPI collectives, checkpoint/restart, gang scheduling and queueing already won; the opportunity is their remaining integration and validation labor.
3. **F:** FT-HSDP, ByteRobust, EROICA, AEGIS, TSGuard, Minerva, Mist, MSCCL++, KAI and Dynamo occupy most obvious agent-plus-AI-compute combinations.
4. **I:** The most useful agent writes a repair or discriminating reproducer; independent state/numerical/protocol checks judge it, while loss and simulation alone are weak oracles.
5. **I/E:** Bet conditionally on recovery-equivalence maintenance; kill it unless real transitions pass hidden state-loss tests with at least half the expert effort of existing tools plus a strong ordinary agent.

## Rejected ideas with one-line reasons

- **I — Generic autonomous GPU SRE copilot:** TSGuard/AidAI and NVIDIA Minerva/Sherlock directly overlap; a chat interface to logs is insufficient differentiation.
- **I — Agent-generated checkpointing as the revival:** Nguyen et al. already implement the generate–validate–repair loop; ByteCheckpoint and DCP already solve portability machinery.
- **I — CPU crash-and-reshard evidence as novelty:** ShardLift already demonstrates this bounded mechanism; actual existing-stack interoperability is the harder question.
- **I — Universal bitwise reproducibility across mesh changes:** floating-point reduction order/kernel changes invalidate that promise; fix a numerical contract and disclose its limits.
- **I — “Loss goes down” as a correctness oracle:** wrong sample accounting, optimizer state or corruption can evade a short smooth loss curve.
- **I — Byzantine consensus for every gradient:** agreement does not establish correct arithmetic, and trusted-fleet SDC does not automatically justify Byzantine replication overhead.
- **I — General online SDC detector:** AEGIS already has production-scale sensing/verification evidence; probe coverage is the narrower conditional seam.
- **I — Backup every slow TP/PP task:** collective/state dependencies and redundancy-induced congestion defeat the simple MapReduce analogy; GREYHOUND and TorchPass already implement practical mitigation.
- **I — Replace BSP/allreduce with a parameter server:** dense traffic, staleness and optimization semantics remain; cheap code is not the missing proof.
- **I — Generic agent selects TP/PP/DP/EP/CP:** GSPMD, Alpa, Mist, DeepSpeed and framework guidance already cover much of the space; unsupported semantics are the possible labor tail.
- **I — Agent discovers ring/tree allreduce:** MPI selection and MSCCL/TACCL/OptCCL synthesis predate the proposal; new-topology backend work needs real hardware validation.
- **I — Another gang scheduler:** KAI/Run:ai, Grove and Workload Map already supply placement and workload contracts; fairness and fragmentation still need explicit policy.
- **I — Simulator score as final acceptance:** an agent can exploit model errors; SimAI/ASTRA-sim/Vidur and physical held-out measurements must remain distinct.
- **I — Generic KV-cache/disaggregated serving optimizer:** Mooncake, vLLM, SGLang, Dynamo, llm-d, Llumnix and Fireworks already occupy it; session/workflow scheduling also has 2026 prior art.
- **I — Maximize tokens/sec or GPU-busy percentage:** it can drop long requests, change quality, hide idle reservations or impair convergence; completed qualified work is the relevant denominator.
- **I — Claim a 100K-GPU failure rate from a 10K-GPU fleet trace:** GREYHOUND's sampled jobs were 512–1,024 GPUs; scale labels and denominators must remain attached.
